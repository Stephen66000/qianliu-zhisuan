> **产品边界决定**
>
> 仟流智算 2.0 是单个客户企业实际使用的产品，是 1.0 的原位增量升级，不是仟流科技管理多家客户的总控台。2.0 可以优化 1.0 的 UI，但不得删减、替换或改写 1.0 已可用的功能、数据口径和操作闭环。

本文是 2.0 产品范围、页面合同和验收基线。原型中的演示数值用于说明口径，生产实现必须展示真实数据；原型已确认的页面结构、字段、操作和状态不得在开发中自行减配。

## 1. 产品定位与唯一目标

### 1.1 产品定位

仟流智算帮助一家企业管理自己购买和使用的多厂商 AI 算力。企业在同一个后台完成：资源登记、模型与额度管理、员工／项目接入、真实用量追溯、月度成本查看、部门预算归集、运行保障和采购复盘。

仟流智算 2.0 继续服务当前企业内部的管理员、员工和项目负责人，不提供跨客户企业经营管理。仟流科技未来用于查看多家客户、开通企业和管理商业关系的产品，统一称为“仟流科技总控台”，另行立项。

### 1.2 唯一版本目标

在不破坏 1.0 已可用能力的前提下，交付以下结果：

1. 企业可以通过企业微信／飞书通讯录或 Excel 模板导入人员和部门，并直接形成可配置的使用主体；
2. 管理员可以查看全部员工／项目或单个员工／项目的日、周、月用量趋势；
3. 企业可以按部门配置预算，并把员工和项目成本唯一归集到部门；
4. 月度经营账单完整保留 1.0 信息，并增加采购清单、部门账和必要的筛选能力；
5. 每项厂商资源都有可解释的利用、耗尽和连续无调用事实；
6. 管理员可依据真实使用事实完成轻量采购复盘。

### 1.3 开发与业务验证分轨

- 没有三家客户访谈和设计客户确认，不阻塞 2.0 标准版开发；
- 标准版先使用脱敏、可重复的企业内部样本完成产品验收；
- 标准版交付后再选择真实客户观察，业务验证结果单独记录；
- 未经真实客户验证的内容只能称为标准版产品判断，不能宣称已证明付费意愿或商业价值。

## 2. 1.0 基线与升级原则

### 2.1 1.0 已可用基线

1.0 已提供并继续作为 2.0 底座：

- 员工／项目使用主体、Principal Key、接入配置和批量模型授权；
- DeepSeek API、Kimi Coding Plan、智谱 Coding Plan 资源登记与使用；
- Provider、资源账号、统一模型、Model Route、计价规则和调度策略；
- 多账号路由、Token 额度、逐 Attempt 用量、费用、账本和请求级结算；
- 首页当前八项指标／字段、条件“需要处理”、资源摘要 14 列与模型下钻、本月 Token 总量和员工排行；员工账、项目账及厂商／请求下钻；
- 厂商额度窗口、供给预测、运行保障、异常和通知；
- 管理员账号与密码生命周期、操作日志和升级日志；
- WorkBuddy、Codex、ZCode 已完成的 1.0 兼容链路；
- `v1.0.0-final` 已有生产数据、Evidence 和工程封板结果。

### 2.2 强制升级原则

1. **原位增加**：2.0 新能力放入 1.0 现有信息架构，不另造一套替代页面。
2. **能力不减**：凡 1.0 已有字段、筛选、下钻、操作、状态和追溯能力，除 Owner 明确确认外不得删除。
3. **口径不换**：真实 Token、API 实际费用、套餐费用、厂商额度和内部预算继续分栏，不把不同事实换算成一个数字。
4. **历史不改**：组织关系、规则和预算变化不得回写历史请求、账本和已生成账单。
5. **先兼容再增量**：开发首先建立 1.0 页面、接口、数据和关键操作回归基线，再实现 FR2-002～FR2-007。
6. **克制建设**：没有当前场景的总控台、Agent、对账导出和复杂 BI 不进入本轮。

## 3. 用户与权限边界

2.0 沿用 1.0 的企业后台角色和服务端权限判定，不建设新的平台运营角色体系。

| 用户 | 主要任务 | 边界 |
| --- | --- | --- |
| 企业 Owner／企业管理员 | 查看企业全局，管理管理员、组织、资源、主体和经营结果 | 只管理当前企业 |
| 资源管理员 | 管理厂商资源、模型、路由、计价、调度、额度和运行保障 | 不查看或修改其他企业数据 |
| 账单管理员 | 查看用量、部门预算、经营账单并填写采购复盘备注 | 不读取资源 Secret |
| 普通员工 | 使用本人已授权的模型，查看本人接入信息和可见用量 | 不查看他人员工账和企业经营数据 |
| 项目负责人 | 管理获授权项目的接入并查看项目用量 | 不查看无关项目 |

管理员账号的创建、改名、启用、停用、本人改密和他人重置密码继续遵循 1.0 规则。当前登录管理员不得停用自己；临时密码和完整 Principal Key 只展示一次。

## 4. 统一事实口径

| 名称 | 冻结口径 |
| --- | --- |
| 真实 Token | 输入 Token＋输出 Token；缓存是输入子集，推理是输出子集，均不得重复累计 |
| API 实际费用 | 按已结算请求和生效计价规则计算的调用费用，不等于充值金额或余额 |
| 套餐支出 | 当月固定套餐成本，不按单次请求伪造 API 费用 |
| 本月总支出 | 首页固定口径：套餐支出＋API 实际费用 |
| 本月采购／充值现金支出 | 当月真实支付的充值和套餐采购金额；与“本月总支出”分开展示 |
| 厂商权益 | 厂商提供的 5 小时、周等窗口事实；与本地真实 Token 并列，不互相换算 |
| 预算使用率 | 部门归集成本÷部门月度预算；不用 Token 计算金额预算使用率 |
| 利用率 | Coding Plan 使用对应厂商原生窗口；API 仅在有可靠预算／额度分母时计算 |
| 价值记录 | 由业务人员填写和确认，系统不根据 Token 自动评价员工或推断价值 |

任何页面汇总必须能够追溯到同一批请求、Usage、Ledger 和 Settlement 事实。前端不得自行重算 Token、费用或分摊结果。

## 5. 核心业务闭环

### 5.1 人员进入使用闭环

```text
企业微信／飞书单向同步，或上传 Excel 模板
→ 匹配已有使用主体
→ 新人员自动生成使用主体并初始化接入配置
→ 管理员配置厂商额度池和模型
→ 员工领取／重置 Key 并使用
```

### 5.2 用量到经营闭环

```text
真实请求与账本
→ 员工／项目日周月聚合
→ 员工账／项目账
→ 按请求主体唯一归入部门账
→ 预算预警与月度经营总览
```

### 5.3 资源到采购闭环

```text
1.0 资源登记、额度窗口、供给预测和健康事实
→ 2.0 利用／耗尽／连续无调用汇总
→ 逐资源采购复盘
→ 管理员填写下一周期复盘备注
```

## 6. 2.0 功能范围

本轮只有 7 条正式功能需求。FR2-001 是开发底线，FR2-002～FR2-007 是 2.0 新增能力。

### FR2-001 1.0 兼容与管理闭环保留

#### A. 使用主体与接入配置

- 使用主体继续支持新建、编辑、停用／重新启用、清理和接入配置；
- 编辑只修改允许变更的主体信息，主体类型不因编辑改变；
- 停用同步撤销有效 Key 和授权，重新启用不自动恢复旧 Key 和授权；
- 无历史引用的主体才允许删除；有历史引用时只能停用并归档，历史用量、账本和日志保留；
- 接入配置完整保留 1.0 三段结构：主体 Key／接入信息、按厂商配置型号与额度、只读授权表及 Agent 使用情况；
- 主体总额度由各厂商池求和，只保留一个“保存并生效”；完整 Key、Base URL 和授权模型可复制，完整 Key 仅在生成／重置后展示一次；
- Agent 使用情况只用于真实请求统计诊断，不参与鉴权、额度、计费或调度，也不代表 2.0 开发 Agent 产品。

#### B. 批量模型授权与额度规则

- 批量模型授权原样沿用 1.0 的页面、字段、草稿、校验、发布、停用和版本历史，不做 2.0 改版；
- 额度规则采用横向页签，但前四项完整承接 1.0：`统一模型｜Model Route｜计价规则｜调度策略`；
- 四项均须保留创建、编辑、启停、校验／发布、版本和历史语义；页签改版不得把管理闭环改成静态列表；
- Token 额度继续在 Gateway 请求前执行原有硬控制，2.0 部门金额预算不替代 Token 额度。

#### C. 厂商资源

- 完整保留 1.0 的资源登记表单、资源列表、额度窗口、供给预测、资源健康与异常；
- 资源列表固定沿用 1.0 表头、顺序和语义：`名称｜厂商/模型｜模式｜厂商经营数据｜数据时间｜凭证指纹｜状态｜创建时间｜操作`；
- DeepSeek、Kimi、智谱的经营数据分别按 API 充值／余额／费用或套餐总额／已用／剩余展示；生产数据取真实值，不用 2.0 演示数据覆盖；
- 保留编辑、同步模型、更新经营数据／套餐配置和异常恢复；
- Coding Plan 同时保留滚动 5 小时和周窗口；厂商未提供的数据明确显示“厂商未提供”，不得显示为 0。

#### D. 首页、用量明细与经营账基础页

- 首页顺序固定为：`本月概览 → 资源摘要 → 员工消耗 Token`；
- 本月概览固定展示：真实 Token 消耗、本月总支出、套餐支出、API 支出、活跃人数、厂商接入账号；
- 六项主概览只是 2.0 编排，不删除 1.0 旧字段：本月充值和本月调度节省迁入资源摘要上方常驻“1.0 经营补充”；最早耗尽资源和资源状态在常驻资源摘要及资源详情保留。零值、健康态和不可计算态均须显示，不得仅依赖条件出现的“需要处理”。
- 资源摘要完整保留 1.0 的 14 列及“本月 Token”单元格内原地下钻“按模型查看”，不得另造下钻列或牺牲字段做卡片；
- 员工消耗 Token 左侧保留 1.0 月度总量及输入、输出、缓存、推理明细，右侧承接 FR2-003 的员工周期用量；
- “请求明细”完整保留 1.0 的请求 ID／主体、项目、Agent、厂商、资源、统一模型、状态、时间和超额筛选、分页及 URL 可复现查询；
- 请求列表保留请求、主体、客户端、模型、资源、Token、扣减、费用、状态、时间和耗时；展开后保留结算、路由候选、各 Attempt、计量质量、计价规则和调度决策；
- 经营账继续保留 1.0 月度总览、员工账、项目账、结账／重开、价值记录和厂商账单快照 CSV 导入。

#### E. 运行、账号与追溯

- 运行保障固定保留：`资源健康｜可用性规则｜熔断事件｜异常中心｜通知与人员`；
- 资源健康合并展示 1.0 运行态势；其余四项完整保留 1.0 的规则、事件、异常处理、通知配置和发送记录，不用空白新模块替换；
- 管理员页面保留新增、改名、启用／停用、修改本人密码、重置他人密码、首次改密和一次性临时密码；
- 系统设置采用：`企业设置｜操作日志｜升级日志`。企业设置新增企业名称、时区、默认货币；操作日志和升级日志完整保留 1.0 字段、筛选、状态及详情下钻。

#### 验收

- 以 1.0 功能清单、现有自动化测试、真实数据口径和已确认原型建立回归矩阵；关键能力通过率 100%；
- 2.0 实现前后，同一固定数据集的请求、Token、费用、路由、授权和月账结果一致；
- 任一既有入口、字段、操作、筛选、下钻或状态缺失，FR2-001 不通过，后续新增功能不得以此掩盖。

### FR2-002 组织通讯录单向同步与 Excel 导入

- “组织通讯录”作为“使用主体”的 2.0 页签，不新增一级导航；
- 支持企业微信和飞书通讯录接口单向同步到仟流智算，不向来源系统回写；
- 支持下载仟流 Excel 模板并上传导入，适用于不开放通讯录接口的企业；
- 两种入口使用同一处理口径：优先按外部成员 ID／员工编号匹配已有主体，新人员自动生成员工使用主体并初始化接入配置；
- 导入姓名和部门关系，后续同步／导入更新当前关系，但不得改写历史请求和账期的部门快照；
- 模板至少包含员工编号、姓名、部门，邮箱／手机号可选；缺失必填、重复编号和非法部门必须给出明确失败行及原因；
- 显示本次新增、匹配、更新和失败数量，失败记录不得伪装为成功；
- 仟流智算不在通讯录页提供新增、调岗、停职等人事操作，这些变化仍在来源系统或 Excel 中维护后再次导入。

#### 验收

- 企业微信、飞书和 Excel 三条入口均能把同一标准样本形成一致的部门和主体结果；
- 已有主体不重复创建，新员工自动进入可操作的使用主体列表并具备接入配置；
- 不开放任何通讯录接口时，仅用 Excel 仍能完成 100 名员工导入；
- 非法文件给出行级错误，已导入结果和失败结果可核对。

### FR2-003 员工／项目日周月与单主体用量

- “用量账本”增加“用量概览”，与 1.0“请求明细”并列；
- 支持 `员工／项目`、`全部主体／单个主体`、`今日／本周／本月`三组组合选择；不再显示重复的“查看主体”标签；
- 今日按时段展示，本周固定周一至周日逐日展示，本月按日期展示；均使用企业时区；
- 选择全部员工／项目时，展示整体指标、趋势和排名；选择单个员工／项目时，指标与趋势只统计该主体；
- 排名中的姓名／项目名可直接进入同一个单主体状态；
- 指标至少包含活跃主体、请求次数、真实 Token、API 实际费用，套餐扣减单独展示；
- 首页只承接员工日／周／月趋势，不把项目视图塞入首页；项目视图继续在用量概览中查看；
- 所有聚合必须能回到 1.0 请求明细的同一请求集合。

#### 验收

- 标准样本中，全部主体汇总等于可见主体之和，单主体趋势之和等于该主体所选周期总量；
- 本周始终按周一至周日展示，不因当前日期改变起止定义；
- 员工、项目、周期和主体切换后，指标、图表、排名和请求下钻口径一致；
- 100 名员工时，主体选择器必须支持输入搜索，并可通过搜索或排名进入指定员工；页面不以固定 6 人样本写死。

### FR2-004 部门预算与唯一成本归集

- 部门是当前企业的组织归集维度，来源于通讯录／Excel；本轮不引入跨企业组织、团队和成本中心体系；
- 项目保存负责人和明确的归属部门。创建时可默认使用负责人当前部门，但必须落下项目部门和发生时点／账期快照；
- 员工主体请求已归属项目时，员工账和项目账都可作为分析视图查看，部门账只按项目归属部门计入一次；
- 员工主体请求未归属项目时，按请求发生时员工部门计入“员工直接成本”；
- 项目主体请求按项目归属部门计入“项目成本”；
- 无有效部门关系的请求进入“待归属”，不得根据姓名、负责人或当前部门猜测；
- 部门账分别展示员工直接成本、项目成本、合计成本、实际 Token、API 费用、套餐分摊和归属状态；
- 额度规则增加“部门预算”页签，列固定为：`部门｜月度预算｜归集成本｜实际使用 Token｜预算使用率｜警戒线｜状态`；
- 低于警戒线为“正常”，达到或超过警戒线为“已预警”，达到或超过 100% 为“超预算”；金额预算只提醒，不阻断 Gateway 调用；
- 部门关系、项目负责人或预算变更不得回写历史账期。

#### 验收

- 每条账本事实在部门维度只归属一次；`全部部门合计＋待归属＝企业当月总成本`；
- 部门实际 Token 使用真实 Token 口径，缓存和推理不重复累计；
- 预算使用率、警戒线和状态按冻结公式计算；
- 调岗、项目负责人变化和补归属后，历史已冻结账期不改变，新账期使用新关系。

### FR2-005 月度经营账单增量

- 月度总览完整保留 1.0 的总投入、API 实际消耗、固定套餐费用、API 预付余额、套餐利用率、活跃使用主体、已确认价值和厂商投入构成；
- 增加“本月买了什么”清单，展示采购项、采购形态、服务周期、本月支付和本月使用结果；
- 现金采购、API 实际费用、套餐当月成本和内部成本分摊必须分栏，不能相互替代或重复计算；
- 员工账保留 1.0 的厂商下拉和“搜索员工”，支持组合筛选；筛选后同步更新记录数、可见行和合计，空结果明确提示；
- 项目账继续展示项目、负责人、归属部门、真实 Token、API 费用、套餐分摊、合计成本及模型／请求下钻；
- 部门账使用 FR2-004 的唯一归集结果；标题右侧不显示重复的“唯一归属口径”标签；
- 账单沿用 1.0 的 `DRAFT／CLOSED` 用户可见状态和版本机制：检查结果独立展示；结账冻结新版本，重开回到可编辑草稿，再结账生成新版本并保留旧版本；
- 1.0 已有厂商账单快照 CSV 导入继续保留，仅草稿账单可更新；
- “对账与导出”页签本轮只显示 `Coming Soon`，不展示模拟记录、模拟差异或可点击导出。

#### 验收

- 月度总览不因增加采购清单而丢失任何 1.0 指标、厂商投入或价值记录；
- 员工账厂商筛选和姓名搜索可处理 100 名员工，结果和合计一致；
- 员工账、项目账、部门账是同一批事实的不同视图，不允许相互相加造成重复成本；
- 草稿、检查、结账、重开和版本历史继续符合 1.0 行为；Coming Soon 页面不得伪装成功能已完成。

### FR2-006 资源利用、耗尽与闲置事实

- 在完整保留 1.0 厂商资源页后增加“资源利用概况”，逐项资源展示真实使用证据、利用率、耗尽风险、最近使用和连续无调用天数；
- Coding Plan 分别展示厂商原生滚动 5 小时利用率和周利用率，不能合成一个来源不明的百分比；
- API 展示本月真实 Token、实际费用、余额和覆盖预测；仅有可靠预算／额度分母时计算利用率，否则显示“—／未设置”；
- 耗尽信息复用 1.0 供给预测，展示 1h／24h／7d 速度、预计耗尽、下一恢复、覆盖时长和可信度；
- 余额未知、速度不足或周期未知时显示不可计算原因，不制造精确日期；过期快照不得冒充当前预测；
- 首版只展示最近使用和连续无调用天数，不冻结统一闲置阈值，也不自动断言资源闲置；“闲置状态”显示未判定；
- 利用概况可以下钻回 1.0 的额度窗口、供给预测和资源健康，不另造第二套事实。

#### 验收

- DeepSeek API、Kimi Coding Plan、智谱 Coding Plan 均有独立资源行；
- 5 小时、周、API 预算三种利用率来源明确，无分母时不显示 0%；
- 利用、预测、最近使用与下钻页使用同一事实水位；
- 不可计算、厂商未提供和未判定三种状态可区分。

### FR2-007 轻量采购复盘

- “采购复盘”作为经营账单页签，不建设独立 BI 系统；
- 顶部展示本月采购金额、API 实际费用、套餐平均利用和需关注资源数量；
- 逐项资源展示：采购／充值、真实使用证据、利用情况、利用率、建议标签和判断依据；
- DeepSeek、Kimi、智谱等每项资源必须分别显示自己的利用率；无可靠分母时显示“—／未设置”；
- 建议标签可以基于已展示事实提示“维持、关注耗尽、利用不足”，但不是自动采购决定；
- 删除右上角没有操作价值的“人工判断”标识，只保留“采购复盘备注（人工填写）”；
- 备注由管理员填写和保存，系统不自动创建订单、不替企业决定采购。

#### 验收

- 每项资源的采购、Token／费用、利用率、耗尽／连续无调用事实与 FR2-005、FR2-006 一致；
- 利用率列逐资源展示且标明口径；
- 人工备注可保存并按账期读取；页面不出现自动采购或大 BI 指标扩张。
