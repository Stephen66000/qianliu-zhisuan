# 企业微信 API 与 CLI 接入可行性核查

日期：2026-09-07。状态：官方资料及已授权 CLI 实时接口定义核查完成；未执行实际联系人搜索、群消息发送、全员同步或产品接入。

## 1. 用户要求

- 客户不需要逐家创建自建应用。
- 主要需要员工姓名、部门和可持续绑定的成员身份；不依赖企微手机号。
- 第一条路线：开启通讯录 API，判断能否读取姓名和部门。
- 第二条路线：现有 AI 模块调用官方 CLI，查员工、建立对应，并向内部群发送消息。

## 2. 结论

| 路线 | 已确认 | 不能承诺 |
| --- | --- | --- |
| 管理工具中的通讯录同步 Secret | 官方已限制读取；主要返回成员、部门标识，相关旧 IP 有历史过渡安排 | 新企业开一个 API 开关即可取得姓名和部门；不采用旧 IP 特例作为产品基础 |
| 普通第三方应用授权 | 可用受控组件显示姓名、部门；官方限制直接获取和存储名称 | 管理员授权后普通 API 就把全公司明文姓名、部门返回给我们 |
| 官方 wecom-cli 智能机器人授权 | 联系人搜索返回姓名、部门路径；支持向授权人及机器人最近互动过的可达会话发消息 | 全量通讯录导出、任意内部群广播、无需客户任何配置、后台长期授权及多企业托管已验证 |

建议先验证 CLI 的按需员工对应和指定可达群通知。它是独立授权通道，不需要客户创建传统自建应用；仍需要企业微信扫码绑定或配置智能机器人，并受企业管理及授权范围约束。

## 3. 通讯录 API 的核查依据

读取了企业微信官方页面正文：

- [通讯录同步接口调整](https://developer.work.weixin.qq.com/document/path/96079)：管理工具中的通讯录同步读取限制包括姓名、部门名称；不能依赖此 Secret 为新客户建立完整读取路线。
- [通讯录展示组件](https://developer.work.weixin.qq.com/document/path/91958)：普通第三方页面使用 open-data 显示名称；官方明确区分组件展示与第三方获取、存储名称。该页当前显示更新日期为 2026-08-30。
- [获取部门成员详情](https://developer.work.weixin.qq.com/document/path/90201)：自建应用等路径按可见范围读取，并有敏感字段限制；由于用户明确排除客户自建应用，本路径仅用于说明现有连接器为何不能直接当作新接入方案。

结论针对具体授权机制，不能推广成“企业微信所有工具都拿不到姓名”；官方 CLI 的接口另有实际返回定义。

## 4. 官方 CLI 核查

### 4.1 授权与运行方式

[官方仓库](https://github.com/WecomTeam/wecom-cli)和[CLI 参考](https://github.com/WecomTeam/wecom-cli/blob/main/docs/cli-reference.md)表明：

- 支持 macOS、Linux 和 Windows；可作为后台进程调用，默认输出结构化 JSON。
- 支持企业微信扫码创建绑定，或手动配置智能机器人凭证。扫码过程默认等待最多 5 分钟，支持不打开浏览器及二维码输出，具备封装成产品连接入口的技术基础。
- 手动方式需要按[官方机器人说明](https://open.work.weixin.qq.com/help2/pc/cat?doc_id=21677)创建 API 模式、长连接智能机器人并配置可见范围。它与传统自建应用是不同对象，客户侧仍有授权或机器人配置动作。
- 配置和临时目录可分别覆盖，凭证加密存储；这给企业隔离提供实现基础，不等于 CLI 已自带多租户服务。
- 服务目录、方法和 Schema 由服务器动态下发，不能只按安装版本推断能力。
- CLI 源码采用 MIT 许可证；远程服务的数据保存、批量同步和 SaaS 托管适用条件需要另核，代码许可证不能替代服务授权。

### 4.2 当前本机验证范围

现有 CLI 为 `1.1.0`，本地授权状态为 `authorized`。仅执行版本、授权状态、帮助及 Schema 读取；没有安装、重新扫码、轮换凭证或读取凭证内容。

已读取当前服务端定义：联系人搜索、机器人最近会话、机器人消息发送。没有执行搜索或发送，因此结论是“接口能力已确认”，不是“正式企业人员已同步／群消息已送达”。

### 4.3 员工姓名和部门

[官方联系人说明](https://github.com/WecomTeam/wecom-cli/blob/main/skills/wecomcli-contact/SKILL.md)及实时 Schema 均包含成员姓名、部门路径列表及成员身份字段；主部门靠前。接口按姓名、拼音、英文名和别名搜索。

实时 Schema 的重要约束：

- 每次输入 1～10 个搜索关键词。
- 默认模式按热度等截断；列表模式也标明数量截断。
- 当前联系人资源只公开搜索方法，没有发现全企业成员遍历、部门树全量导出或对应游标分页方法。
- 响应包含限制提示，必须保留并展示；不能将“关键词的列表模式”解释为全公司完整通讯录。
- 不通过空关键词、字典遍历或猜测隐藏接口绕过限制。

这足以支持一个有价值的最小流程：在已有员工旁点击“关联企业微信”，用本地姓名检索企微候选，显示姓名和部门，管理员确认一个候选，保存内部身份对应。名称不同时支持手动输入企微名称搜索；同名和多结果不自动确认。保存哪些返回资料以及长期保留策略，需要核对该 CLI 授权和服务适用范围。

仍待验证：授权人／机器人范围之外的可见性、成员标识在重新扫码及机器人更换后是否稳定、员工改名后是否可按身份刷新、授权撤销后的行为，以及目标企业实际返回的数据完整性。

### 4.4 内部群消息

[官方消息说明](https://github.com/WecomTeam/wecom-cli/blob/main/skills/wecomcli-message/SKILL.md)确认机器人可以向授权人及最近互动过的有效单聊／群聊发送文本等消息。

实时最近会话 Schema：最多 20 个，按最近互动时间排列，不支持分页或过滤；机器人被移出、群解散或被封禁等无效群不返回。部分 Skill 文案仍写最近 10 个，数量以当前服务端定义为准，实际发送流程仍须从当次合法会话列表选择。

因此：

- 可对当次可达的指定内部群发送通知；必须先查询合法目标。
- 不能因为查到了某员工就直接把联系人身份当消息会话使用。
- 不能承诺覆盖所有内部群或长期无人互动的固定群。
- “向某个内部群发一条通知”与“向所有员工／所有群广播”是不同能力。
- 本次未发送测试消息；后续实发必须有明确目标和内容授权。

## 5. 集成到仟流的建议设计

推断方案：`仟流 AI 或页面操作 → 企业微信工具服务 → 企业隔离的官方 CLI → 当前企业授权范围`。

1. 每家企业独立连接状态、凭证目录、任务和缓存；客户扫码由自己的连接会话承接，不复用开发人员的授权。
2. 查员工、列可达群、发消息以固定工具接口开放；后端构造参数并限制操作，AI 不直接拼接任意 Shell 命令或接触密钥。
3. AI 可以帮助提出搜索词、解释候选、起草通知；身份绑定和账单关联由确定性业务代码保存，首次歧义由管理员确认。
4. 页面按钮也能直接调用同一个工具服务；通讯录对应不需要每次调用大模型。
5. 一期按钮命名“查找／关联企微员工”，不要命名“全量同步通讯录”。已有绑定优先复用，不能因搜索不到就自动取消绑定或停用员工。
6. 发消息前查当前合法群会话，展示发送目标和内容；明确授权的业务自动通知后续再配置范围、触发条件、重试和防重。遇到发送超时不能盲目重发造成重复通知。
7. 加入超时、失败提示、重新授权入口及脱敏审计；凭证不进入 AI 上下文或业务日志。

## 6. 最小验证方案与决策条件

| 验证 | 操作 | 通过标准 |
| --- | --- | --- |
| 接入体验 | 在独立测试配置中扫码连接 | 无需传统自建应用；确认扫码人要求、机器人创建及企业审批步骤 |
| 员工查找 | 对明确指定的少量测试员工搜索，覆盖同名／不同部门 | 姓名、部门和候选可读；限制提示可见；不依赖手机号 |
| 绑定稳定性 | 重复查询、重启；在测试授权中验证重新连接 | 不把其他企业或新机器人身份误接到旧主体；变化可被检测 |
| 返回完整性 | 验证同名超过截断数量及可见范围外人员 | 不把未返回判成不存在，不宣称全员同步 |
| 后台运行 | Linux 容器或实际目标运行环境 | 连接隔离、凭证读取、错误处理及重新授权流程可运行 |
| 内部群通知 | 获得明确授权后向专用测试群发送指定内容 | 目标来自当次可达列表；实际收到且不重复；移出群后不继续发 |
| 产品适用范围 | 核实官方服务说明或向官方确认 | 明确持久绑定／资料保存、后台使用、多企业托管及调用额度条件 |

如果上述验证通过，可把 CLI 作为一期“企微员工关联＋指定群通知”路线。若业务必须完整复制企业通讯录、自动追踪全员变化或固定群长期推送，需取得相应正式能力依据，不能用搜索结果拼接冒充全量同步。

## 7. 对原修复计划的影响

- 保留内部人员、员工主体、项目负责人和审计底座。
- 将“先全量同步企微，再自动建员工”的假设替换为待选方案；当前优先验证“已有员工按需查找、人工确认绑定”。
- 连接入口从要求客户填写传统应用 Secret，转向研究扫码连接智能机器人。
- 手机号不是连接条件；也不是企微与本地主体的匹配键。
- 内部群通知列入新研究范围，实际实现、消息发送和部署均未执行。
