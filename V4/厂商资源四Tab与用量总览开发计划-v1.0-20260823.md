## 1. 结论

“厂商资源”页面调整为四个 Tab：

1. `资源利用`
2. `用量总览`
3. `额度窗口`
4. `供给与健康`

本次不仅调整前端页面结构，还要把最新候选中首页已有的“厂商 + 模式”聚合及模型 Token 聚合迁移到“用量总览”专用读取路径；模型级额度、费用、速度和所属资源耗尽信息属于本次新增读取能力。否则即使首页不再显示资源大表，后端仍会执行原有重计算，无法达到减少首页耗时、开发复杂度和无效计算的目的。

默认不新增数据表、不新增调度器、不修改额度窗口、供给预测和资源健康的业务逻辑。

## 2. 已确认的产品方案

### 2.1 页面总体结构

页面标题仍为“厂商资源”，页面内按以下顺序显示四个 Tab：

| 顺序 | Tab | 职责 |
| --- | --- | --- |
| 1 | 资源利用 | 查看逐资源利用事实，并管理已登记资源 |
| 2 | 用量总览 | 查看厂商总体用量及具体模型使用明细 |
| 3 | 额度窗口 | 查看 Coding Plan 厂商原生额度窗口 |
| 4 | 供给与健康 | 查看供给预测、资源健康与异常 |

默认打开“资源利用”。Tab 状态进入 URL，支持刷新、书签和直接访问。

### 2.2 Tab 一：资源利用

#### 资源利用事实表

最终保留以下字段：

| 字段 | 展示规则 |
| --- | --- |
| 资源 | 只显示资源名称；取消账本明细、额度窗口、供给预测、资源健康等链接 |
| 形态 | 只显示 `Coding Plan` 或 `API`，不再展示原生窗口 |
| 请求 / 真实 Token | 保留现有真实统计及不可计算语义 |
| 费用 / 余额 | 费用保留；余额存在时才显示余额；余额未设置时只显示费用，不显示“未设置” |
| 利用率 | 只适用于 Coding Plan；API 显示 `—` |
| 订阅周期 | 保留；无适用周期时显示 `—` |
| 最近使用 / 无调用 | 保留最近使用时间和连续无调用事实 |
| 预算 | 保留 API 月预算的设置、修改、清除及历史版本能力 |

取消以下字段和内容：

- 原生额度窗口信息；
- 耗尽、恢复、速度；
- 判断依据；
- 数据更新时间、新鲜度；
- 资源名称下的全部下钻链接。

#### 已登记资源

资源利用事实表下方继续完整保留所有已登记厂商资源，以及现有：

- 登记资源；
- 编辑资源名称和并发限制；
- 同步模型；
- 更新套餐配置／经营数据；
- 资源恢复；
- 历史经营快照；
- 凭证安全与既有二次确认规则。

### 2.3 Tab 二：用量总览

“用量总览”由上下两张卡片组成，不再使用“按模型查看”下钻。

#### 上半部分：厂商总体使用情况

按厂商和模式聚合全部已登记 AI 算力资源，保留：

- 厂商；
- 模式；
- 账号数；
- 总额度；
- 已用额度；
- 剩余额度；
- 已分配给主体；
- 经营余额／套餐；
- 本月花费；
- 本月 Token；
- 消耗速度；
- 预计耗尽；
- 状态。

取消：

- “余额可承载 Token”；
- “按模型查看”入口和原地下钻详情。

#### 下半部分：模型使用明细

每一行以“具体模型 + 具体资源”为唯一对象，避免同一模型登记在多个资源后被错误合并。展示：

- 模型；
- 所属厂商／资源；
- 已用额度；
- 所属资源剩余额度；
- 本月花费；
- 本月 Token；
- 最近 24 小时消耗速度；
- 所属资源预计耗尽；
- 状态。

模型明细不增加弹窗、展开行或二次下钻。

#### 模型数据口径

1. 模型已用额度取当前资源、当前有效周期内该模型的真实账本扣减。
2. Coding Plan 的剩余额度属于共享资源，不得伪装为模型独享额度；列名或次级说明必须明确为“所属资源剩余额度”。
3. API 模型本月花费取已结算账本中的真实费用。
4. Coding Plan 套餐固定费用没有真实模型分摊事实时显示“套餐固定费，不按模型拆分”，不得按 Token 比例伪造成本。
5. 模型消耗速度统一使用最近 24 小时的真实 Token／额度速度，并明确单位。
6. 预计耗尽引用所属资源的供给预测，不制造模型级独立耗尽时间。
7. Token、费用、额度或预测不可计算时保留明确原因，不以 `0` 代替未知。

### 2.4 Tab 三：额度窗口

完整复用现有 `QuotaWindowPanel`：

- 卡片结构不变；
- 字段不变；
- 5 小时和周窗口展示不变；
- 同步状态、新鲜度及失败保鲜逻辑不变；
- 手动同步和既有接口不变。

本次只改变所在 Tab，不重做组件。

### 2.5 Tab 四：供给与健康

按现有顺序放置：

1. 供给预测；
2. 资源健康与异常。

两块内容完整复用原有组件和逻辑：

- 不删字段；
- 不改卡片样式；
- 不改预测算法；
- 不改健康判断；
- 不改恢复操作；
- 不新增告警平台或调度器。

## 3. 首页调整

### 3.1 页面调整

从首页移除原“资源摘要”大表及其“按模型查看”下钻。首页继续保留已有核心经营概览、必要的资源数量、最早耗尽和异常摘要，不把完整厂商／模型表重新放回首页。

### 3.2 计算路径调整

原首页厂商／模型重聚合不能只在前端隐藏，必须从 `/dashboard` 的默认聚合路径迁出：

- 首页请求不计算模型使用明细；
- 首页请求不返回完整厂商用量表；
- “用量总览”使用独立只读接口；
- 只有打开“用量总览”Tab 时才请求和计算对应数据；
- 用户在四个 Tab 间来回切换时复用前端查询缓存，避免重复请求。

## 6. 验收标准

### 6.1 页面结构

- [ ] 厂商资源准确显示四个 Tab，顺序正确。

- [ ] 资源列只显示名称，不再显示下钻链接。
- [ ] 形态列只显示 API／Coding Plan。
- [ ] 请求／真实 Token 保留。
- [ ] 余额未设置时只显示费用，不显示“未设置”。
