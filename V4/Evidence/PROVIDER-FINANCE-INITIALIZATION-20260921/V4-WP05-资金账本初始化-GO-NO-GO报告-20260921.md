## 三、安全与失败关闭

- **身份**：所有请求体（预检草稿、激活、静默租约）都不含 `enterprise_id` / `admin_id`；
  权威企业与管理员只来自认证会话。前端不新增任何可覆盖服务端身份的入口（PFA-07 / PFU-02）。
- **权限**：无 `resources.operate` 时草稿只读、写入口（预检/激活/租约变更）不可用；
  DARK 模式同。服务端权限仍是最终门禁（PFU-06），前端只是提前给出可读反馈。
- **失败关闭**：写操作 `retry: 0`；`ACTIVATION_RETRY_REQUIRED` 不改变任何本地状态，
  只提示人工重试且同键；候选失效类错误立即清除可激活状态；
  所有 409 语义有可读映射，未知码回退服务端消息。
- **不可变回执**：`ActivationReceiptPanel` 无任何修改入口，也不接受调用方本地构造的数字；
  回执只能来自服务端 `activation-state.activation_receipt`。
- **本地校验不越权**：本地只拦结构性错误；业务缺口（必要账户缺期初、旧记录未关闭、
  `UNKNOWN_COST`、守恒、经营账单完整性）一律由服务端只读投影判定（PFU-03）。

## 四、关键实现裁决（复核请重点看这里）

1. **静默排空是两段式门禁，前端不得把第二段当第一段的前置条件。**
   服务端 `assertPrePreviewQuiescent`（投影**之前**）只查 租约有效、剩余 ≥5 分钟、
   `IN_PROGRESS` 请求、未结束 `upstream_attempt`、`PENDING` 交易；
   `unpaired_usage_lines` 的排空判定在投影**之后**的 `assertDrainedForCandidate`，
   且会用候选自己冻结的确定性修复行集做豁免（WP03 §3.5 收口结论）。
   因此 `activation-preflight-model.ts` 拆成 `prePreviewBlockers`（阻断预检）与
   `prePersistBlockers`（仅展示 + 注明「预检时会按候选修复集重算」）。
   **若把未配对用量行当预检前置条件，首次预检永远不可达——而这正是初始化存在的场景。**
   该语义有专项测试锁定（preflight 模型 1 项 + 向导交互 1 项）。

2. **HTTP 面命名不搞「统一化」二次加工。**
   `activation-state` / `activation-preview` 的暴露面是 snake_case，但
   `gaps`（`preview.gaps`）、`usage_repairs`、`projected`、`activation_receipt` 是
   **领域对象原样透传**，保持 camelCase。Web 类型逐一对照
   `activation-routes.ts` / `packages/database` 的 `ActivationCandidateView` /
   `ReadOnlyCandidateProjection` / `ActivationPreviewResult` / domain `ActivationGap`、
   `ActivationReceipt`、`UsageRepairSummary`、`ProjectedFinanceSummary` 抄写，
   并在类型注释里写明「为什么这里是 camelCase」。过程中实际发现并修正了一处
   snake_case 误写（会把缺口定位全部读成 `undefined`）。

3. **静默读取源唯一化。**
   `activation-state.quiescence` 已返回租约有效期、剩余时间与排空计数，
   因此 Web 不再单独查询 `GET /activation-quiescence`，避免同一窗口出现两份可能矛盾的快照；
   租约变更成功后失效 `activation-state` 即可。服务端该路由保留，供其它消费方与集成测试使用。

4. **企业 ID 从既有 `AccessContext` 取，不再另订会话。**
   `RequireAuth` 直接用 `session.admin` 作为 `AccessContext` 值，其中已含 `enterpriseId`。
   为此给 `permissions.tsx` 的 `Access` 增加**可选**字段 `enterpriseId?`（纯加法，不影响
   既有 `canAccess` 语义与任何调用点），容器从 `useAccess()` 读取。
   这样避免了容器里第二个 `useAdminSession` 订阅（重复 `/auth/me` 轮询），
   也避免了 `session.data.admin` 形状不完整时的空引用崩溃（全量回归中实际暴露过）。
   该字段只用于**展示与二次确认**，不参与任何前端授权判定。

5. **幂等键的生命周期绑定「一次人工提交」，而非「一个草稿」。**
   弹窗打开时生成、重试复用、取消重开才换键。这样 `ACTIVATION_RETRY_REQUIRED` 的人工重试
   天然满足「同键重放」，而管理员主动放弃后再激活会拿到新键（不是无意义的同键冲突）。
