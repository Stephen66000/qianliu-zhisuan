### 2.2【v1 首次证据·保留】根因

**(a) 排除逻辑要求合成标记**（4 处同一判据 `migrated.external_reference = ('legacy-purchase:' || purchase.id::text)`）：

| 文件 | 行 | 作用 |
| --- | --- | --- |
| `provider-finance-registered-history.ts` | 45 | 旧记录是否已被新账本承接（未排除则并入历史金额） |
| `operating-analysis-purchases.ts` | 44 | 经营分析的旧购买并集 |
| `provider-finance-activation-facts.ts` | 206 | 激活事实水位/守恒口径 |
| `provider-finance-cutover-repository.ts` | 143 | 切换守恒核对 |

**(b) 原写入路径写的是业务订单引用**：`provider-finance-activation-coordinator.ts` 的
`writeRecharges` / `writePurchases` 传 `externalReference: recharge.externalReference` /
`purchase.externalReference`（草稿业务订单引用，本套件为 `SYNTH-ZHIPU-ORD-1`），标记从未产生。

**(c) 双计入通路**（`provider-finance-repository.ts`）：新账本汇总 `provider_finance_event` 得 `199.00`
→ `:235-236` 再并入 `historicalMonthlyFinance()`，其内部 `registeredSubscriptionHistory()`
以 `NOT EXISTS(… external_reference='legacy-purchase:'||purchase.id)` 判承接——标记不存在故
`NOT EXISTS` 成立 → 旧记录**仍被返回** → 再计 `199.00`；`cashOutflowCny = 249 + 199 = 448.00`。

**(d) 逃逸分析**：既有 `operating-feedback.integration.test.ts:45` **手工构造**该标记后断言 `199.00000000`
通过——即排除机制本身正确，但**无门禁覆盖「激活写入侧是否真的写出标记」**；WP07 是首个在真实激活产物上
断言金额口径的套件。

### 2.3【v2 新增】修复决策与代码差异

**决策依据（技术裁决）**：四处聚合排除逻辑与 `operating-feedback.integration.test.ts` 已确立

**改动范围（3 个文件，+33/−3 行，零 schema / 零迁移 / 零读模型改动）**：

| 文件 | 变更 |
| --- | --- |
| `packages/database/src/repositories/provider-finance-activation-writes.ts` | **新增** 纯 helper `legacySourceMarker(sourceRecordId, businessExternalReference)` 与常量 `LEGACY_PURCHASE_MARKER_PREFIX`（+24） |

```ts
export function legacySourceMarker(
  sourceRecordId: string | null | undefined,
  businessExternalReference: string | null | undefined,
): string | null {
  const recordId = sourceRecordId?.trim();
  if (recordId) return `${LEGACY_PURCHASE_MARKER_PREFIX}${recordId}`;
  return businessExternalReference ?? null;
}
```

**语义边界（逐条对齐授权要求）**：

1. **迁移行**（草稿 `sourceRecordId` 非空）⇒ 事件 `external_reference = 'legacy-purchase:${sourceRecordId}'`；
   **非迁移行**保留原业务引用 ⇒ 日常 `ADMIN` / `SYSTEM_RENEWAL` 写入语义**零改动**
   （两条路径不经该 helper，`insertRechargeTx`/`insertSubscriptionTx` 原语未改）。
2. **业务订单引用不丢失**：仍在候选草稿（`candidate_draft` 列）与
   `provider_finance.legacy_purchase.close` 的不可变审计 `change_summary.external_reference`
   （由 `closeLegacyPurchaseTx` 继续写 `resolution.migratedExternalReference`，未改）；
   周期继续以 `migration_source_record_id` 绑定源记录。
3. `findMigratedEventId` 按**幂等键**（非 `external_reference`）定位迁移事件，故该改动不破坏关闭映射。

**回归门禁升级**：WP07 套件的 §10.1/§10.2 由 `it.fails` 改为**正向 `it`**（金额不再翻倍、排除链接命中、
