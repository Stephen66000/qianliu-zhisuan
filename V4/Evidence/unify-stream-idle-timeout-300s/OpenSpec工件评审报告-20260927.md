## 4. P2 建议项

1. **spec 心跳措辞与实现判定层不一致**（spec Requirement 2 / Scenario「上游 SSE 心跳是有效活动」）：spec 写"合法的非空 SSE 注释或心跳"，实现按**原始块层**判定（`byteLength > 0` 即刷新，不解析事件合法性）。建议 spec 措辞统一为"非空原始数据块（含合法注释/心跳）"，避免实施者误解为需先解析出合法事件才刷新。计划 v1.1 §3.1.2 同措辞，可一并注记。
2. **Responses 下游等待数值三处并存易误读**：spec Scenario「Responses 聚合超过 330 秒」与 A10 用 330 秒（验收下限），design 决策 5 与 tasks 6.3 用 660 秒（配置目标）。建议在 spec 该 Scenario 补注"330 秒仅为验收下限，可控链路配置目标不低于 660 秒"，防止实施者按 330 配置代理即视为达标。
3. **tasks 缺"计时器清理无残留"显式测试项**：计划 §3.1.4 要求"计时器清理后不得残留回调或重复结算"，tasks 3.1 覆盖了零长度块/心跳/299 秒恢复/多次重置/异常 EOF，但未列 dispose 后无残留回调断言。建议补入 tasks 3.1（或 4.2 的释放一次语义中）。
4. **design 决策 3 的 headersTimeout 未给派生公式**：bodyTimeout 已明确 `300000 + 30000 = 330000`，headersTimeout 仅写"大于所有有效首字节门限并留有余量"。建议补明确派生规则（如 `max(有效首字节门限) + 30000`），减少实施裁量空间。
