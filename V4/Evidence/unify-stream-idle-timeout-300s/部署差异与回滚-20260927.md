## 2. 代码行为差异

| 项 | 变更前（cfe818e） | 变更后 |
|---|---|---|
| 流式空闲门限 | 全局 45 秒；智谱 Coding Plan 特例 120 秒；厂商/模式变量可覆盖 | 统一 300,000ms，单一来源，厂商和模式无关 |
| 零长度块 | 刷新空闲计时（`readSseData` 无条件 `onChunk`） | 不刷新（仅 `byteLength > 0` 刷新） |
| 空闲超时后 failover | 未提交时可切换上游 | 终止性结果：不再新增 Attempt |
| `STREAM_IDLE_TIMEOUT` 文案 | 已提交"上游流超时"；未提交裸 `upstream_timeout` | 已提交/未提交统一："上游模型响应中断，等待超时。请稍后重试，或切换其他模型。" |
| Undici dispatcher | 默认（bodyTimeout=300s 与业务竞争） | 显式 Agent：bodyTimeout=空闲+30s，headersTimeout=max(首字节,总时限)+30s |
| Coding Plan 并发租约 TTL | 仓储默认 60 秒 | `requestTimeoutMs + 60_000`（默认 660 秒）由 runtime 同源派生 |
| 管理探针/发现/验证时限 | 15/30/60 秒显式配置 | 不变 |

## 4. 反向代理差异（部署时应用）

生产入口（宝塔/Caddy/CDN）`/v1/*` 的读超时/空闲超时必须覆盖：

- **下限 660 秒**（600 秒总调用时限 + 60 秒错误发送余量）；330 秒只是验收测试下限，不是配置目标。
- 保持流式透传设置（如 Caddy `flush_interval -1`，禁用响应缓冲）。
- Chat/Messages 已提交后的空闲窗口至少覆盖 300 秒 + 错误发送余量。
- WP1 生产实际反代核验（tasks 1.2）已于 2026-09-28 只读完成：`ic-gw.qianliuai.com` 当前为 `proxy_buffering off`、`proxy_read_timeout 600s`、`proxy_send_timeout 600s`，转发至 `127.0.0.1:9093`。600s 可覆盖 300 秒空闲提示，但低于本节 660 秒发布目标；部署时必须将读/写超时提升至至少 660s。

## 5. 发布步骤（需单独部署授权）

1. 复核 tasks 1.2 的生产只读证据仍与窗口现场一致（当前镜像、容器环境、全部旧空闲变量实际值、实际反代链路）；基线证据见 `production-readonly-preflight-20260928.md`。
2. 记录当前 Gateway 镜像 tag、容器环境变量全量脱敏快照、代理配置快照（回滚依据）。
3. 构建候选镜像（候选提交绑定）。
4. 选择无关键长请求窗口；先改代理时限（≥660 秒），再替换镜像并清理旧空闲变量。
5. 核验：启动日志出现 0 次弃用提示（变量已清理）；实际生效空闲门限 300 秒；健康检查通过。

## 6. 回滚步骤

1. 恢复原镜像（步骤 2 记录的 tag）。
2. 恢复原环境变量（含被清理的旧空闲变量原值——旧值在新代码下不生效，但回滚后立即恢复原语义）。
3. 恢复原代理时限配置。
4. 核验：有效空闲门限回到 45/120 秒、健康状态、并发租约释放、请求账本无残留失败。
5. 无数据库回滚（本次无迁移），历史失败事实不修改。

## 7. 发布后观察（沿用现有账本与异常中心）

- 断流比例与等待时长分布（`failure_layer=STREAM_IDLE_TIMEOUT` 的时长应贴近 300 秒）。
