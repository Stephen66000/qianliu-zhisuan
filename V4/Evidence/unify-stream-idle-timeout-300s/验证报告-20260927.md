### 2.3 真实本地 HTTP 慢流（真实时间，非假时钟）

`packages/provider-adapters/src/__tests-integration__/real-slow-stream-idle.test.ts`，全部本机回环 + 合成内容：

| 场景 | 实测耗时 | 结果 |
|---|---|---|
| 首块后真实静默 300 秒 | 301,711ms | ✅ `STREAM_IDLE_TIMEOUT`，早于 Undici bodyTimeout 330 秒；未被记为 `UPSTREAM_NETWORK` |
| 首块后 299 秒真实恢复 | 299,027ms | ✅ 不提前失败，窗口重置，usage 正常结算，status 200 |
| Node 本地反向代理透传 | 300,024ms | ✅ 代理全程未切断；业务层错误穿透代理返回 |

dispatcher 有效性另经独立探针实证：全局 fetch 与 undici fetch 均尊重 `init.dispatcher`（1,000ms bodyTimeout 实测约 1,500ms 终止）。

> 口径说明：上表第 3 行的"反代透传"用例验证的是 **Caller 层经上游侧代理** 的计时与连接保持（`Outcome.failureLayer`），不是北向客户端合同；北向合同由 §2.4 补齐。

### 2.4 北向端到端慢流（真实时间，tasks 6.2 证据）

`apps/gateway/src/__tests-integration__/northbound-slow-stream-idle.test.ts`：
真实 Chat 路由（`registerChatRoute`）→ 真实 `createChatStreamWriter` → 真实 Caller（统一 300 秒门限）→ 慢上游，下游客户端经本地可控反代访问 Gateway `/v1/chat/completions`。真实 300 秒静默后实测（**实测 301,426ms**）：

1. ✅ 客户端先收到正常 SSE 正文 chunk（已提交流）；
2. ✅ 空闲超时后收到流内 error frame：`code=upstream_timeout`、约定中文文案（`STREAM_IDLE_TIMEOUT_MESSAGE`）、`request_id` 与 `x-ai-request-id` 响应头一致；
3. ✅ 随后收到 `data: [DONE]`，连接由服务端正常结束；
4. ✅ 全程 ≥ 300 秒业务门限（约 300 秒量级），错误帧穿透反代到达客户端。

范围说明：DB 侧鉴权/路由/额度/账本依赖 Postgres 容器（本环境无 Docker），不在该用例覆盖；其合同由单元与既有数据库集成测试保证（见测试文件头注释）。
