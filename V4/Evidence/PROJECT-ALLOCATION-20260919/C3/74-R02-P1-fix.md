## 2. 修复

**原则**：输入摘要必须覆盖**全部决定归集结果的输入**；只要摘要能被"摘要外变更"绕过，
幂等短路就不可信。

1. 核算窗口进摘要：`loadAllocationContexts` 新增 `accountingDigest`
   （`(project_principal_id, accounting_started_at, accounting_ended_at)`，与
   `ruleDigest/membershipDigest` 同构：排序后 `sha256(JSON)`），并纳入 `inputDigest`
   （`project-allocation-run-repository.ts:437-467`）。同时在摘要中计入
   `financeEnabled`（决定 `account_at` 口径）与 `earliest`（决定 `historicalCutoff`，金额中性）。
2. 代次清除加条件守卫（复核 §4-②，同块顺手收紧）：清 `dirty=false` 与代次对齐都改为
   `WHERE generation = <本次读取/对齐后的值>`（`:619-663`）。并发标记推进代次时不再被吞，
   保持"闸门拒绝 + 调度仍可重新登记"的 fail-closed 形态。
3. no-op 短路分支本身不变（仍不写 `input_digest`、不夺 current）。摘要完备后，
   "摘要命中"⇔"当前输入与已发布结果一致"，此时对齐并清脏是**正确**的。
