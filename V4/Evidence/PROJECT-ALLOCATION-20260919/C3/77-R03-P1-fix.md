## 1. R03 P1：按第二种修法闭合

**根因（复核 §4-① 已实证）**：短路用"任意摘要命中的已发布批次"判幂等（无 `is_current`
限定），代次对齐取"当前批次"；二者不同批次时（人工指定 A→B→A，经公开 API
`assignRequestToProject` 可达）把闸门迁就到陈旧批次，冻入错误归属（fail-open）。

**实施**：

1. **幂等索引限定 current**（**选择原地改 0077**，非追加 0078）：候选未合并未部署、
   测试库均为临时实例，无向前兼容负担；`migration.integration.test.ts`（migrateUp/Down）
   与 foundation 迁移用例改后全绿。
   `packages/database/migrations/0077_project_allocation_compute.js:60-64`：
   `... WHERE status = 'SUCCEEDED' AND input_digest IS NOT NULL AND is_current`。
2. **短路收紧**（`packages/database/src/repositories/project-allocation-run-repository.ts:487-497`）：
   `existing` 增加 `.where("is_current", "=", true)` —— 只有"命中批次就是 current"才 no-op；
   命中非 current 历史批次走完整重发布（新行、新份额、新余量、关旧 current）。
   不再需要"认出旧状态"，正确性来自确定性重算。
3. **删除代次对齐 hack**（`:608-645`）：短路分支只清 `dirty` 标志，不再改写代次；
   条件写入 `WHERE generation = <读取值>` 保留（并发推进代次时不吞标记）。
4. **闸门谓词改为"未消费"**（`packages/database/src/repositories/project-allocation-freeze.ts:58-75`），
   精确谓词：

   ```sql
   dirty.dirty = true AND dirty.generation > run.input_dirty_generation   -- 才 stale_input
   ```

   理由：代次单调累加，任何配置变更都会推进它；只有"标志为真且代次前进"才代表未消费。
   `dirty=false` 只可能由成功执行（发布覆盖，或 no-op 证明与 current 同一输入状态）写入。
   **只读状态同谓词**：`getAllocationRunStatus.stale`（`project-allocation-read-repository.ts:47-63`）
   与闸门一致，避免页面报"待更新"而结账放行的矛盾。
5. **不变量写入合同**：见 `76-CONTRACT-AMENDMENT-01-run-idempotency.md`（含措辞对照表）——
   "current 批次永远反映当前输入状态"。

## 2. 余量 authority P2：按事件性质分治

- **plan-cash（挂钩 + 入摘要）**：`provider_finance_event` 的 CODING_PLAN 购买/续订/冲正
  是三处低频写入点，均在既有事务内，已按 P1-b 同一模式补钩子：
  - `provider-finance-events.ts` `recordSubscription`（CODING_PLAN_PURCHASE/RENEWAL）；
  - `provider-finance-events.ts` `reverseFinanceEvent`（REVERSAL，仅当资源 `mode='CODING_PLAN'`，
    取自 `lockResource` 返回值）；
  - `provider-finance-renewal.ts` `renewDueSubscription`（SYSTEM_RENEWAL，按周期起始月）。
  均调用 `markAllocationDirty(trx, enterpriseId, [shanghaiMonthOf(occurredAt)])`
  （新增单时点月份助手 `project-allocation-common.ts:150-154`，与余量按月口径一致）。
  同时把 plan-cash authority 摘要并入 `inputDigest`（`project-allocation-run-repository.ts`
  新增 `planCashDigest`）：现金事件变化时即使其它输入未变，也不会被幂等短路跳过余量刷新。
- **资源快照（接受滞后）**：`provider_resource_operating_snapshot` 属高频采集、估计口径，
  不挂钩、不入摘要；口径已写入合同（`10-WP01-contract.md` §3 residual 行）：
  "按下次任意输入变更刷新"。余量不进 close ref、不进守恒，不影响结账正确性。
- **未触发"停下来报回"**：三处写入点均在既有事务内、无跨库写入，不满足"无法同事务挂钩"的条件；
  未静默降级为"都接受滞后"。其它 finance 写路径（`API_LEGACY_COST_ADJUSTMENT`、
  `API_BALANCE_RECONCILIATION`、期初更正）`cash_paid_cny` 为 NULL 或类型不在 authority 列表内，
  不需要钩子（已在记录中核对）。
