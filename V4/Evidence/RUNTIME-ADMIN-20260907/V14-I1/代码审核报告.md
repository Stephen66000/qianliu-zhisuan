## 4. 已冻结 Findings

### F-01 · P1 · 历史决策达到 65,535 条后异常列表整体失败

- 规则：编码规范 §3、§7.2、§8.1/8.4；审计模板 §2.2、§2.5、§2.7。
- 位置：`packages/database/src/repositories/alert-event-request-derivations.ts:19`，调用处 `:108–112`。
- 问题：deriveDispatchAlerts 先加载企业所有非空 matched_policy_id 的历史决策，尚未筛选异常便把每个 request ID 传入 `where(..., 'in', requestIds)`。65,535 个请求 ID 加 enterprise_id 共 65,536 个绑定参数，超过 PG 协议上限。正常 ALLOW/ALLOW 决策也计入，无时间窗口或批次限制。
- 独立复现：在完整迁移的临时 PG17 中生成 65,535 条正常 ALLOW 决策，调用真实 deriveDispatchAlerts，返回 `08P01: bind message supplies 0 parameters, but prepared statement "" requires 65536`。见 [reproduction3.log](./reproduction3.log)、[复现脚本](./reviewer-reproduce.ts)。
- 影响：`GET /alerts` 和 `?history=true` 必先 await evaluate；derive 报错会中断整个请求。客户端月份筛选发生在取得全部数据后，不能绕过错误。没有修改或删除历史事实的安全用户级 workaround。
- 最小处置：用 SQL JOIN/子查询、单个数组参数或有界批次读取最新 Attempt；先筛异常可减少成本，但不能单独解决异常数量本身超限的问题。补入相同边界的定向回归。需要功能复审。

### F-02 · P2 · 下一次评估会抹去 0066 补齐的资源关联

- 规则：§7.2、§8.1、§8.4；审计模板 §2.2/2.3。
- 位置：`packages/database/src/repositories/alert-event-repository.ts:76`、`:93`；必要上游 `deriveCallDeduction` 的 resourceId 仍固定为 null。
- 问题：0066 为所有有 ai_request_id 的历史告警补资源，包含 call_deduction_anomaly；evaluate 新增的无条件赋值又把该类事件的 resource_id 清成 null。处置后但源仍异常的历史记录也走相同覆盖路径。
- 独立复现：同一个真实事件在执行 0066 up 后 resource_id 为实际资源 UUID，紧接一次真实 evaluate 后变为 null。见 [reproduction3.log](./reproduction3.log)。
- 影响：按厂商筛选时漏掉这些事件，列表/详情退回未关联。全部异常和请求 ID 仍可查询，因此定为 P2。
- 最小处置：让派生与补全使用一致的资源关联语义；只有确认关联失效时才清空。补“0066 后首次 evaluate”的回归。
- 建议 Owner/处置：异常模块负责人，由 Planning 确认；DEFER_WITH_GUARD 时明确这些事件需从全部异常或请求 ID 查询，复核不晚于下一次有界修复；退出条件是补全经过后续评估仍保留。

### F-03 · P2 · 关联信息请求失败被展示为业务事实缺失

- 规则：§7.3；审计模板 §2.5。
- 位置：`apps/web/src/pages/runtime-assurance/AlertsPanel.tsx:30–40`、`:120`；AlertTableParts 使用缺失映射回退为“系统级/未关联资源”。
- 问题：只处理 alertsQuery.error，忽略 principalsQuery、resourcesQuery、providersQuery 的错误；这些请求失败时默认空集合。已有 principalId/resourceId 的事件会显示“系统级/未关联资源”，已有厂商筛选也可能把全部结果排除而显示无异常。
- 证据：完整组件与 hook 调用链；三个辅助请求均能独立失败，错误没有传入任何反馈组件。当前测试仅提供辅助查询成功 fixture。
- 最小处置：展示关联数据加载失败/重试，保留 ID 或“信息加载失败”的明确回退；不能把网络失败等同于系统级或没有异常。
- 建议 Owner/处置：Web 模块负责人，由 Planning 确认；DEFER_WITH_GUARD，复核不晚于下一次异常中心修改；退出条件为辅助查询失败不会产生错误归属或空结果事实。
