# 凭证隔离的 Chat 验证恢复（本地候选）

2026-09-10。分支 `codex/credential-chat-recovery-20260910`，基线 `60b737a`（继承已部署的凭证隔离修复与运行保障，并保留系统设置权限实现）。生产当前版本未在本轮重新核对；本轮没有提交、推送、部署或调用真实厂商。

## 行为与入口

- 厂商资源 → 供给与健康 → 验证当前凭证并恢复。管理员须有资源操作权限，并确认本次消耗少量厂商额度。
- `POST /provider-resources/:id/credential-probes` 只接受幂等 UUID 和额度确认，不接受替换模型或明文凭证。
- 固定使用原故障模型、当前保存凭证和业务 Caller 的 endpoint 选择逻辑，发送一次非流式请求，上限 32 输出 Token、60 秒总超时；无自动重试。
- 一个资源只允许一个活动探测，90 秒租约，五分钟重试间隔。同一幂等键不重复调用厂商。失败/不确定结果保持隔离，管理员可在冷却后再次验证。
- 成功提交前锁资源，复核故障代号、模型、凭证版本、密文摘要、厂商状态及配置摘要。并发新 401（即使可见状态不变）生成新故障代号，使旧结果作废；刷新失败也作废旧探测。
- 恢复资源、刷新相关主体的 Key 模型列表、写状态事件、探测证据和操作日志在同一事务中完成。取消期间回滚恢复；过期或已处理的探测不再有恢复权。
- 额度同步仍不能解除 `CREDENTIAL_INVALID`。旧内部 `adminRecover` 不再接受仅递增凭证版本作为鉴权恢复证据；实际轮换继续使用现有管理写事务。
- 健康文案区分额度下一次同步与 Chat 验证；隔离资源的手动额度/模型同步返回明确的隔离提示。

## 迁移与历史兼容

`0073_credential_chat_probe` 添加独立鉴权故障身份及模型/配置摘要，并新增探测记录表。

历史数据只在最新隔离事件为 `CREDENTIAL_REJECTED` 且能关联到附近真实 401/403 Attempt 时补齐原模型。没有模型证据时拒绝探测，不猜默认模型。历史故障没有 endpoint 摘要，只能使用当前部署配置进行复核；新故障由真实 Caller 记录配置摘要并校验一致性。

不保存凭证明文、上游原始错误或业务正文。`GET .../credential-probes` 只返回明确投影的模型、凭证版本、结果、时间与白名单诊断，不返回密文或摘要。已有探测记录时拒绝破坏性 down；发布时优先保留增量表做前向修复。
