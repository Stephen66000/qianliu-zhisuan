## 触发事实

1. 当前确认的可用 1.0 `6fc1bec2…` 首页明确实现并测试“八项指标”，另有条件展示的“需要处理”；员工区只有本月总量与员工排行，没有日／周／月切换。
2. 冻结开发规划 §2 把“六项本月指标＋员工日／周／月”写成 1.0 必须保留合同。
3. 同一规划把员工／项目日周月放在 FR2-003、W20-04／05；PRD §7.1／§7.3、AT-003 和原型也把它定义为 2.0 增量。
4. PRD 要求 2.0 首页固定六项及固定区域顺序；AT-001 又要求任何 1.0 字段不得丢失。若直接按“六项就是 1.0”写特征测试，会把不存在的历史能力冒充基线，并可能静默删除八项中的旧字段。

## 生效决策

1. 1.0 事实基线改为：八项现有指标／字段、条件“需要处理”、资源摘要 14 列与模型下钻、本月 Token 总量和员工排行。
2. 2.0 目标仍按 PRD：首页主概览固定六项并按 `本月概览 → 资源摘要 → 员工消耗 Token` 排列。
3. 为同时满足 AT-001，1.0 的充值、调度节省、最早耗尽、资源状态等旧字段不得删除。冻结稳定落点：充值与调度节省放在资源摘要上方的常驻“1.0 经营补充”区；最早耗尽与资源状态放在常驻资源摘要及资源详情。零值、健康态和不可计算态也必须显示，不得依赖条件出现的“需要处理”区；每项绑定直接 URL／字段 oracle 和自动回归。
4. 员工／项目日周月、单主体选择和趋势明确属于 FR2-003，由 W20-04／05 实现；W20-01 只锁住当前本月总量／排行与 1.0 请求事实。

## 备选方案

- 把六项和日周月当作历史 1.0：与当前代码事实冲突，不建议。
- 2.0 继续保留八张主卡：与已冻结 PRD／原型“固定六项”冲突，不建议。
- 推荐“六项主概览＋旧字段稳定入口保留”：同时尊重 2.0 设计与 1.0 不减能力合同；单纯条件展示或未定义下钻不算保留。
