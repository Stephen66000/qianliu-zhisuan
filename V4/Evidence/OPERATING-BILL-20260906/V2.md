# 第二批：原型合并与主体月度订阅金额

2026-09-06。沿用独立分支 codex/operating-bill-redesign-0906。本文件更新第一批 README 中关于员工／项目订阅金额的待确认状态。

## 本轮确认

订阅费仍按当月使用占比分配。“删除套餐分摊列”是调整报表字段，不是取消费用分配算法。每份套餐分别计算：本月套餐费用 × 该主体本月套餐 Token ÷ 该套餐所有主体本月 Token。分母含员工与项目，只限所选自然月，缓存已包含在输入 Token 中，不重复相加。

## 已完成的产品代码

- 员工／项目每列一个数：总 Token、输入、输出、缓存命中；DeepSeek Token 和 API 消费；智谱 Token 和订阅金额；Kimi Token 和订阅金额；API 消费合计、活跃天数、请求次数、最后一次使用。
- 移除主表的使用厂商拼接列、额度扣减、套餐分摊、归集成本、活跃／请求合列及用量口径列。估算和未知 Token 仍保持原来的明确表达，不伪装为精确值。
- 后端厂商分组增加 totals。未使用的厂商显示零；旧接口有厂商却没有分项数据时显示未知。
- 启用新资金账的草稿月份：从 provider_finance_event 取得当前自然月套餐实付净额，按 ledger_line.settled_at 选取当月 Token，按资源和主体分配。先计算完整分母，再执行厂商、搜索和分页筛选。
- 以数据库现有 8 位金额精度分配尾差，固定按余数及主体 ID 排序，确保主体金额合计守恒。下钻再按请求 Token 分配该主体金额。
- 未启用新资金账的旧口径及 CLOSED 已冻结金额不改写；两类数据均增加厂商分项返回。
- 部门表和项目负责人／部门归属模型本轮未改，继续作为下一项独立处理。

## 原型第二版

- 套餐利用率：合并月度 Token 和历史峰值利用率，两者在同一行；不再显示第二张重复月份表。
- 采购复盘：保留年度采购实付矩阵；DeepSeek 明细按月份逐行，期初余额、充值到账、实际付款、API 消耗、期末余额各占一列；下方以 Kimi、智谱两行展示各月峰值利用率。
- AI 使用趋势：桌面顶部一行四个数，公司月均 Token、公司月均环比、本月人均 Token、本月人均 Token 环比；月度明细仍以月份为行。
- “公司月均”暂按用户前句所指的公司当月总 Token 理解；人均暂按公司当月总 Token（含项目）÷ 当月平均在职人数。已向用户提出可选口径问题并说明本轮原型采用这一假设，尚未接入正式统计 API。
- 原型数据仍为示例。套餐峰值百分比与订阅费月度分配占比为不同指标。
- 跨月／年付订阅如何按服务月计费仍待另行确定；本轮没有改写厂商资金账现有付款月规则。
