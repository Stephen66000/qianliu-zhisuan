# 历史额度补充：独立受控合同

当前实现只提供 `quota-reconcile preview` 和 `preflight`；`--apply` / `--execute` 被明确拒绝。没有本次历史生产写入，也没有伪装成已经实现的 apply 执行器。

## 已交付能力

- 显式企业、员工范围、半开时间范围；repeatable-read + READ ONLY。
- 原始 ledger_line 来源、真实 Token、套餐扣减、API 金额、已用质量及当前授权/旧 counter 证据。
- 当前授权不是历史授权证明；不能确定的旧 grant/version 标 UNKNOWN，original/target/difference 为 null。
- 确定性清单 hash；生产记录不写、不删除、不按今天价格重算。隔离 PG/只读 CLI 用例已验证该边界。

## 如果以后授权写入，必须先满足的合同

1. 冻结一份有唯一 hash 的执行清单，逐条来源、历史 grant/version/basis/月归属可证明。UNKNOWN 行不能进入可执行集合。
2. 写前重新核验源记录与原值；变化则拒绝旧清单，不按旧差额盲加。
3. 内部补充事实使用来源唯一标识并保留原/目标/差额和批准原因，同一来源重复执行不得重复加量；与对应计数调整同事务。
4. 不改原 input/output、规则快照、套餐 deducted_quota、API 金额、已结财务账，不执行第二次厂商收费。
5. 失败无部分提交，结果逐行可追溯；不可证明历史完整性时继续待核。不得以补记为借口清空、回写或重算原账本。
6. 生产执行与消息更正分别授权。历史补充不能自动触发旧报告发送。

上述写入合同是后续独立实施/授权的约束，不作为本批新月正常计量上线的隐含任务。新月独立建账，不依赖把 9/19 起累计账强行改成旧月预算。
