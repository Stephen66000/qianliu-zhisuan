## 需要确认的合同变化

当前项目工程规范 `V3/仟流智算-质量门禁-v1.0.json` 锁定 Node 22.17.x，package engines 为 >=22.17 <23。Undici 8 的已核实修复版本要求 >=22.19.0。因此要保持测试工具依赖主版本并消除该条公告，需要提升项目的 Node 22.x 最低运行版本，连带核对开发、CI、候选容器的版本一致性。

推荐：使用项目局部固定的、已修补的 Node 22.x，不改变用户系统默认 Node；审批并记录运行时合同后再更新依赖及锁文件。未来生产镜像变化仍是独立发布动作，当前不部署。

不建议：为让审计变绿新增 blanket ignore、把测试依赖从审计中藏掉，或未经兼容测试将全部 Undici 8 强制降成7、全部旧 minimatch强制换成11。

## 执行与再验收

1. 用户同意依赖/项目局部运行时范围后，记录 Planning Change 和精确版本。
2. 在现有长时测试自然结束的检查点更新，避免node_modules切换污染正在运行的coverage/mutation/E2E；不删除用户环境/数据库。
3. 安装后审计 moderate以上归零，或对确无修复的条目提供实际证据而不自行接受风险。
4. 在新依赖/局部Node下重新绑定最终候选，复跑全仓测试、构建、覆盖/ratchet、变异、浏览器与官方CLI本地E2E及许可证/零留存检查。旧依赖下结果不能冒充新候选通过。
5. 生产迁移、发布、历史补扣和重发不在该确认范围。
