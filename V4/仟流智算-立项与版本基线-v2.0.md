> 仟流智算 2.0 是单个客户企业使用的产品，是 1.0 的原位增量升级。仟流科技总控台是另一个产品，本轮不启动。

## 1. 当前版本唯一目标

在完整保留 1.0 页面、数据口径和管理闭环的基础上，交付通讯录导入、员工／项目周期用量、部门预算与唯一成本归集、月度经营补强、资源利用事实和轻量采购复盘。

标准版先使用合成、可重复的 100 人企业样本完成工程验收，不等待客户访谈、设计客户签字或完整自然月。

## 2. Scope

- `FR2-001`：1.0 兼容与管理闭环保留；
- `FR2-002`：企业微信／飞书单向同步与 Excel 模板导入；
- `FR2-003`：员工／项目、全部／单主体、今日／本周／本月用量；
- `FR2-004`：部门预算、实际 Token、警戒线和唯一成本归集；
- `FR2-005`：1.0 月度经营完整保留并增加采购清单、部门账；
- `FR2-006`：逐资源利用率、耗尽、最近使用和连续无调用事实；
- `FR2-007`：轻量采购复盘和人工备注。

## 3. Non-scope

- 仟流科技总控台、跨客户企业目录、企业开通／退租／归档／销毁；
- 平台运营管理员、跨企业支持访问和平台／企业双控制面；
- Agent 新运行入口或自动执行；
- 正式对账与导出后端；页面只显示 `Coming Soon`；
- 企业坐席／厂商成员账号、厂商实时市场价格、跨厂商效果评价；
- 后台固时任务、自动采购、自动充值和大 BI；
- 客户访谈、设计客户确认和商业验证作为工程开工条件。

## 4. 1.0 不可破坏边界

- Gateway、Attempt、Usage、Ledger、Settlement、Key、路由、额度和正文零留存继续作为底座；
- 首页资源摘要及按模型下钻、主体接入配置、批量模型授权、厂商资源、额度规则、请求明细、月度账、运行保障、管理员、操作日志和升级日志不得减少；
- 现金采购、API 实际费用、套餐成本、厂商原生窗口和内部预算分别展示，不互相伪换算；
- 组织、项目和预算变化不改写历史请求、账本或已关闭账单；
- 当前 1.0 精确代码起点和真实迁移头由 W20-01 重新核验，不机械回退旧 Tag，不覆盖用户改动。

## 5. 标准验收样本

| 对象 | 标准样本 |
| --- | --- |
| 企业 | 1 个客户企业 |
| 人员 | 100 名员工 |
| 组织 | 多级部门，含调岗前后与待归属 |
| 项目 | 100 个以内，含负责人和明确归属部门 |
| Principal | 200 个以内，覆盖员工、项目和自动化工作负载 |
| 资源 | DeepSeek API、Kimi Coding Plan、智谱 Coding Plan |
| 用量 | 员工／项目、今日／周一至周日／自然月、全部／单主体 |
| 账单 | 草稿、检查、关闭、重开和多个历史版本 |
| 数据量 | 标准目标每月 100 万条已结算 Ledger；更高档位通过容量 Evidence 再提升 |

原型中的 6 名员工和示例金额只用于走查，不是容量或测试真值。

## 6. 成功与退出条件

- PRD、TRD、原型、验收矩阵、架构图和开发计划一致；
- `M20-0～M20-5`、`W20-01～W20-11` 与 `AT-001～008` 在同一候选收口；
- 1.0 回归无确认外的功能缺失，七项 FR 正常／异常／权限／幂等／历史口径测试通过；
- 部门合计＋待归属＝企业总成本，重复归集和重复结算为 0；
- Secret、完整 Key、密码、令牌和请求正文泄漏为 0；
- 目标环境安装／升级、健康检查、必要回退与恢复完成；
- P0／P1 和阻断性 Evidence Gap 为 0 后，`delivery_status=done`；不等待业务验证。

## 7. 主要风险

| 风险 | 等级 | 缓解与退出条件 |
| --- | --- | --- |
| 2.0 改版删减 1.0 已可用能力 | `HIGH` | W20-01 先冻结兼容回归；AT-001 在最终候选复验 |
| 通讯录错误匹配／重复建主体 | `HIGH` | 稳定外部 ID、幂等键、冲突待处理，禁止按姓名猜测 |
| 项目与员工成本重复归入部门 | `HIGH` | 请求时点唯一归属；守恒测试自动阻断候选 |
| 三个入口形成三套用量算法 | `HIGH` | 统一服务端聚合，回算同一请求／Ledger 事实 |
| 厂商未知数据被伪造为 0 或精确日期 | `HIGH` | 来源、数据时间、单位与不可计算原因强制展示 |
| 无客户前置导致标准判断需校准 | `NORMAL` | 先交付标准版；首个真实客户改变合同则走 Planning Change |
