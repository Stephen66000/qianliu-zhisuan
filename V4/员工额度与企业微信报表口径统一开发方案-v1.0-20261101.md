## 1. 目标与结论

将员工厂商池额度改为**企业时区每月 1 日零点重置**，同时补齐 API 内部额度计量，统一日报、团队/个人周报和月报的取数与余额解释。保留当前允许超额设置；不能为了修图关闭员工调用、改财务账、把 22 亿直接减去 27.1 亿或清空旧计数器。

最初授权为“使用 OpenSpec 形成具体方案”，用户随后明确授权“使用多个 GPT-6.1 Sol 子 agent 做具体执行”。本地实现与定向验证已完成；本文件不把开发授权扩大为提交推送、生产迁移、发布、历史补扣或补发授权。实施结果见 [本地交付报告](Evidence/EMPLOYEE-QUOTA-REPORTING-20261101/实施交付报告-20261101.md)。

采用现有本机 OpenSpec CLI **1.15.0**，工作流为 proposal → specs/design → tasks；不重新初始化项目、不安装新 Skill、不调用外部模型。执行时关闭本次 CLI 遥测。结构和场景依据 [OpenSpec 官方工作流](https://github.com/Fission-AI/OpenSpec) 与本机 `spec-driven` schema，严格校验记录见同目录变更包。

## 3. 已确定的业务规则

| 规则 | 明确定义 |
|---|---|
| 周期 | 企业时区自然月，`[本月1日00:00, 下月1日00:00)` |
| 重置 | 新月新账、已用/预占从零开始；旧月不删、不物理清零；未用不结转 |
| 月度分配 | 月初继承有效授权模板；月中新开通领取全额，不按天折减 |
| 月内调整 | SET 改总上限，ADD 追加；保留已用/预占，改变后续月份继承值并留前后记录 |
| 停用后再启用 | 准入服从授权；同员工同厂商本月已有用量不丢失，不靠新 Grant 领取第二份额度 |
| API 内部已用 | 实际 input + output，cache 为 input 子集不重复加；API 金额继续独立 |
| 套餐内部已用 | 冻结规则的额度扣减；真实 Token 保持原量 |
| 超额 | 允许则继续并记超额；禁止则预占不足时拒绝。实际大于预估时照记，后续请求按余额处理 |
| 余额 | 单个同口径池 `可用=max(0,分配−实耗−未结清预占)`；另列 `已确认超额=max(0,实耗−分配)` |
| 单位 | API raw 与套餐折算额度按厂商分列，不再混成统一剩余 Token |
| 请求月份 | 每次 Attempt 以上游前预占时间归月；跨月完成回原月，新月新 Attempt 归新月 |
| 用量统计 | 活动报告延续成功已结算请求；额度覆盖所有真实消费 Attempt，失败实耗也计，明确二者差异 |
| 周报附带额度 | 截至上一完整周结束的所属月份，显示具体截至日期，不使用服务器当前计数器 |
| 旧月缺事实 | 显示“待核账/历史未留存”，不以零或无限代替 |

“每月重置”已由用户选择；“首个完整自然月生效”是本方案推荐的上线安排，随方案审阅确认。若 11 月完成上线，推荐首个周期 **2026-12-01 00:00（企业时区）**，不在当前月中清零。若要追溯 11 月，必须先调整迁移计划、核账预览及影响清单。

## 4. 方案分两段实施

### A 段：先让报告正确且可解释

修改共享查询、自然期间、员工范围、模型占比与图文展示。暂时不改变网关的实际准入和额度计数；老余额缺证就明确待核。

十月图片候选应呈现：

- 真实用量仍为 27.1 亿、22607 次、日均 8740.2 万。
- 额度区不再出现“22 亿 − 3.9 亿 = 月末剩余 18.1 亿”。
- 改为额度范围/待核状态/超额策略摘要，并在厂商明细标注实际 Token 或套餐折算额度；若引用 22 亿，仅标旧授权配置，不能称十月已证月额度。
- 员工排名与 Top3 模型结构保留，实际模型数与展示数分开；GLM 5.3 Flash 和 GLM 5.3 保留两行。
- 个人报告与文字同源，不再各算一遍“剩余额度”；保持原发送窗口和防重身份。

A 段可独立形成 Worker 候选，但发布须针对新候选获得授权；不会因内容修正重发已 SENT 消息。

### B 段：按月额度与 API 计量闭环

```mermaid
flowchart LR
    A[当前有效员工厂商授权] --> B[企业时区月份与计量基础]
    B --> C[本月额度账和Attempt预占]
    C --> D[实际调用]
    D --> E[原月份终态结算]
    E --> F[同源配置页与图文报表]
    A --> G[月初新建下月账]
    G --> C
```

1. 两张最小关系表保存月账及 Attempt 的预占/结算归属；现有授权增加计量基础、企业增加未来生效时点。旧 quota_counter 留历史。
2. Gateway API/套餐共用月度额度入口，套餐并发租约、Key 限制、厂商余额和套餐窗口继续独立。
3. Control API 单人及批量授权变更与月账调整、类型化前后审计同事务；配置页与报告同源。
4. Worker 月初建账，Gateway/当前月查询按需初始化兜底；重复调用只建一个月账。历史查询不拿今天配置伪造旧月账。
5. 新月开始后旧月仍接受其在途 Attempt 的实际结算；未知保持待核，不作为免费使用。
6. 新结构 additive，编号由实施时实际 migration head 决定；不能把旧授权中的 0090 再执行当作本次迁移。

原“仅发布 Worker”授权只对应原修复，不覆盖 B 段的数据库、Gateway、Control API、Worker 和必要 Web 一致升级。
