## 4. 数据契约与计算口径

### 4.1 权威事实与下钻差异
- 复用已有后端事实查询，前端只格式化，不复制计价、分摊、健康判定算法。
- Token = 输入 + 输出，不重复加缓存，不将推理细分或倍率扣减再次相加。明确实报、估算、未知等质量信息。
- 费用沿用经营账单已生效口径，API 费用、套餐费用与现金充值区分；多币种分别展示，不自行换汇。部分已知须保留缺口，未知不是 0。
- 员工和项目分开去重，明确活跃周期、请求状态与有效用量条件，不能相加。
- 关键口径核对：厂商用量总览通常统计成功已结算请求，而经营分析可能包含确有消耗的失败请求；首页 Token 点击厂商用量总览并不自动代表其总量与经营费用同一集合。WP01 必须给出首页四项各自的权威来源、过滤规则和下钻一致性矩阵。以用户指定目的页相应指标口径为优先参照；如存在不可兼容差异，报告具体差异供 Codex 判断，不通过改写既有模块公式强行对齐，不隐瞒差异。

### 4.2 时间及同期
- 返回或记录统一 asOf，当前自然月初至 asOf；明确企业时区与经营账单北京时间差异。各指标按其权威来源统计并说明，禁止悄然混用时区。
- 上月同期对应同一当地日及时间；上月无对应日期时截止上月结束（排他边界），写明截断规则。采用半开区间；固定测试时钟。
- 上月金额/Token 为 0、未知或不可比时不输出正常增长百分比；金额按相同币种分别比较。员工/项目优先显示数量差。
- 旧接口如果只有上月整月费用，必须补真实同期聚合，禁止将整月费用按天数平均折算。

### 4.3 资源状态
- 展示正常、局部异常/异常、待确认等有事实依据的调用状态；映射必须来自现有状态证据，保留数据更新时间。
- 额度同步成功不能证明调用恢复；额度同步失败也不能抹掉已知调用成功。
- 人工已处理与客观已恢复分开；健康数据缺失或过期不得冒充正常。
- 关注信息复用已有异常、同步、供给风险事实，以简短固定模板生成，避免泄露凭证或原始上游敏感内容；无必要不引入大模型生成。
- 按厂商聚合需防止同一问题重复计数，正常厂商也展示；厂商稳定排序，资源数量来自真实数据。

## 6. 验收清单

- AC01：四张卡片真实取数，无样例常量或前端造数；数字单位、精确值、费用币种可理解。
- AC02：同期边界覆盖月初、大小月、上期零值、缺失、企业时区差异；部分当前月不对比完整上月。
- AC03：Token 缓存不重复、套餐倍率不污染、重试请求去重；活跃员工与项目各自去重；保留消费失败记录口径差异的解释证据。
- AC04：正常资源完整可见；局部异常、同步失败但调用成功、凭证失效后只恢复同步等代表性组合正确。
- AC05：五个入口在浏览器里实际进入准确 Tab/页面；返回、刷新和直达均保持路由状态；不再是原型弹窗。
- AC06：保留既有权限与开关行为；无越权数据或无权限目标误导。
- AC07：参考原型核对浅色/深色/跟随系统，1440px 与 1024px 以及常用笔记本视口；不得横向溢出、金额截断或异常文案重叠。正常数据场景为主，同时保留现有错误处理，不能请求失败时清零。深色状态底色正确使用透明度；复用合适的品牌资产，不能照搬原型深色白底 Logo 缺陷。
- AC08：相关 lint/typecheck、后端聚合集成测试、前端交互与路由测试通过；依据变更风险执行现有适用 V1.4 门禁。记录请求次数/查询变化，避免首页引入明显性能退化。
- AC09：更新模块说明首页章节，注明真实数据源和五个入口；不改未涉及的业务算法。
