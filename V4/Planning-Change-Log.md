## PC-20260811-01：由设计客户前置改为标准版先行

| 字段 | 内容 |
| --- | --- |
| 状态 | `done` |
| 提出时间 | 2026-08-11 |
| 生效时间 | 2026-08-11 |
| Planning 负责人 | Codex（记录与影响分析） |
| 批准人 | 佳哥（产品／技术 Owner） |
| 批准依据 | Owner 明确决定：“客户访谈、客户确认肯定没有；不能等聊完客户再做，只能先做一个标准版。” |
| 生效基线 | PRD／TRD／开发规划 `v2.0-draft.3` 及后续版本 |

### 变化前

- Gate 0 要求至少三家目标企业访谈；
- 必须确认一家设计客户、真实组织样本和双方签字人；
- 没有设计客户不得进入正式 2.0 开发；
- 完整自然月和客户签字同时作为 2.0 工程封板条件。

### 变化后

- 2.0 采用“标准版先行”：以已知企业 AI 资源经营共性、1.0 真实系统边界和内部代表性标准样本完成产品与技术方案；
- 客户访谈和设计客户确认不作为 Stage 01、Stage 02 或开发交付的前置条件；
- 未经客户验证的内容只允许标记为标准版假设，禁止声称已证明客户付费意愿或商业价值；
- 客户 Pilot、完整自然月、付费／续用验证转为交付后的独立业务验证轨道；
- 首个真实客户若改变目标、范围、部署、安全、组织、身份源、容量或验收合同，重新发起 Planning Change。

### 影响范围

- PRD：版本目标、目标客户、Gate、成功指标、业务验证假设和 DEC 清单；
- TRD：容量包络、部署假设、身份源和导出方案的冻结方式；
- 开发规划：阶段顺序、里程碑、开发退出条件、排期和业务验证轨道；
- 原型与验收：改用内部代表性标准组织样本，并显式标注“非客户 Evidence”；
- 风险：产品市场匹配风险上升，技术与交付风险不因此降低。

### 明确未影响范围

- 1.0 `v1.0.0-final`、数据库迁移 `0044` 和既有 Evidence；
- 1.0 Gateway、Token、账本、Settlement、正文零留存和安全不变量；
- Agent 不进入 2.0 标准版及交付后首轮业务验证；
- 企业隔离、RBAC、迁移、恢复、结账一致性仍按 `HIGH` 风险检查；
- commit、push、merge、publish、生产数据和外部系统操作权限没有扩大。

### 新增缓解措施与复查触发点

1. 建立标准组织 Fixture，覆盖 1 个企业、组织、团队、成本中心、人员、项目、资源和八类角色；
2. 原型必须完成企业开通、权限、资源、预算、结账、失败恢复和企业归档走查；
3. FR 级初始验收矩阵必须区分“开发交付验收”和“交付后业务验证”；
4. 关键未知项通过 PoC／ADR 冻结，不以“标准版”名义跳过安全和恢复验证；
5. 首个真实客户进入前重新核对角色、身份源、部署、容量、数据保留和业务指标；
6. 客户提出足以改变冻结合同的要求时，触发新的 `PC-YYYYMMDD-NN`。

### 恢复执行点

从 Stage 01 `doing` 恢复：先完成标准版原型、初始验收矩阵和关键 PoC，再执行 Stage 01 完成检查。Stage 01 未达到 `done` 前，Stage 02 保持 `todo`，不得开始产品代码开发。

## PC-20260811-02：回收全局身份核验扩张，保留最小双控与判别式导出

| 字段 | 内容 |
| --- | --- |
| 状态 | `done` |
| 提出时间 | 2026-08-11 |
| 生效时间 | 2026-08-11 |
| Planning 负责人 | Codex（记录、回收与一致性复核） |
| 批准人 | 佳哥（产品／技术 Owner） |
| 批准依据 | Owner 在确认“全局自然人／实名核验方案属于过度治理”的判断后明确回复：“同意”。 |
| 生效基线 | PRD／TRD `v2.0-gate1.1`、验收与角色矩阵 `v1.3`、原型 `v1.8` 及 Stage 02 最终计划 |

### 触发原因

- Gate 1 末轮一致性检查发现：支持访问的跨 realm 职责分离无法仅靠账号名证明真人不同；导出 manifest 同时兼容经营账单和退租最终导出时，来源字段存在可混用空间；
- 曾考虑引入全局 `natural_person`、绑定状态／版本、初始双人核验 CLI 和全员高风险身份核验；该方案把 2.0 标准版扩成身份治理平台，超过当前客户证据、产品目标和必要安全边界；
- Owner 同意按“最小标准版”回收，不以技术复杂度掩盖无法证明的真人身份事实。

### 决策

1. 删除全局自然人主数据、实名核验、跨 realm 自动去重、`PENDING/VERIFIED/REVOKED` 绑定状态机、核验 CLI 和绑定事件等扩张；
2. 保留账号级最小双控：不同账号、独立 realm／Session、独立权限、TOTP step-up、状态机、TTL 和不可变审计；
3. 交付形成高权限职责清单，记录平台账号、企业 Owner 账号、声明持有人和禁止组合；该清单是管理控制，不是技术实名证明；
4. 未披露的同人多账号作为明确残余风险；真实 SSO／统一身份合同出现后在 2.1 重新设计；
5. 保留判别式 `EXPORT_MANIFEST_V1` 修复：`export_kind=source.kind`，经营 Statement 与退租最终导出的来源字段互斥且完整，`source_fingerprint=SHA-256(RFC 8785 JCS(source))`，下载 token 绑定 kind＋来源指纹。

### 影响范围

- PRD／TRD：身份、支持访问、生命周期、Owner 恢复、销毁和导出合同；
- 初始验收矩阵／角色权限矩阵：删除无法执行的真人核验断言，改为账号、realm、权限和职责清单验收；
- 开发规划：删除全局身份绑定 Schema、CLI、API、事件和测试工作量；保留本地身份、MFA、恢复和必要双控；
- ADR／原型／Evidence：同步最小边界与残余风险，补测判别式导出来源和职责清单展示；
- Stage 01 在变更期间临时回到 `doing`，同一候选完成复核后重新锁定；客户业务验证仍为 `todo`，不转成开发门禁。

### 明确未影响范围

- 企业内 `person_id`、RBAC、Provider Secret 双角色确认、分摊自建自批限制和 Principal Key 本人边界；
- 企业隔离、RLS、账期四态、结账一致性、恢复、正文零留存和标准容量合同；
- Agent、OIDC／SSO、共享 SaaS 仍不进入 2.0 标准版；
- 未授权任何 commit、push、merge、publish、产品编码、生产数据或外部系统操作。

## PC-20260812-03：2.0 回归客户企业产品，1.0 原位增量升级

| 字段 | 内容 |

| 生效时间 | 2026-08-12 |
| Planning 负责人 | Codex（记录、影响分析与受影响基线回写） |
| 批准人 | 佳哥（产品／技术 Owner） |
| 批准依据 | Owner 明确冻结“仟流科技总控台”与“仟流智算 2.0”为两个产品；本轮只推进仟流智算 2.0，并于 2026-08-12 确认最终原型 |
| 生效基线 | 已确认原型、`POOL20-001～024`，以及本次回写后的 PRD／TRD／开发规划／验收与派生 HTML |

### 变化前

- 2.0 同时承担仟流科技平台运营、多企业开通、跨部署管理、企业生命周期与客户企业内部经营能力；
- PRD／TRD／开发计划包含平台运营管理员、Platform API、跨企业目录、退租／归档／销毁、支持访问双认证平面等总控台能力；
- 开发计划以企业隔离、平台／企业双控制面和完整账期状态机为主线，弱化了 1.0 已可用页面的原位继承。

### 变化后

1. “仟流科技总控台”作为独立产品方向，本轮不启动，不进入仟流智算 2.0 scope；
2. 仟流智算 2.0 是单个客户企业实际使用的产品，在 1.0 可用版本上原位升级；允许优化 UI，但不得删减、替换或重写 1.0 已有功能；
3. 2.0 当前增量冻结为：组织通讯录单向同步与 Excel 导入、员工／项目日周月用量、部门预算与唯一成本归集、月度经营补强、逐资源利用率／耗尽／闲置事实和轻量采购复盘；
4. 对账与导出只保留 `Coming Soon`，Agent、企业坐席／厂商成员账号、跨厂商效果评价、实时市场价格、后台定时任务和自动采购均不进入本轮；
5. 1.0 的首页、使用主体、批量模型授权、厂商资源、额度规则、请求明细、经营账单、运行保障、管理员、操作日志和升级日志完整保留。

### 影响范围

- 产品：PRD 的定位、角色、FR、scope／non-scope、成功标准和页面合同；
- 技术：TRD 的系统边界、架构、数据、接口、兼容迁移和测试主线；
- 计划：纵向里程碑、工作包、依赖、DoD、排期、风险和 Stage 03 当前对象；
- 验收：从平台运营／企业生命周期验收改为 1.0 回归与六条增量业务主线验收；
- 派生成果：技术架构图、Stage 02／Stage 03 进度表和开发执行基线绑定。

### 明确未影响范围

- 1.0 `v1.0.0-final` 的既有实现、生产数据、Evidence 和当前生产使用；
- Gateway、Attempt、Usage、Ledger、Settlement、Key、模型路由、正文零留存等 1.0 技术不变量；
- 客户访谈与设计客户仍不是标准版开发前置条件，真实业务验证继续单独统计；
- 本变更不授权 commit、push、merge、publish、生产数据修改或外部系统写入。

### 风险、检查与恢复执行点

- 最大风险由“平台级多租户安全”收敛为“2.0 改版破坏 1.0 可用能力”；因此首个开发里程碑必须建立 1.0 功能与数据口径回归基线；
- 通讯录导入、部门归属和月度成本守恒涉及数据写入与历史口径，相关工作包维持 `HIGH`；纯展示增强默认 `NORMAL`，命中迁移、权限或账本变更时升级；
- 只重锁受本变更影响的 Stage 01／02 成果，不重跑已经成立且未受影响的 1.0 Evidence 和 PoC；
- PRD、TRD、开发规划、验收矩阵、架构图和进度表已通过一致性检查，本 Change 转为 `done`；Stage 03 仍为 `todo`，首个工作包固定为 `W20-01`，等待 Owner 单独授权启动。

## PC-20260812-04：校准首页 1.0 事实与 2.0 增量归属

| 状态 | `done` |

| 批准依据 | Owner 指示：“能不能别让我确认了，你直接全部做完吧。”据此采用本变更推荐口径完成 W20-01 收口 |
| 触发工作包 | M20-0／W20-01 |
| 生效基线 | 本变更回写后的 PRD／TRD／开发规划／验收矩阵／原型／开发执行基线 |

### 变化前

- 当前可用 1.0 首页实际为八项指标、条件“需要处理”、资源摘要 14 列及模型下钻、本月 Token 总量和员工排行；
- 开发规划误把“六项主概览＋员工日周月”写成 1.0 基线；
- PRD、AT-003、原型和 W20-04／05 又把员工日周月定义为 2.0 增量。

### 决策

1. 1.0 首页事实基线冻结为当前八项指标／字段、条件“需要处理”、资源摘要 14 列与模型下钻、本月 Token 总量和员工排行。
2. 2.0 首页主概览仍固定六项，并保持“本月概览 → 资源摘要 → 员工消耗 Token”顺序。
3. 本月充值、本月调度节省迁入资源摘要上方常驻“1.0 经营补充”；最早耗尽资源、资源状态在常驻资源摘要及资源详情保留。零值、健康态和不可计算态不得隐藏，也不得只依赖条件出现的“需要处理”。
4. 员工／项目日周月、单主体选择和趋势属于 FR2-003，由 W20-04／05 实现；W20-01 只冻结当前月度总量、员工排行和 1.0 请求事实。

### 影响与恢复执行点

- 仅回写受影响的首页合同、R02 特征测试和绑定 Hash；不改产品范围、架构、数据模型、迁移或排期。
