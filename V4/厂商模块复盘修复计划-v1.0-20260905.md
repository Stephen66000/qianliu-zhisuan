## 2. 利用率口径及接口

```text
利用率 = 所选月份已结算真实 Token / 最近可用的 1～3 个完整自然月真实 Token 均值
```

- 每个具体资源独立计算，API 与 Coding Plan 算法一致。
- 真实 Token 只加输入和输出，不重复加缓存与推理 Token。
- 使用企业时区划分自然月，当前月只累计到查询时刻，不预测月底、不按月份进度折算。
- 选择 2026-09 时，基线是 2026-06、07、08。
- 无调用月份计 0；资源登记时间晚于基线月月初时，该月不算完整历史月。
- `baselineMonthCount` 是最近三个月内资源已完整覆盖的自然月数量，允许为 1、2 或 3。
- 有 1 个完整月就按该月计算；有 2 个就按两个月均值；有 3 个及以上只滚动取最近 3 个。
- 资源登记所在的非完整月份及其 Token 不进入分母。
- 只有没有完整历史月时才因 `INSUFFICIENT_HISTORY` 显示 `—`。
- 完整历史月均为 0 时显示 `—`；本月为 0 而历史均值大于 0 时显示 0%；超过 100% 不截断。
- 以 `settled_at` 归月；旧账本没有该字段时沿用现有 `created_at` 兼容语义。

在 `GET /provider-resources/utilization?month=YYYY-MM` 的每条资源记录中增加：

```ts
tokenUtilization: {
  currentMonthTokens: string;
  trailingThreeMonthAverageTokens: string | null;
  baselineMonths: string[];
  baselineMonthCount: number;
  rate: string | null;
  basis: "CURRENT_MONTH_VS_UP_TO_3_COMPLETE_MONTHS";
  unavailableReason: "INSUFFICIENT_HISTORY" | "ZERO_BASELINE" | null;
}
```

采用一条批量 SQL 聚合所有资源的四个月 Token，数值在 PostgreSQL 内使用 numeric 计算；月均值和比率保留八位小数。百分比从未舍入的可用完整月总量和月份数计算。

此字段只加到厂商资源利用接口。原 `utilizationRate`、API 预算、套餐权益、经营账单、采购复盘及冻结快照继续使用既有合同。前端共享类型中的字段为可选，以兼容没有此字段的采购复盘和旧响应，不回退展示旧利用率。

厂商模块显示精度统一：金额固定两位、利用率一位、Token 整数；速度、覆盖时长、额度窗口数值和近月平均 Token 最多两位并去掉无意义尾零。接口与数据库继续保留原始精度。

主要实现：`apps/control-api/src/resource-insights/token-utilization.ts`，由资源利用接口批量调用。

## 3. 主体额度汇总

- 根因：旧查询使用 `model_alias` 与具体统一模型匹配，厂商池的 `model_alias="*"` 无法匹配；API 分支漏算。
- 按 `pool_model_alias="*"` 识别厂商池，按厂商累计当前有效 Grant。
- 有效范围：`status=ACTIVE`，`valid_from <= 统计时刻`，`valid_until IS NULL OR valid_until > 统计时刻`。
- 有效厂商池优先；同一主体的同厂商历史型号授权不重复累计。
- 没有有效厂商池时保留原型号级授权兼容逻辑。
- 池额度按 Grant 累计，模型或路由数量不会令额度翻倍。厂商池是厂商共享额度，不按型号拆分。
- 主体接入配置保存成功后，刷新用量总览缓存。

主要实现：`packages/database/src/repositories/dashboard-breakdown.ts`。
