## 4. 迁移（0076 + 0077，纯加法）

- `provider_model_probe_run`：企业/Provider/资源（resource 可空，覆盖接入前）/凭证指纹/endpoint scope+host/发现快照哈希/parser version/status/idempotency_key/request_hash/时间。
- `provider_model_probe_item`：run 外联/upstream_model/validation_status/http_status/统一 error_code/error_category/retryable/diagnostic_hash/checked_at。
- **0077（P2-5）**：`provider_model_probe_run` 增加 `(enterprise_id, idempotency_key)` 唯一约束；仓储层 `recordModelProbeRun` 改为 `INSERT ... ON CONFLICT DO NOTHING RETURNING id` + 冲突后回查的原子幂等，并发写入恰落一条 run。
- 不含任何可容纳 Key、Authorization、Prompt、原始错误正文的列（集成测试断言列名黑名单）。
- 旧 `provider_model_discovery_item` 快照不受影响；探针写入失败不再静默吞掉——由调用方 `persistProbeRun` 捕获并 `app.log.warn` 记录（P2-5 整改，删除原 `catch(() => null)`）。
- 失效机制：`request_hash = sha256(providerCode|mode|fingerprint|scope|host|目录内容哈希|模型集)`，Key、模式化端点或官方目录任一变化 → 新 hash → 旧结果不再作为最新证据返回。

## 5a. 整改项 1-5 收口明细（commit / 文件 / 根因与修复）

### 整改 1（P1-1）— commit `8823562`
- **根因**：`credential-probe-routes.ts` 的 `providerCode()` 对 config 匹配大小写敏感，Kimi/KIMI/kimi 变体落不进 Coding Plan 分支；caller 未拿到 `capability_set.base_url`，无法走 RC-0 端点策略。
- **修复**：`providerCode()` 改用 `canonicalProviderCode` 匹配；caller 调用补传 `capability_set.base_url`。
- **文件**：`apps/control-api/src/providers/credential-probe-routes.ts`、`src/__tests-integration__/credential-chat-probe.test.ts`。

### 整改 2（P1-2）— commit `e0cc720`
- **根因**：`compatible` 作为"可选"口径语义混杂，与 `credentialValidation` 三层状态不一致；无凭证验证证据时仍可能可选。
- **修复**：`toPublicModel` 的 `selectable`/`compatible` 统一为 `credentialValidation.status === "READY"`；`selectCompatibleModels` 更名 `selectReadyModels`；`publicStoredDiscovery` 无证据时 `selectable=false`；Web fallback 同步 READY 口径，状态行文案改"凭证验证通过 · HTTP 200"。
- **文件**：`apps/control-api/src/providers/contracts.ts`、`contracts-ready.test.ts`（新增）、`model-discovery-routes.ts`、`apps/web/src/components/resources/ResourceModelDiscovery.tsx`、`ResourceModelDiscovery.sync.test.tsx`（新增）、`ResourceModelDiscovery.version.test.tsx`、`ResourceOnboardingSection.tsx`、`apps/web/src/pages/Resources.test.tsx`。

### 整改 3（P2-3）— commit `800235d`
- **根因**：`/provider-resources/model-discovery` ad-hoc 检测路由缺 cacheKey/singleflight 与探针落库（`provider_resource_id=null` 场景无证据）。
- **修复**：补 cacheKey/singleflight（键 = enterprise + provider + mode + credential fingerprint + endpoint scope/host）；`persistProbeRun` 支持资源可空的 run/item 落库，仅存脱敏字段（无 Key/Authorization/Prompt/正文）。
- **文件**：`apps/control-api/src/providers/model-discovery-routes.ts`、`src/__tests-integration__/pool027-provider-model-discovery.test.ts`。

### 整改 4（P2-4）— commit `34d7018`
- **根因**：`capability_set.endpoints[API|CODING_PLAN]` 仅 discovery 链路消费；model validation、credential recovery、Gateway 仍只看 `base_url`，Moonshot 地址在 CODING_PLAN 模式可能误覆盖。
- **修复**：`resolveProviderEndpoint` 支持 `configuredEndpoints.base_url + endpoints` 输入；五处消费点统一经 `capabilityConfiguredEndpoints` 抽取——Control API model validation、credential recovery、Gateway 正式调用（main / pipeline-attempt-execution / real-pipeline-types）、openai-compatible-caller。
- **文件**：`packages/provider-adapters/src/endpoint-policy.ts`、`index.ts`、`model-discovery.ts`、`model-validation.ts`、`openai-compatible-caller.ts` + `__tests__/endpoint-policy.test.ts`、`openai-compatible-caller.test.ts`；`apps/control-api/src/providers/credential-probe-routes.ts`、`model-discovery-routes.ts`；`apps/gateway/src/main.ts`、`src/pipeline/pipeline-attempt-execution.ts`、`src/pipeline/real-pipeline-types.ts`（合计 13 个）。

### 整改 5（P2-5）— commit `81048e0`
- **根因**：探针 run 落库为 select-then-insert（并发竞态可重复写入），且仓储层 `catch(() => null)` 静默吞写库错误；run 无稳定身份约束。
- **修复**：0077 迁移加 `(enterprise_id, idempotency_key)` 唯一约束；`recordModelProbeRun` 改 `INSERT ON CONFLICT DO NOTHING RETURNING id` + 回查的原子幂等；删 `catch(() => null)`，`persistProbeRun` 失败由调用方 `app.log.warn` 记录；Kysely `selectFrom` 补显式 `selectAll()`；迁移回滚门禁测试补 0077→0076→0075→0073 层级。
- **文件**：`apps/control-api/src/providers/model-discovery-routes.ts`、`packages/database/migrations/0077_provider_model_probe_run_identity.js`（新增）、`src/repositories/provider-model-discovery-repository.ts`、`src/__tests-integration__/model-probe-migration.test.ts`、`credential-probe-migration.test.ts`（合计 5 个）。
