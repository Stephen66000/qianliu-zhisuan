## 5b. 终审修复轮明细（commit `ac1c6de`，2026-09-21 22:26）

### 终审一（P1）— READY 探针证据身份门禁（MODEL_VALIDATION_STALE）
- **要求**：GET models 与 confirm models 必须拒绝与当前资源/当前成功发现不一致或过期的 READY 探针证据；身份不匹配返回 `MODEL_VALIDATION_STALE` 并要求重新同步或重新检测。
- **实现**：新增 `apps/control-api/src/providers/probe-evidence.ts`——`evaluateProbeEvidenceIdentity` 按五要素校验最近一次探针 run：① 凭证指纹（Key 轮换即失效）；② 解析端点 scope/host（capability base_url / endpoints[mode] 变更即失效，经 `resolveProviderEndpoint(MODEL_PERMISSION_PROBE)` 与落库同口径）；③ 官方目录内容哈希；④ 模型集 + 复合身份（`probeRequestHash` 与 `persistProbeRun` 同式复算 `request_hash` 权威比对）；⑤ 新鲜度（run 开始时间超过 24h TTL 即 `EVIDENCE_EXPIRED`）。GET 不匹配时不回填任何 READY 证据（模型全部不可选）并返回 `probe_evidence: { status: "MODEL_VALIDATION_STALE", reason, requires: "SYNC_OR_PROBE" }`；confirm 不匹配时 409 `{ error: "MODEL_VALIDATION_STALE", reason }`。
- **文件**：`apps/control-api/src/providers/probe-evidence.ts`（新增）、`model-discovery-routes.ts`（GET/confirm 门禁 + persistProbeRun 复用 probeRequestHash）。
- **测试**（pool027 新增集成用例，10/10 通过）：基线 CURRENT + READY 可选 → Key 轮换（`CREDENTIAL_FINGERPRINT_MISMATCH`）→ 端点变更（`ENDPOINT_MISMATCH`）→ 目录哈希变更（`DISCOVERY_SOURCE_HASH_MISMATCH`）→ 模型集删除（`MODEL_SET_MISMATCH`）→ 证据拨回 25h 前（`EVIDENCE_EXPIRED`）——全程无任何新探针 run，GET/confirm 均拒绝；随后重新同步生成新 run → 恢复 CURRENT 且 confirm 200。

### 终审二（P1）— 故障证据配置哈希绑定实际解析端点
- **要求**：`providerChatConfigHash` 与认证失败证据忽略 capability base_url 和 mode-scoped endpoints；须对 `resolveProviderEndpoint` 返回的实际 canonical 端点做哈希，Gateway 记录失败与凭证恢复校验用同一逻辑。
- **实现**：`providerChatConfigHash` 增加 `{ env, resolvedBaseUrl }` 入参；caller 在解析端点后以实际 `baseUrl` 计算证据哈希；新增导出 `capabilityChatConfigHash(provider, mode, model, capabilitySet, env)`——内部经 `resolveProviderEndpoint(CHAT_COMPLETIONS)` + `capabilityConfiguredEndpoints` 解析后调用同式哈希，端点歧义抛错。凭证恢复链路（credential-probe-routes + CredentialChatProbeRepository）的 `configHash` 回调签名扩展为 4 参（携带 provider.capability_set），与 Gateway 完全同源；端点无法解析时失败关闭 `configuration_changed`；`provider_unsupported` 在规范化处独立抛出，不被吞掉。哈希 payload 不含 scope 枚举、未升 version——解析结果与旧口径相同的配置哈希不变，既有未过期的故障证据仍可恢复（liveness 优先）。
- **文件**：`packages/provider-adapters/src/openai-compatible-caller.ts`、`index.ts`、`__tests__/openai-compatible-caller.test.ts`；`apps/control-api/src/providers/credential-probe-routes.ts`；`packages/database/src/repositories/credential-chat-probe.ts`、`apps/control-api/src/__tests-integration__/credential-chat-probe.test.ts`。
- **测试**：caller 单测（79/79）——`upstreamConfigHash` 等于对解析端点的 `providerChatConfigHash` 口径，endpoints 变更即哈希变化；credential-chat-probe 集成（20/20）——mode 专属端点未变时恢复成功且调用落在该端点、端点配置变更为 409 `configuration_changed` 且零上游调用、端点歧义（未知自定义域名）409 `configuration_changed` 失败关闭。
