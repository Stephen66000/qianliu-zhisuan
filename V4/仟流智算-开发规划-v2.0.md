> **规划结论**
>
> 仟流智算 2.0 是客户企业使用的仟流智算 1.0 原位升级，不是仟流科技多企业总控台。开发先锁住 1.0 可用能力，再依次增加通讯录导入、周期用量、部门预算与成本归集、资源利用事实和轻量采购复盘，最后用完整回归候选交付。

## 1. 版本目标与边界

### 1.1 唯一主目标

在不削减、不替换 1.0 已有功能的前提下，让单个客户企业能够：

1. 从企业微信／飞书或 Excel 模板单向导入组织通讯录，并衔接现有使用主体；
2. 按员工或项目查看今日、本周、本月和单主体周期用量；
3. 配置部门月度预算，查看实际 Token、成本、使用率、警戒线和状态；
4. 以同一批 1.0 账本事实形成员工账、项目账和不重复计费的部门账；
5. 在既有月度经营账上补强采购、利用率、耗尽、闲置和轻量采购复盘。

### 1.2 Scope

- `FR2-001`：1.0 兼容与管理闭环保留；
- `FR2-002`：通讯录单向同步与 Excel 模板导入；
- `FR2-003`：员工／项目周期与单主体用量；
- `FR2-004`：部门预算与唯一成本归集；
- `FR2-005`：月度经营账单增量；
- `FR2-006`：资源利用率、耗尽与闲置事实；
- `FR2-007`：轻量采购复盘。

### 1.3 Non-scope

- 仟流科技总控台、跨企业目录、多租户开通和企业退租／销毁；
- Agent 新运行入口、Agent 管理或自动执行；1.0 已有 Agent 使用观测只按兼容合同保留；
- 新的对账与导出能力；“对账与导出”首版只保留 `Coming Soon`，不得展示模拟记录或假操作；
- 企业坐席、厂商成员账号、跨厂商任务效果评价、厂商实时价格／市场接口；
- 后台定时任务、自动采购、自动生成经营决策；
- 客户访谈和设计客户确认 Evidence；它们不是本轮开发包或开工前置条件。

### 1.4 工程退出条件

- `M20-0～M20-5` 和 `W20-01～W20-11` 全部 `done`；
- `AT-001～008` 在同一最终候选上完成，P0／P1 和阻断性 Evidence Gap 为零；
- 1.0 回归契约没有功能缺失、字段口径漂移或关键操作失效；
- 新增能力的正常、异常、权限、重复导入、历史归属和金额／Token 守恒测试通过；
- 最终候选绑定唯一 Commit、Tree、迁移、依赖锁、配置、测试结果和 Evidence；
- 目标环境安装／升级、健康检查、必要回退和代表性业务链验证完成。

## 4. 工作包

### 4.1 通用合同

- 工作包只拆到可实现、可集成、可验收，不拆成逐文件、逐函数或逐 commit 治理项。
- 每个包进入 `doing` 前必须满足依赖并成为执行基线中的唯一当前对象；达到 DoD 后才转 `done`。
- `NORMAL` 包完成实现、自检、相关测试和 Evidence；`HIGH` 包在同一候选上同时覆盖功能验收与代码／数据／恢复风险，不另建审核型工作包。
- AI Eval 为 `N/A`：本轮没有生成式 Agent、Prompt 或模型行为变更。
- Evidence 存入 `V4/Evidence/<Milestone>/<WorkPackage>/<YYYYMMDD-HHmm>-<name>/`，至少包含候选指纹、输入、命令、预期／实际、关键截图或结果、失败修复和残余风险。

### W20-01：冻结 1.0 兼容与回归基线

- **里程碑／风险**：M20-0／`HIGH`。
- **Owner**：技术 Owner＋测试 Owner。
- **依赖**：Stage 02 完成；Owner 授权读取并建立 2.0 开发工作树／分支。
- **任务**：只读核验当前分支、远端、Tag、Commit 和未提交文件归属；冻结 2.0 精确代码起点；将 §2 转为可执行回归清单和代表性 Fixture；补齐能锁住 1.0 关键行为的特征测试，不重做 1.0 功能。
- **DoD／测试**：现有 typecheck、lint、单测、集成、E2E、build 真实执行；关键页面、API、账本口径和下钻有回归证据；测试失败先区分既有缺陷与 2.0 引入缺陷。
- **输出／失败返回**：`E-W20-01` 和唯一基线指纹；起点、用户改动归属或回归事实不清时返回 Owner，不清理或覆盖现有改动。

### W20-02：通讯录来源与导入

- **里程碑／风险**：M20-1／`HIGH`。
- **Owner**：接入 Owner＋数据 Owner。
- **依赖**：W20-01。
- **任务**：实现企业微信／飞书单向读取适配、Excel 模板下载与上传；统一外部成员、部门和导入批次格式；完成模板字段、文件大小、重复行、非法行和部分失败校验。
- **DoD／测试**：接口和 Excel 使用同一导入管道；单次／重复／增量导入幂等；失败精确到行且可修复重试；凭证和个人信息不进入日志或 Evidence。
- **输出／失败返回**：标准导入批次和 `E-W20-02`；厂商接口不可用时保留可重试状态，不影响 Excel 路径，公共字段冲突返回 FR2-002／TRD 决策点。

### W20-03：导入成员衔接使用主体

- **里程碑／风险**：M20-1／`HIGH`。
- **Owner**：主体／接入 Owner。
- **依赖**：W20-02；1.0 使用主体和接入配置合同可用。
- **任务**：按外部成员 ID／员工编号匹配已有主体；新成员自动创建使用主体并初始化接入配置元数据；同步部门关系；保留 1.0 编辑、停用、启用和清理入口。
- **DoD／测试**：已有主体不重复创建；新主体可在 1.0 列表继续配置 Key、额度和模型；重复同步不重置 Key／授权；冲突、离开通讯录和缺失部门均有明确状态。仟流智算不提供新增、调岗、停职等人事操作。
- **输出／失败返回**：导入→主体→接入配置代表性链和 `E-W20-03`；无法唯一匹配进入待处理，不按姓名猜测绑定。

### W20-04：周期用量聚合合同

- **里程碑／风险**：M20-2／`NORMAL`。
- **Owner**：账本 Owner。
- **依赖**：W20-01；沿用 1.0 Usage／Ledger 事实。
- **任务**：提供员工／项目、全体／单主体、今日／本周／本月聚合；周固定周一至周日；统一请求数、真实 Token、API 费用、套餐扣减和部门／项目标签口径。
- **DoD／测试**：缓存 Token 不重复加入真实 Token；跨日、跨月、时区、空结果和无权限主体可验证；聚合结果与同筛选条件下的 1.0 请求明细逐项核对。
- **输出／失败返回**：稳定聚合契约和 `E-W20-04`；发现 1.0 基础事实歧义时返回 W20-01，不在聚合层修账。

### W20-05：周期用量页面与 1.0 下钻集成

- **里程碑／风险**：M20-2／`NORMAL`。
- **Owner**：Web Owner＋产品 Owner。
- **依赖**：W20-04。
- **任务**：在首页员工消耗区和用量概览接入日／周／月、员工／项目及可搜索的单主体选择；排名姓名进入同一主体状态；完整保留请求明细的筛选、URL、分页和证据下钻。
- **DoD／测试**：同一筛选下指标、趋势、排名和请求明细一致；刷新／复制 URL 后状态可复现；移动端和大数据量下选择、搜索、空态和加载态可用。

### W20-06：部门预算与预警

- **里程碑／风险**：M20-3／`HIGH`。
- **Owner**：经营 Owner＋数据 Owner。
- **依赖**：W20-03、W20-04。
- **任务**：实现部门月度预算、警戒线和版本；展示归集成本、实际 Token、预算使用率和状态；预算只做经营预警，不改写 1.0 主体 Token 硬额度，也不阻断调用。
- **DoD／测试**：`预算使用率=归集成本÷月度预算`；低于警戒线、达到警戒线、达到 100%、预算为零／缺失和跨月版本结果正确；越权写入、并发修改和重复告警可验证。
- **输出／失败返回**：部门预算链和 `E-W20-06`；若需求变为金额硬拒绝或跨部门 Token 计数，必须走 Planning Change。

### W20-07：唯一成本归集与月度经营

- **里程碑／风险**：M20-3／`HIGH`。
- **Owner**：账本 Owner＋经营 Owner。
- **依赖**：W20-05、W20-06。
- **任务**：按请求发生时点快照把项目主体归入项目部门、非项目员工请求归入员工部门、缺失关系归入待归属；形成员工账、项目账、部门账和月度总览；在 1.0 月账上增加本月采购／充值清单。
- **DoD／测试**：每条事实在部门维度只计一次；`部门合计+待归属=企业当月总成本`；员工账、项目账是分析维度而非相加后的新总账；API 实际费用、套餐成本、现金采购分栏；负责人调岗不改写历史；员工账厂商筛选和员工搜索可组合使用。
- **输出／失败返回**：同一事实集的月度经营链和 `E-W20-07`；无法归属时进入待归属，禁止按当前部门或负责人猜测历史。

### W20-08：逐资源利用、耗尽与闲置事实

- **里程碑／风险**：M20-4／`NORMAL`。
- **Owner**：资源 Owner＋经营 Owner。
- **依赖**：W20-04、W20-07；1.0 厂商资源、额度窗口和供给预测可用。
- **任务**：在完整保留 1.0 厂商资源页的基础上增加资源利用概况；Coding Plan 分别展示 5 小时与周窗口，API 展示 Token、实际费用、余额和覆盖预测；展示最近使用和连续无调用天数。
- **DoD／测试**：所有数字可下钻到原窗口、预测或账本；厂商未提供、分母未设置、余额未知、速度不足和快照过期均明确显示不可计算；不把余额比例当利用率，不凭 Token 少自动判定闲置。
- **输出／失败返回**：逐资源事实链和 `E-W20-08`；数据源不足保持未知，不新增自动调度或写配置副作用。

### W20-09：轻量采购复盘

- **里程碑／风险**：M20-4／`NORMAL`。
- **Owner**：产品 Owner＋经营 Owner。
- **依赖**：W20-08。
- **任务**：按资源展示采购／充值、真实使用、利用情况、利用率、建议标签和判断依据；保留“采购复盘备注（人工填写）”；删除无操作意义的“人工判断”标识。
- **DoD／测试**：DeepSeek、Kimi、智谱等每项资源都有独立利用率或明确未知；建议只由冻结规则和可追溯事实生成；备注可保存、可审计但不改变账本；不形成采购订单或大 BI。
- **输出／失败返回**：月度采购复盘链和 `E-W20-09`；缺少可靠分母时显示“—／未设置”，不得补造 0%。

- **里程碑／风险**：M20-5／`HIGH`。

## 7. 关键路径与集成顺序

```text
精确 1.0 基线
→ 通讯录导入批次
→ 使用主体与部门关系
→ 员工／项目周期聚合
→ 部门预算与发生时点归属
→ 员工账／项目账／部门账／月度经营守恒
→ 资源利用事实
→ 采购复盘
→ 完整候选与目标环境交付
```

不能跳过的约束：

- W20-01 未冻结，不允许以 2.0 UI 替换 1.0 功能；
- 通讯录身份无法唯一匹配时，不自动绑定主体；
- 周期聚合未与请求明细核对前，不进入部门成本计算；
- 发生时点归属和待归属未成立前，不宣称部门账守恒；
- 资源分母或厂商窗口未知时，不输出利用率或精确耗尽日期；
- 最终候选变化后，按影响范围重跑回归并更新候选锁。
