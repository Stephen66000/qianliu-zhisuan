# ADR-20-005：标准版部署、身份与导出边界

> **历史方案（2026-08-12）**：本 ADR 的平台身份、对象存储和导出合同已退出 PC-20260812-03 当前范围。对账与导出本轮只保留 Coming Soon，不得据此实现后端。

| 适用版本 | 仟流智算 2.0 标准版 |
| 对应决策 | `DEC-002`、`DEC-004`、`DEC-009` |
| 复查触发 | 共享 SaaS；明确客户 OIDC 合同；对象存储不可用；法规或数据驻留要求改变 |

## 决策

### 1. 部署

1. 标准版采用一企业一部署：平台控制面可登记多套部署元数据，但一个业务部署清单只绑定一个初始化后不可变的 `DEPLOYMENT_ENTERPRISE_ID`，并保存绑定记录与校验 Hash；同栈第二企业、环境值篡改或换企业复用旧数据均在启动／写入前拒绝。应用仍执行完整 EnterpriseContext、复合约束和 RLS，不以物理隔离替代代码安全边界。
2. 平台运营只管理部署、版本、企业状态和健康；换企业必须新建部署，不建设共享 SaaS 商业后台，也不默认读取企业业务明细。
3. 共享 SaaS、多企业同库、跨企业运营和自动租户编排均不在 2.0；进入时必须单独 Planning Change、威胁模型、容量和迁移 ADR。

### 2. 身份

1. 标准版首发只交付本地账号、邀请／重置、批量导入和人员生命周期；本地 RBAC 是唯一授权终审。
2. 企业身份权威为 `person + local_identity + role_assignment`，平台身份使用独立 `platform_admin`。1.0 `admin_user / employee_login` 经显式人员映射清单迁入，旧 `admin_session` 全撤销且不迁移；用户名冲突或人员歧义在 DDL／切流前阻断，不允许双写或凭名称猜测合并。
3. 密码使用 Argon2id（最低 `19 MiB / t=2 / p=1`）；平台／企业普通 Session、各自 bootstrap、凭证恢复和企业生命周期恢复分别使用不同的 `__Host-` Cookie 名称、realm、摘要、CSRF token 与 `auth_version`，即使不同域名也不复用；普通 Session 执行 30 分钟空闲与 8 小时绝对时限。邀请、重置、Session 和恢复码只存摘要；登录限速跨实例共享。
4. 平台管理员、企业 Owner、AI 管理员和高风险动作执行人使用 TOTP＋10 分钟 step-up；TOTP Secret 使用独立 KEK 的 AEAD 密文，恢复码只存摘要。TOTP 不标注为抗钓鱼或 NIST AAL2，WebAuthn／Passkey 延后 2.1。参数依据见 [本地身份安全基线](../../_knowledge_base/2.0本地身份安全基线-2026年8月.md)。
5. OIDC／OAuth／SSO 不进入 2.0 标准版首发，因为当前没有真实客户 issuer、claims、JIT、域和停用合同；不得为假想 IdP 实现一套无法验收的适配。
6. 只保留 `external_identity` 和 OIDC Authorization Code＋PKCE 的架构说明；2.0 不建外部身份表、不存 client Secret、不发布端点或 E2E。出现真实客户合同后走 2.1／Planning Change。
7. 身份源未来接入时不得用邮箱作为唯一身份，`sub` 必须与企业／issuer 联合稳定；JIT 默认关闭；外部故障不得升级本地权限。
8. 标准版不依赖 SMTP／短信：首位平台管理员由目标主机一次性 bootstrap，后续平台／企业邀请与重置只在签发响应显示一次，由获授权人员经项目外批准渠道交给本人。平台身份一人一号，禁止应用内 peer 重置，只能使用本人恢复码；全部平台凭证丢失走环境 Owner 批准的离线灾难恢复 runbook。任何企业 Owner 目标都禁止同级单人重置，统一由两名不同平台管理员分别在各自最近 10 分钟 step-up 下创建／批准，并分别交付至少 256-bit CSPRNG、只存用途绑定 HMAC 的 share A／B；恢复提交共享限速且仅双份同时成功时原子消费，目标本人合并后进入受限恢复。任一平台管理员或任一 share 都不能独立消费，不允许平台代设凭证、改角色或取得企业 Session。
9. 2.0 标准版不建设全局自然人主数据、实名核验或跨 realm 自动去重。支持申请／批准、生命周期请求／执行、Owner 恢复双批和销毁执行／复核分别使用不同账号、独立 realm 或 Session、独立权限与独立 step-up；部署高权限职责清单记录账号、声明持有人和禁止组合。运行时只验证账号、realm、权限、MFA、时限和状态机，不把职责清单冒充技术身份凭证。无法识别未披露的同一人员多账号是明确接受的 2.0 残余风险；需要实名证明、统一身份源或跨 realm 去重时，必须在 2.1／真实 SSO 合同下另立 Planning Change。

### 3. 导出

1. 导出使用私有 S3-compatible 对象存储合同。标准 Compose 可捆绑 MinIO，目标环境也可接客户批准的 S3-compatible 服务；本地业务目录不是正式导出存储。
2. Bucket 不公开；对象键至少包含企业隔离前缀、导出 Job ID 和内容 SHA-256。服务端从认证上下文确定企业，客户端不能传任意路径或企业 ID。
3. 文件传输使用 TLS，静态数据必须有受控加密；对象存储凭证与数据库密钥分离。导出不含调用正文、Secret、Key 明文或无权限个人字段。
4. 默认保留 7 天，可配置但标准上限 30 天；过期、取消、企业停用或授权版本变化后下载立即拒绝，并由清理任务删除对象和可重建缓存。
5. 每个导出生成不可变、判别式 `EXPORT_MANIFEST_V1`。公共字段含 `export_kind / source / source_fingerprint`，且 `export_kind=source.kind`；`source={kind:"OPERATING_STATEMENT", operating_statement_id, statement_version}` 或 `source={kind:"OFFBOARDING_FINAL", lifecycle_request_id, offboarding_snapshot_id, ledger_watermark, export_scope_hash, checklist_hash}`，除共同 kind 外两组字段互斥、必须完整且不得以假 Statement／nullable 打洞；`source_fingerprint=SHA-256(RFC 8785 JCS(source))`。`hash_algorithm` 固定 `SHA-256`；冻结 `total_bytes / file_sha256 / chunk_size_bytes=8388608 / chunk_count` 及每片 `index / byte_start / byte_end_exclusive / size_bytes / chunk_sha256`，最后一片可短，小文件仍是一片。客户端不得自选或扩大 Range；未知版本／算法、kind／source 不一致和 MD5／CRC 替代均拒绝。敏感导出只经 Control API 下载：每个固定分片签发一次性应用 token，最长 10 分钟并绑定 Session／身份版本／manifest／kind／来源指纹／chunk，兑换时原子消费；对象存储 Bucket、对象地址和预签名 URL 永不返回客户端。
6. Control API 在首字节前并在流中每 1 秒或 1 MiB（先到者）重验企业、导出任务、kind／来源指纹、绑定 Session 状态／到期、操作人授权版本和撤销状态，失败立即中止后续字节。一般账单只允许同一操作人以有效的新普通 Session＋step-up 为下一固定分片签发新 token；`RECOVERY_ONLY` 只允许冻结资格 Owner 为当前 `OFFBOARDING` 已冻结最终导出的下一固定分片签发新 token，不能创建任意导出或读取一般账单。两条路径按每片 SHA-256 和最终 `file_sha256` 校验后各自跨会话续传，不延长旧 Session／token且禁止 kind、source 或认证平面交叉访问。申请、生成、manifest、签发、实际下载、中止、重试、失败、过期和删除均审计。
7. 数据库只保存 Job、范围、判别式来源、对象引用、manifest、Hash、大小、状态和过期时间，不保存文件正文。

## 后果

- 标准版可以不等待客户 IdP，直接形成可验收的登录、导入、撤权和交付路径。
- 一企业一部署降低首发运维面，但不会制造“代码可忽略租户”的债务。
- 标准 Compose 增加对象存储及其备份、Secret、监控和生命周期工作；W20-15／18 必须完成权限、过期、销毁、恢复和 canary。

## 被拒绝方案

| 方案 | 原因 |
| --- | --- |
| 首发共享 SaaS | 当前没有运营、计费、租户编排和多企业恢复合同 |
| 没有客户 IdP 仍强做 OIDC | claims、生命周期和失败合同不可真实验收，扩大首发范围 |
| 导出写入 Web 本地目录 | 多实例、升级、权限、过期、备份和销毁难以形成稳定合同 |
| 公共 Bucket 或任何客户端直连签名 URL | 撤权后无法及时阻断已签 URL；与标准版即时撤权合同冲突 |
