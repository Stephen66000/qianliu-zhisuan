| 核心修订 | 管理员点击后直连厂商官方来源；补充解析器版本、可配置官方 URL、核心页面与索引双路径、语境提取、历史来源兼容和 `[1m]` 客户端变体 |

> **方案结论**
>
> 管理员点击“同步模型”后，仟流应直接访问当前厂商的正式 List Models API；厂商没有正式列表接口时，读取厂商自己的官方模型索引或官方模型文档。发现结果与上次成功快照比较后展示给管理员。同步只负责发现，不自动启用路由、不自动扩大主体授权；管理员确认加入并完成一次显式真实调用验证后，模型才可启用。

## 1. 问题与根因

### 1.1 用户现象

智谱官方已经宣布 GLM Coding Plan 面向全量用户支持 `glm-5.3`，但管理员在仟流智算资源页点击“立即同步”后，仍只看到：

- `glm-5.2`；
- `glm-4.7`；
- `glm-4.6`。

### 1.2 当前实现

当前 `packages/provider-adapters/src/model-discovery.ts` 对智谱不调用上游模型列表，也不读取智谱官方模型索引，而是直接返回代码内置目录：

```ts
const ZHIPU_CATALOG_VERSION = "2026-08-03";
const ZHIPU_CATALOG = {
  API: ["glm-5.2", "glm-4.7", "glm-4.6", "embedding-3"],
  CODING_PLAN: ["glm-5.2", "glm-4.7", "glm-4.6"],
};
```

因此当前“同步”实际是“读取当前软件版本内置目录”。管理员重复点击不会产生新结果，智谱官方已经公布的新模型也只有在修改代码并重新发版后才会出现。

### 1.3 目标场景

真实使用方式是：

1. 管理员看到厂商发布新模型的新闻或公告；
2. 管理员进入仟流智算，点击“同步模型”；
3. 仟流实时检查厂商官方来源；
4. 官方来源已经更新时，显示新模型；
5. 官方来源尚未更新时，显示“本次未发现新模型”，管理员可过几天再同步；
6. 新模型确认并真实验证通过后，再启用和授权。

该场景不需要仟流中心维护另一份目录，也不需要长期安排人员监测、值班或发布目录。

## 2. 目标与边界

### 2.1 目标

1. 厂商官方来源出现新模型后，管理员点击同步即可发现，不需要修改仟流内置模型数组；
2. 不同厂商按其公开能力选择正式 List Models API 或官方模型文档；
3. 页面显示官方来源、检查时间、新增和消失差异；
4. 新模型经过“发现 → 确认 → 待配置 → 真实验证 → 启用 → 授权”后才可使用；
5. 官方来源失败、格式变化或模型消失时，不破坏现有路由、授权和历史账本；
6. 不把新闻、搜索结果、非官方页面或文档指令当成可执行配置；
7. 不把未知能力、未知计价和未验证可用性伪造成已支持。

### 2.2 首版 Scope

- 管理员手动点击“同步模型”；
- Provider 级官方来源策略；
- 正式 List Models API；
- 厂商官方模型索引／文档解析；
- 最近成功同步快照和本地内置兜底；
- 同步差异与企业接入状态；
- 管理员确认加入；
- 显式真实兼容性验证；
- Model Route 待配置／启用门禁；
- 操作日志、请求 Evidence 与回退。

### 2.3 Non-scope

- 首版不增加后台定时同步任务；
- 不建设仟流中心远程模型目录；
- 不设置目录运营值班、发布 SLA 或目录发布人；
- 不建设目录签名私钥、公钥轮换和签名发布体系；
- 不访问搜索引擎、媒体报道或第三方模型聚合站作为同步依据；
- 不自动猜测厂商未公开的 `/models` 接口；
- 不执行厂商文档中的命令、脚本、Prompt 或操作说明；
- 不自动创建已启用路由；
- 不自动向员工、项目或 Agent 增加模型授权；
- 不自动删除上游不再公布的模型；
- 不自动生成厂商价格、套餐扣减倍率或能力结论；
- 不因同步结果改写历史请求、账本、结算和模型身份；
- 首版不承诺完全离线／无外网部署无需发版即可获得新模型。

## 3. 核心原则

### 3.1 点击同步才检查

首版只有管理员点击“同步模型”时才访问厂商官方来源，不增加后台轮询、定时任务或中心运营流程。

### 3.2 厂商官方来源是唯一外部事实源

优先使用厂商正式 List Models API。没有正式列表接口时，只访问在 Provider Adapter 中明确登记的厂商官方域名、官方索引和官方模型文档。

### 3.3 发现不等于启用

同步发现的新模型只进入候选列表。管理员确认后只创建待配置路由，真实验证通过后才允许启用；主体授权继续由既有批量授权／Key 权限流程管理。

### 3.4 失败不伪装成功

官方来源不可达或解析失败时，可以展示最近成功快照或内置兜底目录，但必须标记过期和失败原因，不能显示“刚刚同步成功”。

### 3.5 消失不等于删除

模型未出现在本次成功同步结果中时，只标记“官方来源未再列出”。现有统一模型、路由、主体授权和历史账本保持不变，是否停用由管理员决定。

### 3.6 同步不消耗模型额度

普通同步只读取模型列表或官方文档，不发起生成请求。真实模型验证是独立动作，执行前明确提示会产生一次或少量测试调用。

### 3.7 经营事实不能猜

新模型的 Token、套餐扣减、价格、上下文和输出上限只能来自官方资料或真实响应。未知值保持未知，不能沿用旧模型规则或按名称推断。

## 5. 官方来源策略

### 5.1 来源优先级

| 优先级 | 来源 | 条件 | 失败行为 |
| --- | --- | --- | --- |
| 1 | `PROVIDER_API` | 厂商提供正式 List Models API，当前资源凭证可以调用 | 回退最近成功快照，不猜未公开接口 |
| 2 | `OFFICIAL_DOCUMENTATION` | 厂商没有正式列表 API，但有固定官方模型索引／文档 | 回退最近成功快照 |
| 3 | `LAST_SUCCESSFUL_SNAPSHOT` | 当前资源存在历史成功同步 | 标记 `stale=true`，显示快照时间和本次失败原因 |
| 4 | `BUILTIN_FALLBACK` | 首次接入且官方来源不可用 | 只显示软件内置兜底，明确可能过期 |

### 5.2 首批厂商映射

| 厂商／资源模式 | 首选来源 | 官方来源示例 | 说明 |
| --- | --- | --- | --- |
| DeepSeek API | 正式 List Models API | `https://api.deepseek.com/models` | 继续沿用现有实时发现 |
| Kimi API | 正式 List Models API | `https://api.moonshot.cn/v1/models` | 继续沿用开放平台目录 |
| Kimi Coding Plan | Kimi 官方模型文档 | `https://www.kimi.com/code/docs/kimi-code/models.html` | 不把 Coding Plan Key 发往开放平台 List Models |
| 智谱 API | 正式接口存在并验证后使用；否则官方文档 | 固定模型页／切换指南为核心，`https://docs.bigmodel.cn/llms.txt` 为补充 | 不使用未公开接口猜测 |
| 智谱 Coding Plan | 智谱官方核心页面＋补充索引 | `https://docs.bigmodel.cn/cn/coding-plan/latest-model`、GLM 模型页；`llms.txt` 补充发现 | GLM-5.3 当前走此策略 |

官方来源 URL 使用“代码内安全默认值＋部署配置覆盖”：

- 每个 `provider + resource_mode` 配置核心页面、补充索引和字段能力页；
- 厂商迁移官方路径时，部署管理员可以更新 URL 配置，不要求重新编译／发布应用；
- URL 覆盖仍必须满足 HTTPS、厂商官方域名白名单、重定向和响应大小限制；
- 官方域名白名单也允许通过受控部署配置扩展，但不能由普通业务管理员在页面随意修改；
- URL 或域名配置变更写操作日志，并在下次同步时生效。

### 5.3 Provider Adapter 合同

```ts
type DiscoveryResult = {
  source: "PROVIDER_API" | "OFFICIAL_DOCUMENTATION" | "LAST_SUCCESSFUL_SNAPSHOT" | "BUILTIN_FALLBACK" | "VERSIONED_CATALOG";
  parserVersion: string | null;
  sourceUrl: string | null;
  sourceEtag: string | null;
  sourceLastModified: string | null;
  sourceContentHash: string | null;
  sourceCheckedAt: string;
  discoveredAt: string;
  stale: boolean;
  reused: boolean;
  models: DiscoveredModel[];
  catalogDiff: {
    added: string[];
    retained: string[];
    notAdvertised: string[];
  } | null;
  integrationStates: Array<{
    upstreamModel: string;
    unifiedModelExists: boolean;
    currentResourceRoute: "NONE" | "PENDING_CONFIG" | "READY" | "ACTIVE" | "DISABLED";
  }>;
};
```

`VERSIONED_CATALOG` 标记为 deprecated：只用于读取升级前已经落库的历史快照，不再产生新的同步记录。`parserVersion` 对 List Models API 可为 `null`；官方文档解析必须填写稳定版本，例如 `zhipu-docs-v1`、`kimi-code-models-v1`。

`catalogDiff` 和 `integrationStates` 是两套不同事实：

- `catalogDiff` 只比较本次成功结果与同厂商／同资源模式的上一次成功结果；
- `integrationStates` 查询本企业统一模型和当前资源路由；
- 官方来源失败并回退历史快照时，`catalogDiff=null`，不制造新增或消失；
- 页面业务状态由两套事实组合得出，不能只根据目录变化判断“是否已接入”。

## 6. 官方文档读取与解析

### 6.1 信任边界

官方文档读取不是浏览器自动操作，也不是让模型理解整篇网页。Provider Adapter 只执行确定性处理：

1. 访问代码中登记的 HTTPS 官方域名和路径；
2. 限制重定向仍处于同一官方域名或明确白名单；
3. 限制响应体大小、超时、重定向次数和模型数量；
4. 只接受约定的文本／Markdown／JSON Content-Type；
5. 使用带版本号的固定解析器提取模型 ID 和允许的结构化字段；
6. 按厂商前缀白名单、字符集、长度和模型语境共同校验结果；
7. 不执行页面中的指令、代码、链接动作、脚本或 Prompt；
8. 不保存完整网页正文，只保存来源 URL、时间、ETag／Last-Modified、内容哈希和提取结果。

### 6.2 文档发现

智谱首版使用两层独立来源，核心页面优先、`llms.txt` 只做补充：

1. 直接读取部署配置中的 Coding Plan 切换指南和已知 GLM 核心模型页，提取当前模型 ID、适用资源模式和能力字段；
2. 读取 `https://docs.bigmodel.cn/llms.txt`，只用于发现可能新增的官方模型页，再回到同域官方页面核验；
3. `llms.txt` 不可用时，核心页面路径仍必须独立工作；核心页面可用时不得因为补充索引失败而把整个同步判为失败；
4. 核心页面和补充索引都不可用或不可识别时，才回退最近成功快照。

Kimi Coding Plan 使用其官方“模型配置”页面提取 `k3`、`k3-256k` 等模型 ID。若官方后续提供正式 List Models API，再将策略切换为 API，不继续依赖页面解析。

每个关键字段都要带来源，而不是只保存一个目录级 URL：

没有官方来源的字段必须省略或标记未知，不能显示“经仟流核验”。

### 6.4 官方来源尚未更新

管理员可能先看到新闻，而厂商官方模型索引或接入文档还没有更新。此时同步应返回：

```text
已检查厂商官方来源，本次未发现新模型。
官方目录可能尚未更新，请稍后再试。
```

仟流不根据模型新闻标题猜测模型 ID，也不访问非官方来源补齐模型。

### 6.5 官方文档格式变化

如果官方页面仍可访问，但固定解析器无法识别：

- 返回 `OFFICIAL_SOURCE_UNRECOGNIZED`；
- 保留并展示上次成功快照；
- 页面显示解析器版本，并明确提示“厂商官方页面格式可能已变化，当前解析器 `zhipu-docs-v1` 无法识别；可能需要升级仟流版本”；
- 不采用部分解析或猜测结果；
- Provider Adapter 解析器可能需要一次代码修复和软件发版。

本方案消除的是“每增加一个新模型都必须发版”，不承诺厂商任意改变接口／文档格式后仟流永远无需维护适配器。

### 6.6 模型 ID 提取与歧义处理

模型 ID 不能通过全文正则命中后直接进入同步结果，必须同时满足：

1. **厂商前缀白名单**：例如智谱只接受 `glm-`、`embedding-` 等已登记前缀，Kimi Coding Plan 只接受 `k3`、`k3-`、`kimi-for-coding` 等已登记前缀；
2. **规范化比较**：解析时对大小写做规范化比较，最终保存官方页面中可证明的规范模型 ID；
3. **模型语境**：模型 ID 必须出现在代码标签、配置字段、模型表格、明确模型标题，或 `"model": "..."`／`model: ...` 等确定语境中；
4. **多来源一致性**：模型页、切换指南或正式 API 之间出现冲突时，不自动选择其中一个；
5. **歧义显式失败**：语法合法但只出现在普通正文、实验／Alpha 描述、历史对比或多个来源互相冲突时，返回 `OFFICIAL_SOURCE_AMBIGUOUS`，不静默丢弃也不作为可加入模型；
6. **不猜版本上限**：不能仅因为 `glm-99.9` 版本号看起来过大就判非法；判断依据是正式模型语境和官方来源，而不是当前版本经验。

## 7. 同步、确认与启用状态机

### 7.1 状态定义

| 状态 | 含义 | 可执行动作 |
| --- | --- | --- |
| `DISCOVERED_NEW` | 当前企业尚无统一模型 | 查看官方来源、选择加入 |
| `MODEL_EXISTS_ROUTE_MISSING` | 统一模型已存在，但当前资源尚无路由 | 复用统一模型，为当前资源确认建路由 |
| `RESOURCE_ROUTE_EXISTS` | 当前资源已有路由 | 查看该路由的配置、验证和启停状态 |
| `NOT_ADVERTISED` | 本次成功结果未再列出 | 保持现状、人工复核、停用 |
| `PENDING_CONFIG` | 已确认加入，路由未启用 | 配置计量／计价和验证 |
| `VALIDATION_FAILED` | 真实验证未通过 | 查看错误、修正后重试 |
| `READY` | 验证通过但尚未启用 | 管理员启用路由 |
| `ACTIVE` | 路由已启用 | 另行分配主体授权 |
| `DISABLED` | 管理员停用 | 保留历史与配置 |

### 7.2 同步动作

同步执行：

1. 解析当前厂商和资源模式；
2. 选择官方来源策略；
3. 安全读取并解析官方来源；
4. 规范化模型类型和能力；
5. 仅在本次成功获得新结果时，与最近成功结果比较形成 `catalogDiff`；
6. 保存成功快照及来源 Evidence；
7. 查询本企业统一模型与当前资源路由，形成 `integrationStates`；
8. 返回目录变化、接入状态和不兼容模型；
9. 写操作日志。

同一企业、同一资源 60 秒内重复点击同步时，返回最近一次结果并标记 `reused=true`、`retry_after_seconds`，不重复访问厂商；并发同步使用 singleflight，共享同一个进行中的请求。

同步不执行：

- 不调用生成模型；
- 不创建员工 Key；
- 不新增主体 Grant；
- 不启用 Model Route；
- 不修改现有模型计价；
- 不删除旧模型。

### 7.3 确认加入

管理员选中新模型后：

- 创建或复用统一模型；
- 使用稳定别名 `ql-{upstream_model}`，例如 `ql-glm-5.3`；
- 为当前资源创建 `enabled=false` 的 Model Route；
- 统一模型状态保持 `PENDING_CONFIG`；
- 不自动创建或扩大主体授权。

确认接口按两个维度幂等：

1. 统一模型和当前资源路由都不存在：创建两者；
2. 统一模型已存在、当前资源路由不存在：复用统一模型，只创建当前资源禁用路由；
3. 当前资源路由已存在：不重复创建，返回现有对象及状态；
4. 同一幂等键携带不同参数：返回幂等冲突，不覆盖已有对象。

### 7.4 真实验证

真实验证是独立、显式、可审计的动作：

1. 页面提示将产生少量厂商额度；
2. 根据官方字段生成最小合法请求；
3. 验证非流式返回；
4. 验证流式首事件和正常结束；
5. 官方声明工具能力时验证最小 Function Calling；
6. 记录状态码、稳定错误码、Request ID、返回模型名、Token 和耗时；
7. 不记录 Prompt 正文、响应正文和凭证；
8. 必需项通过后状态转为 `READY`。

同一企业、资源和上游模型同一时刻只允许一个 `IN_PROGRESS` 验证。相同幂等键重试返回原结果；不同幂等键并发请求返回 HTTP 409／`MODEL_VALIDATION_IN_PROGRESS`。互斥必须持久化，不能只依赖单进程内存锁。

GLM-5.3 验证必须满足：

- 上游模型 ID 为 `glm-5.3`；
- 使用 Coding Plan OpenAI Chat Completions 端点；
- 文本输入；
- 不发送 `thinking.type=disabled`；
- `reasoning_effort` 仅使用 `low`、`high` 或 `max`；
- 能解析输入、输出和思考 Token；
- 不用超长输入验证 1M，避免不必要额度消耗。

### 7.5 启用与授权

只有 `READY` 路由允许管理员启用。启用后仍不会自动授予任何主体；员工、项目和 Agent 继续通过现有批量模型授权流程获得 `ql-glm-5.3` 权限。

## 8. 数据与兼容方案

### 8.1 复用现有数据结构

现有表已经覆盖首版主要能力：

- `provider_model_discovery`：同步来源、状态和时间；
- `provider_model_discovery_item`：模型、能力、兼容性、首次／最近发现和验证时间；
- `provider_model_onboarding`：确认加入的幂等结果；
- `unified_model`：对员工暴露的稳定模型身份；
- `model_route`：厂商资源和上游模型路由；
- `principal_grant`：主体模型授权。

### 8.2 最小数据变更

1. 来源类型增加 `OFFICIAL_DOCUMENTATION`、`LAST_SUCCESSFUL_SNAPSHOT`、`BUILTIN_FALLBACK`，并保留 deprecated 的 `VERSIONED_CATALOG` 读取兼容；
2. `VERSIONED_CATALOG` 不再产生新数据；已有记录无需改名，可继续读取、展示和审计；
3. 快照增加或保存 `parser_version`、`source_url`、`source_etag`、`source_last_modified`、`source_content_hash`、`source_checked_at` 和 `stale`；
4. 发现响应增加 `catalog_diff` 和 `integration_states`；
5. `capabilities` 保留 JSONB，并明确结构化字段和客户端变体合同；
6. 验证互斥增加持久状态或唯一约束；
7. 不新建中心目录、签名或模型市场数据结构。

### 8.3 模型身份

- `glm-5.3` 是新的上游模型身份；
- 对外别名为 `ql-glm-5.3`；
- 对仟流当前使用的智谱 OpenAI Chat Completions 上游，规范模型参数保持 `glm-5.3`，1M 记录为 `context_window=1000000`；
- `glm-5.3[1m]` 记录为 Claude Code／Anthropic 客户端变体，不创建第二个统一模型和 `ql-glm-5.3-1m` 路由；
- 只有真实验证证明仟流当前上游 API 必须把 `[1m]` 作为独立 `model` 参数，才允许通过 Planning Change 重新定义其身份；
- 不把 `ql-glm-5.2` 原地改名为 `ql-glm-5.3`；
- 历史 `ai_request.unified_model`、`unified_model_id` 和账单模型身份保持不变；
- 同一企业内重复同步、重复确认必须幂等。

## 11. 计量、计价与经营账边界

### 11.1 Token 事实

启用新模型前必须确认上游响应能被现有 Adapter 正确解析：

- 输入 Token；
- 输出 Token；
- 缓存 Token；
- 思考 Token（厂商返回时）；
- Request ID；
- 模型 ID。

### 11.2 Coding Plan 扣减

同步发现不得自动复制 GLM-5.2 的倍率给 GLM-5.3。若官方尚未发布 GLM-5.3 套餐扣减规则：

- 使用事实可以记录 Token；
- 套餐扣减倍率显示“未知／待确认”；
- 经营账不得伪造积分或成本；
- 是否允许“只记 Token、扣减未知”的模型启用，由产品 Owner 决定。

### 11.3 历史账单

同步、确认、路由启停均不能修改历史账单。模型别名变化通过稳定模型 ID 和历史 Alias 处理，不重算已关闭账期。

## 12. 错误与降级合同

| 场景 | 稳定错误／状态 | 系统行为 |
| --- | --- | --- |
| List Models 401／403 | `UNAUTHORIZED` | 标记当前凭证无权发现，不切换另一产品体系 Key |
| 官方来源 429 | `RATE_LIMITED` | 返回最近成功快照并标记过期 |
| 官方来源超时／5xx | `OFFICIAL_SOURCE_UNAVAILABLE` | 返回最近成功快照；首次接入使用内置兜底 |
| 官方正文不符合当前解析器 | `OFFICIAL_SOURCE_UNRECOGNIZED` | 拒绝本次结果，返回解析器版本和升级提示 |
| 模型 ID 语境不明确／来源冲突 | `OFFICIAL_SOURCE_AMBIGUOUS` | 拒绝歧义模型，不静默采用或丢弃 |
| 官方响应超大小／数量 | `OFFICIAL_SOURCE_TOO_LARGE` | 读取前终止，保留旧快照 |
| 官方来源尚无新模型 | 正常成功，`catalog_diff.added=[]` | 显示本次未发现新模型 |
| 真实验证 4xx | 稳定上游错误 | 保持 `VALIDATION_FAILED`，不启用路由 |
| 真实验证 429／5xx | 稳定上游临时错误 | 保留 Evidence，可人工重试 |
| 并发验证 | `MODEL_VALIDATION_IN_PROGRESS` | HTTP 409，不重复调用和扣费 |
| 模型从成功结果消失 | `NOT_ADVERTISED` | 保留统一模型、路由、授权和历史 |

`ProviderModelDiscoveryError` 在现有错误基础上至少增加：

```text
OFFICIAL_SOURCE_UNAVAILABLE
OFFICIAL_SOURCE_UNRECOGNIZED
OFFICIAL_SOURCE_AMBIGUOUS
OFFICIAL_SOURCE_TOO_LARGE
```

错误必须稳定映射 HTTP 状态、页面文案和审计事件，不能统一落为 `unknown`。

## 13. 离线与网络边界

| 部署形态 | 同步能力 | 客户预期 |
| --- | --- | --- |
| 可联网 | 直接访问厂商官方域名 | 官方来源更新后，点击同步可发现新模型 |
| 受限联网／白名单 | 通过客户出口代理或域名白名单访问 | 未放行官方域名时按离线处理 |
| 完全离线／内网隔离 | 不能访问厂商官方来源 | 首版只能使用内置目录；新增模型需要应用发版 |

销售、合同和交付材料必须明确：完全离线部署不满足“点击同步即可发现厂商新模型”。首版不建设离线目录包导入。

## 14. 审计与 Evidence

每次同步至少记录：

- 企业、管理员、资源和厂商；
- 来源类型、解析器版本、官方 URL、检查时间、ETag／Last-Modified 和内容哈希；
- 新增、保留、未再列出和不兼容数量；
- 是否使用历史快照或内置兜底；
- 成功／失败分类；
- 不记录厂商 Key和官方页面完整正文。

每次确认至少记录：

- 被确认的上游模型；
- 创建／复用的统一模型；
- 稳定 Alias；
- 创建／复用的当前资源禁用路由；
- 幂等键。

每次真实验证至少记录：

- 候选 Commit／版本；
- 资源、上游模型和协议；
- Request ID、状态码、耗时、首字节和 Token；
- 必测项通过／失败；
- 错误稳定分类；
- 敏感正文已排除的扫描结果。

字段级 Evidence 保存每个关键能力字段对应的官方 URL、核验时间和提取结果哈希。无法出示来源的字段不得标记“官方已确认”。

5. 管理员启用测试路由并向测试主体授权；
6. 核对请求、Token、账本和经营事实；
7. 再决定是否向正式主体开放。

### 17.2 回退策略

- 配置开关可以停用某个官方文档解析器；
- 官方来源失败不覆盖最近成功快照；
- 可临时固定展示最近成功快照或内置目录，并明确过期；
- 回退应用版本不删除已创建的统一模型和路由；
- 新模型路由可以独立停用，不影响既有模型；
- 回退不触发历史账单重算。

## 18. 实施前决策与工作量

### 18.1 已确认方向

1. 管理员点击同步后直接检查厂商官方来源；
2. 不建设仟流中心远程目录；
3. 不设置目录运营负责人、值班发布或签名密钥体系；
4. 同步只发现，不自动启用或授权；
5. 官方尚未更新时正常提示稍后重试；
6. 首版不增加后台定时任务。

### 18.2 实施前仍需 Owner 确认

1. 真实验证是确认加入后自动触发，还是由管理员单独点击；
2. 扣减规则未知时是否允许模型以“只记 Token”状态启用；
3. 工具调用验证只在官方声明支持时执行，还是所有 Chat 模型强制执行；
4. 本能力并入当前 2.x 问题池，还是作为独立小版本交付。

以上是产品／范围决策，不要求设置目录运营人员或签名密钥责任人。

## 19. 完成定义

本方案只有同时满足以下条件才算完成：

- 厂商官方来源出现新模型后，可联网部署点击同步即可发现，不需要修改内置模型数组；
- 核心页面在 `llms.txt` 不可用时仍可独立同步；官方 URL 可以通过受控部署配置更新；
- 官方来源尚未更新、不可达或格式无法识别时，状态和下一动作明确；
- 同步来源、URL、解析器版本、检查时间和过期状态对管理员可见；
- 文档中的指令、脚本和非模型内容不会进入配置或执行链；
- 新模型不自动启用、不自动授权；
- GLM-5.3 通过真实 Coding Plan 请求；
- `glm-5.3[1m]` 作为 Anthropic 客户端变体保存，不在当前 OpenAI 上游重复创建统一模型；
- Token、思考、流式和官方声明的工具调用事实可核验；
- 计价／扣减未知不伪造；
- 官方来源失败、模型消失和回退不破坏现有使用与历史账本；
- 双层状态、限频、幂等、验证互斥、企业隔离和敏感信息检查通过；
- 完全离线部署边界已在产品、销售和交付材料中明确；
- 历史 `VERSIONED_CATALOG` 快照继续可读且不再产生新记录；
- 同一最终候选上的 AT-MD-001～011 全部通过；
- 编码、提交、发布、部署和正式主体开放分别获得明确授权。
