## 2. POC20-001：企业隔离与 RLS 边界

- 明确问题：仅靠一企业一部署是否会掩盖代码和 Schema 的跨企业漏洞；RLS 是否作为第二道防线。
- 代表环境：PostgreSQL 目标版本、真实迁移副本、两个合成企业、相同业务 ID 模式、Control API／Gateway／Worker／Redis 代表入口。
- 操作：直接 ID、列表、聚合、批量、导出、Worker、通知、缓存污染和运维脚本跨企业读写；分别启用和禁用 RLS。
- 可观察结果：SQL／API 结果、拒绝 reason code、审计、Redis Key、约束错误和性能增量。
- 通过门槛：跨企业读取和写入为 0；应用授权与数据库约束均可独立解释；RLS 性能和运维复杂度在冻结阈值内。
- 失败结论：任一入口串租户；企业归属依赖无约束 join；RLS 造成无法接受的维护或性能风险且无替代防线。
- Evidence 计划：`V4/Evidence/Stage01/POC20-001/`。

### 2.1 实际结论（2026-08-11）

- 状态：`done`；结果：`PASS_WITH_LIMITATIONS`。这表示架构命题在限定合同下成立，不表示产品实现已经完成。
- 动态结果：PostgreSQL 17.10、真实 `pg.Pool 8.16.3`、两个合成企业；跨企业读写、复合 FK、上下文缺失／非法、commit／rollback 后连接复用和 24 次并发交替均符合 fail-closed 预期。
- 已复现风险：session-level `SET` 会跨连接池 checkout 残留，2.0 合同明确禁止。
- 静态缺口：当前 1.0 是单工作空间设计，运行角色可绕过 RLS；10 张租户相关表无直接 `enterprise_id`，大量事实链缺少复合 FK，运行保障／Worker 仍是全库入口，真实 Redis／导出链尚不可验证。
- 决策：采用 [ADR-20-001](../ADR/ADR-20-001-企业隔离与RLS边界.md)；迁移与回填进入 POC20-002，性能进入 POC20-004，产品实现仍保持 `todo`。

## 3. POC20-002：0044 迁移与回滚

- 明确问题：新增企业、组织、RBAC、预算和账期结构后，历史事实是否保持且旧版本能否安全恢复。
- 代表环境：脱敏结构等价的 1.0 数据副本；包含正常、缺归属、历史账期、Alias、Attempt、Usage、Ledger、Settlement 数据。
- 操作：`0044 → 2.0 → 校验 → 回滚 → 旧版只读验证 → 重升`；重复运行回填和 Hash 校验。
- 可观察结果：迁移时间、锁时间、行数、Hash、未知归属清单、回滚边界和旧应用写保护。
- 通过门槛：基础账本行数和金额／Token 守恒；回填幂等；未知归属显式阻断；旧应用不会在不兼容 Schema 上写入。
- 失败结论：历史事实被改写、猜测回填、不可回滚写入或恢复步骤不可重复。
- Evidence 计划：`V4/Evidence/Stage01/POC20-002/`。

### 3.1 实际结论（2026-08-11）

- 状态：`done`；结果：`PASS_WITH_LIMITATIONS`。真实 45 条迁移执行到 `0044`，再验证代表性 2.0 up／down／re-up；不等同正式 `0045` 或生产演练。
- 历史事实：0044 老字段 SHA-256 在全部 checkpoint 相同；Request／Attempt／Usage／Line／Transaction 为 3／4／2／2／2，Token、套餐扣减、API 金额和两个 Statement 均守恒，错配为 0。
- fail-closed：缺目标企业清单返回 `P2000`，跨企业脏引用返回 `P2002`，两者 DDL 残留均为 0；旧版角色读成功、写返回 `42501`。
- 回滚边界：Writer 切流前允许 down 并保持旧版只读；切流后 down 返回 `P2004`，禁止破坏性降库。
- 限制：物理列序号在 down／re-up 后漂移，但语义 Schema Hash 一致；正式迁移、生产 drift、真实数据、大表锁时和应用候选仍待实现／Gate 2 验证。
- 决策：采用 [ADR-20-002](../ADR/ADR-20-002-0044迁移与回滚边界.md)；下一步进入 POC20-003。

## 4. POC20-003：结账水位与在途 Settlement

- 明确问题：结账冻结水位时，在途请求完成、重复提交、超时重试和重开是否会造成少记、重记或重复结算。
- 代表环境：两个企业、跨时区账期、可控制提交顺序的 Gateway／Worker／PostgreSQL 集成测试。
- 操作：在结账锁前后提交 Settlement；重复 close／reopen；失败重试；跨月边界；未归属和检查失败后恢复。
- 可观察结果：账期状态、账本水位、Statement Hash、锁等待、重复结算数和守恒结果。
- 通过门槛：状态只使用四态；失败回到 `DRAFT` 并保留检查结果；重复结算为 0；账期与基础事实 100% 一致。
- 失败结论：任何事实丢失、跨期、重复、死锁不可恢复或旧 Statement 被覆盖。
- Evidence 计划：`V4/Evidence/Stage01/POC20-003/`。

### 4.1 实际结论（2026-08-11）

- 状态：`done`；结果：`PASS_WITH_LIMITATIONS`。在 `v1.0.0-final` archive 中，真实并发回归源码含 35 个静态测试声明，Vitest 展开执行 `57/57` 通过；代表性 2.0 Overlay 在 PostgreSQL 17.10 上完成四态、锁等待、失败恢复、水位、幂等、重开和跨时区验证。
- 状态合同：检查失败保存 `period_check.result=FAILED` 并回到 `DRAFT`；最终永久 `CHECKING=0`、RUNNING Check=0。
- 并发合同：Settlement-first 精确纳入，Close-first 拒绝迟到写入；同 close key 20 路重放一致，重复 Settlement=0；不同企业同账期不互相阻断。
- 版本合同：v1/v2 水位 `settlement_seq=1/2`；旧 Statement Hash 不变且 UPDATE 返回 `P3008`；旧 reopen 重放不改变 v2，新键＋旧版本返回 `P3013`。
- 限制：不是正式迁移／Repository；未真实 SIGKILL／数据库故障；request hash、双 Hash、分摊守恒、跨多月和生产规模仍待实现验证。
- 决策：采用 [ADR-20-003](../ADR/ADR-20-003-账期状态机水位与锁序.md)；容量和锁争用转 POC20-004，产品实现仍保持 `todo`。

## 5. POC20-004：容量、部署与恢复包络

- 明确问题：候选的并发、月账本、结账时间、RPO／RTO 和资源成本是否适合作为标准版默认包络。
- 代表环境：固定 CPU、内存、磁盘、PostgreSQL、Redis、网络和容器版本；数据分布包含流式、项目调用和月末聚合。
- 操作：阶梯压测 Gateway、管理查询、月末结账；注入 PostgreSQL／Redis／Worker 故障；使用最新候选备份隔离恢复。
- 可观察结果：吞吐、TTFT 增量、P95、锁等待、CPU／内存／磁盘、备份体积、RPO、RTO 和月度成本估算。
- 通过门槛：由 PRD `DEC-010` 在执行前冻结；未冻结前 TRD 数值只属于候选包络。
- 失败结论：阈值无法在合理资源下达到、恢复不满足合同或成本超出 Owner 接受边界。
- Evidence 计划：`V4/Evidence/Stage01/POC20-004/`。

### 5.1 实际结论（2026-08-11）

- 状态：`done`；结果：`PASS_WITH_LIMITATIONS`。本项按职责拆为 Stage 01 校准 `POC20-004A` 和 Gate 2 完整候选资格验证 W20-18／W20-19，避免要求尚不存在的 2.0 成品反向阻塞开发启动。
- 数据面：100 成员、1,000 Principal、1,000 万月账本；代表性结账 3.17 秒，常用查询 P95 2.66ms，500 路混合查询 P95 223ms，RLS 跨企业可见行 0。
- 恢复：Dump 15.9 秒、全新库 Restore 36.5 秒，1,000 万行与事实 Hash 一致；只证明恢复路径与观测 RTO，不证明持续 RPO。
- Gateway：在 `v1.0.0-final` 上，500＋200 和 100＋50 均 100% 成功且账本守恒，但自增 TTFT P95 分别为 788.328ms、193.859ms，未达 150ms；50＋20 为 79.408ms 并达标。
- 决策：采用 [ADR-20-004](../ADR/ADR-20-004-标准版容量与恢复包络.md)，标准默认冻结为 50 Gateway／20 流式并发；500／200 降为 W20-19 Stretch Goal。
- 限制：代表性 Schema＋真实 1.0 Gateway，不是完整 2.0；长流、大 Payload、稳态 RPS、全 Compose、容器资源曲线和持续备份仍待 W20-18／19。

## 6. 执行顺序与停止条件

```text
POC20-001 企业隔离
→ POC20-002 迁移与回滚
→ POC20-003 结账并发
→ POC20-004 容量与恢复
```

- 任一 PoC 发现 P0：立即停止受影响动作；
- 任一 PoC 证明方案不成立且无替代路径：状态 `failed`，返回 Stage 01 修改方案；
- 仍有可继续验证的问题：保持 `doing`；
- 结果、限制、原始 Evidence 和写回完成后才标记该 PoC `done`；
- 当前计划不授权产品代码、生产数据或外部环境操作。

四项关键 PoC 已收口。当前唯一下一动作是完成 Stage 01 Evidence 索引和独立 Gate 1 一致性复核；Stage 02 和产品编码继续保持 `todo`。
