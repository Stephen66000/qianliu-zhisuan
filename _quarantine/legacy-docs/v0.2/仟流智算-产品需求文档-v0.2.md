## 1. 一句话定位

仟流智算是企业 AI 资源管理系统：管理员统一登记企业购买的 API 和 Coding Plan，为员工或项目分配独立 Key、模型和额度，再通过统一 Gateway 计量谁用了多少、扣了多少额度、产生多少费用以及是否异常。

## 2. 首期要解决的问题

企业同时购买 DeepSeek、智谱、Kimi 等资源后，通常存在以下问题：

1. 厂商账号、充值余额、套餐费用和有效期分散在不同后台。
2. 多名员工共享企业资源，但无法准确知道每个人用了多少。
3. Coding Plan 可以被多人在不同时间或同时使用，但厂商只给出一份总额度。
4. API 与套餐的计算方式不同：API 按价格计费，套餐按厂商规则扣减额度。
5. 员工使用 WorkBuddy、Claude Code、ZCode 等不同工具，企业难以统一分配和统计。
6. 管理员最关心资源是否可用、额度是否即将耗尽，以及谁的用量突然异常。

## 3. 首期目标

1. 管理员可以登记 DeepSeek API、智谱 Coding Plan、Kimi Coding Plan。
2. 管理员可以创建员工或项目，给每个使用主体分配独立 Key、模型和额度。
3. WorkBuddy、Claude Code、ZCode、仟流 IDE 可以通过仟流 Gateway 使用已分配资源。
4. 每次调用都能归属到员工或项目，并记录原始用量、实际扣减和费用。
5. 管理员可以在桌面 Web 中查看本月资源、费用、人数、额度和异常。
6. 员工额度耗尽时默认停止；管理员可以单独允许超额使用。
7. 使用内容默认不保存，只保存完成计量所需的元数据。

## 4. 阶段边界

### 4.1 一期范围

- 单企业：只服务仟流科技。
- 管理入口：桌面 Web。
- 管理角色：管理员，所有管理员权限相同。
- 使用主体：员工、项目。
- 员工工具：仟流 IDE、WorkBuddy、Claude Code、ZCode。
- 首批资源：DeepSeek API、智谱 Coding Plan、Kimi Coding Plan（首用模型为 Kimi K3）。
- 资源管理、Key、额度、Gateway、计量、费用、异常、操作日志。
- 10 人完成一个完整自然月的内部真实使用。

### 4.2 二期范围

- 仟流智算 Agent，供管理员查询、解释和执行常用管理操作。
- 仟流智算 Agent 的入口在一期原型中预留于页面右上角；一期制品不开放该功能。
- 企业微信等外部通知渠道。
- 员工把单次任务指定到某个项目。
- 多企业切换、企业开通和 SaaS 商业化能力。

### 4.3 一期不做

- 手机端。
- 员工 Web 管理后台。
- 语音入口。
- OA、短信、邮件、企业微信集成。
- 部门预算、产品预算和多层预算体系。
- 自动抓取厂商价格与套餐规则。
- 自动采购和充值。
- 保存员工提示词、代码、文件内容和模型回答正文。
- 终端流量监听、浏览器扩展、VPN、根证书或 TLS 解密。

## 5. 用户和使用主体

### 5.1 管理员

- 使用桌面 Web。
- 是系统最高权限。
- 可以创建其他管理员账号。
- 老板不单独建立角色，老板账号就是管理员账号，显示名称可以修改。
- 可以管理资源、员工、项目、Key、额度、规则、账本和异常。
- 提交管理操作后直接执行，并记录操作人、时间、对象、结果和失败原因。

### 5.2 使用主体

系统统一使用“使用主体”表示消耗企业 AI 资源的对象：

| 类型 | 说明 |
| --- | --- |
| 员工 | 真实员工，可以使用账号登录仟流 IDE，也可以在第三方工具中使用个人 Key |
| 项目 | 非人的调用主体，拥有独立 Key、模型和额度，使用方式与员工相同 |

员工和项目复用同一套 Key、分配、额度、计量、停用和异常能力。部门仅作为员工的可选信息，不形成独立额度层。

## 6. 核心业务流程

### 6.1 员工开通

顺序固定：

1. 管理员创建员工账号。
2. 系统为员工生成一把独立仟流 Key。
3. 管理员为员工分配 DeepSeek、智谱、Kimi 的使用权限和额度。
4. 系统生成员工接入信息。
5. 员工在自己的工具中完成配置并开始使用。

不得把模型分配放在账号和 Key 之前。

### 6.2 项目开通

1. 管理员创建项目。
2. 系统为项目生成独立仟流 Key。
3. 管理员为项目分配模型和额度。
4. 项目服务通过 Gateway 调用。

### 6.3 员工接入信息

接入信息包含：

- Gateway 地址；
- 员工专属 Key；
- 已开通模型名称；
- WorkBuddy、Claude Code、ZCode 的配置说明；
- 一键复制内容。

Key 明文只在创建或重置时显示一次，之后只显示掩码。重置后旧 Key 立即失效。

仟流 IDE 使用员工账号登录，自动取得 Gateway 地址、可用模型和受控凭证，不要求员工手动复制 Key。

### 6.4 停用

- 停用员工或项目后，其 Key 立即失效，全部模型权限停止。
- 历史用量、费用和异常记录保留。
- 重新启用员工后必须生成新 Key。
- 修改名称不改变历史记录的归属。

## 7. 厂商资源

### 7.1 两种资源模式

| 模式 | 示例 | 主要记录 |
| --- | --- | --- |
| API | DeepSeek API | 充值金额、余额、本月用量、本月费用、价格规则 |
| Coding Plan／套餐 | 智谱、Kimi K3 | 套餐名称、套餐费用、总额度、已用额度、有效期、扣减规则 |

### 7.2 资源账号

同一厂商可以登记多个账号或套餐。每个资源账号至少记录：

- 厂商；
- 资源模式；
- 账号名称；
- 可用模型；
- 充值金额或套餐费用；
- 总额度和剩余额度；
- 生效、失效和重置时间；
- 状态；
- 上游凭证；
- 价格或额度扣减规则。

### 7.3 资源池

- 员工或项目只分配厂商、模型和个人额度，不绑定具体上游账号。
- Gateway 自动选择资源池中的可用账号。
- 单个账号限流、失效或耗尽时，可以切换到同一资源池的其他账号。
- 只有使用主体额度耗尽，或资源池全部不可用时才停止。
- 系统记录每次调用实际使用的上游账号。
- 不人为串行化多人请求；上游并发、限流和总额度才是实际边界。

### 7.4 套餐与 API 路由

- 同一模型同时存在套餐和 API 时，默认优先套餐。
- 套餐不可用后默认不自动转 API，避免产生非预期费用。
- 管理员可开启“允许 API 兜底”并设置资源优先级。
- API 兜底产生的费用单独统计。

## 8. 额度

### 8.1 分配方式

- 管理员可以直接填写某个使用主体的额度数值。
- 管理员可以创建额度规则模板并批量套用。
- 套用后允许单独修改。
- 优先级：主体单独设置 > 额度规则 > 系统默认值。
- 额度单位可选择 Token、金额或厂商原生单位。

### 8.2 有效期

- 使用主体额度的生效、失效和重置周期跟随对应厂商资源。
- 厂商进入新周期后，已使用额度自动清零，分配规则继续沿用。
- 上一周期未使用额度默认不结转。
- 厂商资源到期、耗尽或失效后，关联使用主体停止使用。

### 8.3 用完和超额

- 额度用完默认停止该主体继续使用该资源。
- 管理员可以为主体开启“允许超额使用”。
- 超额部分单独统计和预警。
- 超额列表按超出比例排序。

## 9. 用量、扣减和费用

系统不得把三个概念混成一个数字：

| 概念 | 含义 |
| --- | --- |
| 原始用量 | 上游返回或 Gateway 计算的原始 Token／Prompt |
| 实际扣减额度 | 原始用量经过套餐规则折算后的额度 |
| 实际费用 | API 调用按照调用当时价格计算的真实费用 |

### 9.1 API

- 原始 Token 不因价格变化而改变。
- 费用按照调用发生时命中的价格版本计算。
- 使用主体按 Token 分配时扣原始 Token；按金额分配时扣实际费用。

### 9.2 Coding Plan

- 原始用量按照厂商套餐规则折算为实际扣减额度。
- 员工或项目费用显示“套餐内”，不显示为 0 元。
- 套餐固定费用记录在厂商资源账号，不伪造员工真实单次费用。
- 异常判断主要依据额度消耗速度和超出比例。

### 9.3 规则配置

厂商资源配置支持两类可版本化规则：

1. API 分时价格规则；
2. 套餐额度扣减规则。

规则至少包含：

- 厂商、资源、模型；
- 生效和失效日期；
- 星期、时间段和时区；
- 输入、输出、缓存等价格项，或额度扣减倍数；
- 优先级和启用状态。

一期由管理员选择系统模板并手工维护。规则修改只影响新调用，历史调用继续引用原规则版本。

初始业务口径：

- DeepSeek：API 模式，支持版本化分时价格规则，但系统不预置固定时段和单价；管理员根据实际采购渠道、合同或厂商当期规则配置。
- 智谱：Coding Plan 模式，支持北京时间 14:00–18:00 的高峰扣减规则。
- Kimi：Coding Plan 模式，首用 Kimi K3，支持按模型档位和厂商规则配置扣减倍数。

## 10. 管理后台

### 10.1 一级入口

1. 首页看板；
2. 使用主体；
3. 厂商资源；
4. 额度规则；
5. 用量账本；
6. 异常告警；
7. 系统设置。

一期原型在页面右上角预留仟流智算 Agent 入口位置，通过功能开关隐藏。

### 10.2 首页看板

首页只显示当前自然月，不放同比、环比和复杂趋势。页面中的“本账期”指企业当前自然月报表周期，不等于任一厂商资源的额度重置周期。

核心指标：

- 厂商资源账号数量；
- 本账期活跃人数，旁边显示当前正在使用人数；
- 本月套餐支付金额；
- 本月 API 费用；
- 本月充值金额；
- 资源可用状态和额度状态。

人数口径：

- 本账期活跃人数：当前自然月内至少成功调用过一次的员工数。
- 当前正在使用人数：存在进行中调用，或最近 5 分钟内成功调用过的员工数。
- 同一员工同时使用多个工具或模型，只计算 1 人。

资源摘要按厂商展示：

- 厂商；
- API／套餐；
- 账号数量；
- 充值金额或套餐费用；
- 总额度、已用额度、剩余额度；
- 本月使用费用；
- 当前状态。

超额列表只显示：

- 谁；
- 类型；
- 分配多少；
- 使用多少；
- 超出多少；
- 超出比例。

### 10.3 用量账本

支持按以下条件筛选：

- 员工／项目；
- 工具；
- 厂商和模型；
- 时间；
- 成功、失败和拒绝；
- 是否超额。

每条记录至少显示：

- 发起主体；
- 客户端；
- 模型；
- 上游账号；
- 原始用量；
- 实际扣减额度；
- API 实际费用或“套餐内”；
- 命中的规则版本；
- 状态、错误类型、时间和耗时。

## 11. 异常告警

一期保留四类异常：

1. 厂商或模型不可用、错误率突然升高；
2. 某个人或项目用量／费用突然异常增长；
3. 频繁限流、调用拒绝或额度扣减异常；
4. 账号、凭证失效或出现非预期使用。

重点突出：

- 资源是否还能使用；
- 谁的额度或费用异常。

一期告警只在管理后台展示，可以标记已处理，不发送到外部渠道。

## 12. 客户端与环境

### 12.1 员工工具

| 工具 | 一期接入方式 |
| --- | --- |
| 仟流 IDE | 员工登录后自动取得 Gateway、模型和受控凭证 |
| WorkBuddy | 手工填写 Gateway URL、员工 Key、模型 |
| Claude Code | 配置 Anthropic 兼容 Gateway 地址和员工 Key |
| ZCode | 配置 OpenAI 或 Anthropic 兼容 Gateway 地址和员工 Key |

同一员工默认共用一把 Key。系统尽力识别客户端；无法可靠识别时标记为“未知客户端”，但不影响员工归因。

### 12.2 内部试用设备

- 8 名员工使用 Windows；
- 2 名员工使用 Mac；
- 仟流 IDE 首期只在 2 台 Apple Silicon Mac 验证；
- Windows 员工主要使用 WorkBuddy、Claude Code、ZCode；
- 不以仟流 IDE 支持 Windows 作为仟流智算一期完成条件。

### 12.3 Web 验收

- Windows 11 + Chrome；
- macOS + Chrome；
- 桌面 Web；
- 一期没有手机端。

## 13. 安全和隐私

- Web 和 Gateway 通过公网 HTTPS 提供服务。
- Web 与 Gateway 使用不同子域名。
- 上游真实凭证只保存在服务器，不交给员工。
- 员工 Key 只保存不可逆摘要，明文仅展示一次。
- 管理员密码和员工密码使用安全密码哈希保存。
- 默认不保存提示词、代码、文件内容和模型回答正文。
- 计量元数据包括主体、客户端、资源、模型、用量、扣减、费用、时间、耗时和错误。
- 所有管理操作记录操作人、时间、对象、前后变化摘要和结果。
- 停用主体或重置 Key 必须立即生效。

## 15. 真实业务周期

内部验证使用 10 名员工，连续运行一个完整自然月。厂商额度仍按各自有效期和重置周期执行，不因验证周期改变。

核心指标：

1. 10 名员工全部使用独立账号和 Key。
2. 纳入试点的调用主体归因率不低于 90%。
3. 重复记账率为 0，已确认调用事件丢失率低于 0.1%。
4. 价格、额度倍数、有效期和周期重置计算与配置规则一致。
5. 仟流 IDE、WorkBuddy、Claude Code、ZCode 均完成真实接入。
6. 管理员无需询问员工即可看到资源、人员、额度、费用和异常。
7. 默认正文落库数量为 0。

四种工具各至少覆盖 2 名真实员工；同一员工可以使用多种工具。

测试、演示和开发数据必须与真实周期数据隔离。

## 16. 原型真实任务走查

K3 原型必须以本文和 [TRD v0.2](./仟流智算-技术需求文档-v0.2.md) 为输入，至少走查以下任务：

1. `WT-01`：管理员登记 DeepSeek API、智谱套餐和 Kimi 套餐。
2. `WT-02`：管理员创建员工、取得 Key、分配模型和额度。
3. `WT-03`：员工根据接入信息在第三方工具中完成首次调用。
4. `WT-04`：管理员创建项目并按同样方式分配资源。
5. `WT-05`：管理员查看某员工原始用量、实际扣减和 API 费用。
6. `WT-06`：员工额度耗尽后停止；开启允许超额后恢复并产生超额记录。
7. `WT-07`：套餐账号失效后切换同资源池账号；套餐转 API 只在开关开启时发生。
8. `WT-08`：管理员从首页发现资源不可用或使用主体异常，并进入明细。
9. `WT-09`：管理员停用员工或重置 Key，旧 Key 立即不可用。
