## 1. 当前版本主目标

让仟流科技的管理员能够把 DeepSeek API、智谱 Coding Plan、Kimi K3 Coding Plan 分配给 10 名员工或项目，并通过仟流 Gateway 完成真实调用、额度控制、用量和费用统计。

## 2. 一期范围

- 单企业；
- 多个同权限管理员；
- 员工／项目统一使用主体；
- 每主体独立 Key；
- DeepSeek、智谱、Kimi；
- API 和 Coding Plan；
- OpenAI／Anthropic 兼容 Gateway；
- 仟流 IDE、WorkBuddy、Claude Code、ZCode；
- 额度、分时价格、扣减倍数和资源池；
- 桌面 Web 七个一级入口；
- 用量账本、异常和操作日志；
- 10 人完整自然月验证。

## 3. 非目标

- 手机端；
- 仟流智算 Agent 功能；
- 语音；
- 外部通知；
- 部门和多层预算；
- 多企业管理界面；
- 自动采购；
- 自动同步厂商规则；
- 员工任务选择项目归属；
- 调用正文存储。

### S01-B：真实任务走查

参与者：

- 佳哥：产品、技术、业务和日常管理 Owner；
- K3 原型；
- 必要时由一名真实员工复现接入步骤。

走查顺序：

1. `WT-01`：管理员登记 DeepSeek API、智谱套餐和 Kimi 套餐。
2. `WT-02`：管理员创建员工、取得 Key、分配模型和额度。
3. `WT-03`：员工根据接入信息在第三方工具中完成首次调用。
4. `WT-04`：管理员创建项目并按同样方式分配资源。
5. `WT-05`：管理员查看某员工原始用量、实际扣减和 API 费用。
6. `WT-06`：员工额度耗尽后停止；开启允许超额后恢复并产生超额记录。
7. `WT-07`：套餐账号失效后切换同资源池账号；套餐转 API 只在开关开启时发生。
8. `WT-08`：管理员从首页发现资源不可用或使用主体异常，并进入明细。
9. `WT-09`：管理员停用员工或重置 Key，旧 Key 立即不可用。

以上编号和文字以 [PRD v0.2 §16](./仟流智算-产品需求文档-v0.2.md#16-原型真实任务走查) 为唯一权威；本节只引用，不另行压缩或解释。

产出：

- 走查问题清单；
- PRD／TRD／原型修订；
- 走查结论。

## 5. Stage 02 里程碑草案

以下只表示建议顺序，不是当前执行授权。

### M1：资源和使用主体可管理

真实闭环：

```text
管理员登录
→ 登记厂商资源
→ 创建员工／项目
→ 生成 Key
→ 分配模型和额度
→ 页面可查
```

完成标准：

- 单企业管理员登录可用；
- 员工／项目统一主体可用；
- Key 明文一次展示、重置和停用可用；
- 三厂商资源和两种模式可登记；
- 操作日志完整；
- 上游 Secret 不出现在页面和日志。

### M2：一个客户端完成 Gateway 真实调用

真实闭环：

```text
主体 Key
→ Gateway 鉴权
→ DeepSeek
→ 流式返回
→ 用量和费用入账
→ Web 可查
```

完成标准：

- OpenAI 兼容协议通过；
- DeepSeek 真实调用通过；
- 原始用量和 API 费用正确；
- 失败、取消和重试不重复记账；
- 默认正文零留存。

### M3：三类上游和资源池闭环

真实闭环：

```text
员工选择模型
→ Gateway 选择资源池
→ DeepSeek／智谱／Kimi
→ 套餐优先
→ 同池切换
→ 条件式 API 兜底
```

完成标准：

- 三类上游真实适配通过；
- 多账号并发可用；
- 不人为串行化员工调用；
- 套餐到 API 的默认关闭和开启路径均通过；
- 上游账号和切换原因可查。

### M4：额度、规则和账本闭环

真实闭环：

```text
原始用量
→ 命中规则版本
→ 计算扣减／费用
→ 更新主体额度
→ 停止或允许超额
→ 账本和异常可查
```

完成标准：

- API 分时价格正确；
- 套餐倍数正确；
- 厂商周期重置正确；
- 并发额度预占不穿透；
- 额度用完默认停止；
- 超额值和比例正确；
- 历史规则版本不被重算。

### M5：桌面 Web 完整可用

真实闭环：

```text
管理员打开首页
→ 发现资源或主体异常
→ 下钻账本
→ 调整资源／额度
→ 结果立即生效
```

完成标准：

- 七个一级入口可用；
- 首页只显示本月核心信息；
- 四类异常可查看和处理；
- Windows 11 Chrome、macOS Chrome 通过；
- 没有手机端入口；
- 二期 Agent 入口功能关闭。

### M6：四种员工工具兼容

完成标准：

- 仟流 IDE 在 Apple Silicon Mac 真实使用；
- WorkBuddy、Claude Code、ZCode 在 Windows 真实使用；
- 每个工具覆盖普通调用、流式、工具调用、错误和主体归因；
- 每个工具至少覆盖 2 名真实员工；
- 仟流 IDE 登录后自动取得模型和受控凭证；
- 第三方工具使用同一员工主 Key；
- 停用和重置在所有客户端生效。

### M7：内部试用就绪

完成标准：

- 10 名员工账号和 Key 建立；
- 8 台 Windows、2 台 Mac 环境准备完成；
- 三类真实上游资源可用；
- 测试数据和正式数据隔离；
- 监控、备份和故障处理说明可用；
- 管理员可以独立完成全部日常操作。

### M8：完整自然月验证

完成标准：

- 10 人完成一个完整自然月；
- [PRD v0.2 §15](./仟流智算-产品需求文档-v0.2.md#15-真实业务周期) 七项指标形成真实结果；
- 厂商周期和自然月报表口径没有混淆；
- 形成资源、费用、超额、异常和下一周期人工调整结论；
- 遗留问题进入下一版本，不伪装完成。

## 6. 建议集成顺序

```text
主体与资源
→ Key 与登录
→ OpenAI Gateway + DeepSeek
→ 账本
→ 智谱和 Kimi
→ 额度与规则
→ 资源池和兜底
→ Web
→ 四客户端
→ 10 人试用
```

不能先做完整看板再补真实账本，也不能只做转发而没有主体和额度。

| 主体 | 员工、项目、停用主体 |

## 8. 风险

| 风险 | 影响 | 处理 |
| --- | --- | --- |
| 第三方客户端协议细节不同 | 填入 Gateway 后局部功能不可用 | Stage 01 冻结版本并执行真实 PoC |
| Coding Plan 上游行为变化 | 用量、限流或工具调用不稳定 | Provider Adapter 隔离、规则版本化 |
| 上游不返回完整 usage | 计量精度降低 | 适配器估算并标记质量 |
| 多人并发穿透额度 | 主体或资源超额 | 请求前预占、事务结算和恢复任务 |
| 价格和套餐规则变化 | 账本费用或扣减错误 | 管理员维护版本和生效时间 |
| 仟流 IDE Windows 未完成 | 8 名 Windows 员工无法使用第一方客户端 | 一期 Windows 使用第三方工具，IDE 只在 2 台 Mac 验证 |
| 内容意外进入日志 | 员工代码和对话泄露 | 字段白名单、日志脱敏和 canary 扫描 |
| 范围再次膨胀 | 一期无法收口 | 以 [PRD v0.2 §4](./仟流智算-产品需求文档-v0.2.md#4-阶段边界) 的 scope / non-scope 为唯一产品边界 |
