## 2026-07-31 补充：能否换算成固定 Token

### 结论

不能准确换算。Kimi Code 的套餐上限不是一个公开的固定 token 包，而是服务端的抽象额度。

当前账号通过 Kimi Code 官方 `/usages` 接口读取到：

- 周额度：`limit=100`、`used=60`、`remaining=40`
- 5 小时额度：`limit=100`、`used=3`、`remaining=97`
- 并发上限：20

这里的 100 是归一化额度点/百分比，不是 100 万 token。官方 CLI 源码同样只把 `used / limit` 渲染为百分比，没有把它换算为 token。

同样数量的 token 消耗不同，因为至少受以下因素影响：

- 模型不同：K3 与 K2.7 Code 费率不同
- token 类型不同：缓存命中输入、缓存未命中输入、输出的权重不同
- K3 thinking effort 不同会改变输出/思考 token
- HighSpeed 按官方说明约消耗普通版 3 倍套餐额度

### 官方 API 费率（可用于做“成本等价”估算）

| 模型 | 缓存命中输入 / 1M | 缓存未命中输入 / 1M | 输出 / 1M |
|---|---:|---:|---:|
| Kimi K3 | $0.30 | $3.00 | $15.00 |
| Kimi K2.7 Code | $0.19 | $0.95 | $4.00 |

Allegretto 月付 $39，按 4.345 周/月折算约 $8.98/周。若只做保守的“订阅价格等价”估算：

- K3：约 0.60M 纯输出，或 2.99M 纯未缓存输入，或 29.9M 纯缓存输入/周
- K2.7 Code：约 2.25M 纯输出，或 9.45M 纯未缓存输入，或 47.3M 纯缓存输入/周

这不是套餐真实 token 上限，只是用订阅价格除以官方 API 单价得到的成本等价值。官方说明订阅通常比同量 API 更划算，因此真实可用量可能更高，但没有公开系数。

### 内部分配建议

按 100 个周额度点管理，不按固定 token 管理：

- 预留 20 点应急缓冲
- 可分配 80 点
- 4 个使用单元时，每个单元 20 点/周
- 每个单元独立 API Key，并记录每次响应中的 input、cached input、output token
- 每天记录 `/usage` 百分比；跑满一个周期后，用“额度点变化 ÷ 加权 token 成本”反推本账号的真实系数

注意：Kimi 官方帮助中心写明当前 Kimi Code 会员权益用于个人开发，企业/多人生产使用应考虑 Kimi 开放平台或企业方案。

- 原始总 token；
