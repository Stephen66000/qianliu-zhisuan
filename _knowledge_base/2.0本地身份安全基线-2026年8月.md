# 仟流智算 2.0 本地身份安全基线

| 用途 | 冻结 2.0 标准版本地账号、Session、CSRF 与高权限 MFA 的最小安全合同 |

## 结论

1. 密码使用 Argon2id，最低参数 `m=19456 KiB, t=2, p=1`；每个密码使用随机盐并保存 PHC 字符串。目标环境实测单次校验小于 1 秒，旧参数在成功登录时升级。密码明文不得落库、日志或 Evidence。
2. 单因素本地密码最少 15 个字符，至少允许到 128 个 Unicode 字符；拦截常见／已泄露密码。没有泄露或明确风险时不做无意义的周期性强制轮换。
3. 生产 Session Cookie 使用 `__Host-` 前缀、`Secure`、`HttpOnly`、`SameSite=Lax`、`Path=/` 且不设置 `Domain`。服务端执行 30 分钟空闲超时、8 小时绝对超时，认证或授权版本变化立即失效。
4. Cookie 鉴权的非安全方法同时校验同源 `Origin`／`Sec-Fetch-*` 和绑定当前 Session 的防 CSRF Header；不能只依赖 SameSite。
5. 邀请、重置、Session、下载和恢复码只保存不可逆摘要；邀请 token 使用至少 256 bit 随机值、24 小时过期且原子单次消费；密码重置 token 30 分钟过期且原子单次消费，成功后提升 `auth_version` 并撤销已有 Session。
6. 平台管理员、企业 Owner、AI 管理员，以及执行凭证管理、结账／重开、完整导出或支持访问批准的角色必须启用 TOTP；高风险动作要求 10 分钟内完成 step-up。TOTP Secret 采用独立 KEK 的 AEAD 密文，恢复码一次性且只存摘要。
7. TOTP 不是抗钓鱼认证，因此 2.0 不宣称达到 NIST AAL2 或具备 phishing-resistant MFA。WebAuthn／Passkey 进入 2.1 候选，必须通过 Planning Change 冻结。
8. 登录失败限速必须跨实例共享：至少同时按 `auth_realm（平台或企业）+ normalized_username + IP` 和 IP 聚合执行 `5 次失败／5 分钟`，统一返回不泄露账号是否存在的错误与稳定 `429`，成功登录只清理对应账号桶。

## 来源与采用依据

- [OWASP Password Storage Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)：推荐 Argon2id 最低 `19 MiB / 2 iterations / parallelism 1`、每密码唯一盐、目标服务器实测并在登录时升级工作因子。
- [OWASP Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)：推荐 `__Host-` Cookie 约束，并要求服务端同时执行空闲和绝对超时；办公应用常见绝对时限为 4～8 小时。
- [OWASP Cross-Site Request Forgery Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)：有状态应用应使用同步 token 或等效 Session 绑定防护；Fetch Metadata 需要 Origin 等回退，不应只靠 Cookie 属性。
- [NIST SP 800-63B](https://pages.nist.gov/800-63-4/sp800-63b.html)：单因素密码最低 15 字符、应允许至少 64 字符；AAL2 必须提供抗钓鱼选项，而手工输入 OTP 不具备抗钓鱼能力。

## 与 1.0 现状的关系

- 1.0 已有 Argon2id `m=19456, t=2, p=1`、HttpOnly Cookie、生产 Secure、SameSite=Lax、8 小时绝对时限和单实例登录限速，可作为实现底座。
- 2.0 必补：共享限速、空闲超时、`__Host-` Cookie、Session 绑定 CSRF、防泄露 token 生命周期、高权限 TOTP／step-up 和密钥版本化。
