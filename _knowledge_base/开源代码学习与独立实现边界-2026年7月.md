# 开源代码学习与独立实现边界

- 收集时间：2026-07-26
- 调研目的：明确仟流智算学习 TokenHub、Sub2API 的架构和代码思路并自行实现时，应遵守的知识产权与开源许可证边界。
- 说明：本文是研发管理边界，不替代针对具体发布方式和代码来源的正式法律意见。

## 结论

可以学习功能、架构、算法思想、处理流程和工程方法，再按仟流自己的产品定义、领域模型、接口和测试独立实现。

不能因为源码公开，就默认可以无条件复制具体源码、注释、文档、界面素材或大段结构化表达。直接复制或修改源码时，必须遵守对应仓库许可证、保留通知并履行分发义务。

## 法律和许可证依据

《计算机软件保护条例》第六条规定，软件著作权保护不延及开发软件所用的思想、处理过程、操作方法或者数学概念；第十七条允许为了学习和研究软件内含的设计思想和原理而使用软件。与此同时，条例仍保护具体程序和文档表达，并规定未经许可复制、部分复制、修改、传播软件可能构成侵权。

因此应区分：

| 对象 | 原则 |
| --- | --- |
| 产品功能和业务目标 | 可以学习和独立实现 |
| 架构分层和处理流程 | 可以学习和独立实现 |
| 通用算法和协议实现思路 | 可以学习；自行编码和测试 |
| 具体源码、注释、测试文本和文档 | 受著作权及许可证约束 |
| Logo、名称、截图和界面素材 | 不直接复制，另查商标和素材授权 |

## 对 TokenHub 和 Sub2API 的处理

### TokenHub

- 仓库标注 Apache License 2.0。
- 如果直接使用或修改代码，应按 Apache 2.0 保留许可证、版权和归属通知，修改文件应有显著修改说明，并检查是否存在 `NOTICE`。
- 架构和代码思路可以消化后按仟流标准独立实现。

### Sub2API

- 本地仓库 `LICENSE` 为 LGPL v3。
- LGPL v3 对直接修改、组合和分发有明确义务，不能按“源码公开”等同“无条件使用”。
- README 同时声明“无商业授权”，与标准 LGPL 文本的通常理解存在表述冲突。在商业使用、分发或形成衍生代码前，应让权利人或专业法律人员确认准确许可边界。
- 在许可结论明确前，可以做阅读、研究、黑盒 PoC 和思想层面的独立实现；不要把来源不清的代码直接并入仟流商业代码库。

## 仟流研发规则

1. 产品定义、领域模型、接口合同和验收测试由仟流先定义。
2. 阅读外部实现时记录“学到了什么”，不要以复制文件作为设计过程。
3. 优先复现行为和测试，不复制大段源码、注释、命名和文件组织。
4. 必须复用源码时，登记来源仓库、Commit、文件、许可证和修改范围。
5. Apache、MIT、BSD、LGPL、GPL、AGPL 分别评审，不能一概而论。
6. 商业发布前形成第三方代码清单、许可证清单、NOTICE 和源码提供义务清单。
