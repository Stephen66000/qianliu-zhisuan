# 厂商 API 模型自动发现与后台选择

- 收集时间：2026-08-03 19:40（Asia/Shanghai）
- 目的：判断仟流智算能否根据厂商凭证和资源类型自动发现可用模型，替代管理员手工输入上游模型 ID。

## 结论

应采用“厂商模型发现适配器 + 资源／套餐过滤 + 管理员下拉选择”的统一方案。

- DeepSeek 和 Kimi 开放平台提供模型列表 API，可使用对应 API 资源凭证在服务端查询；
  Kimi Code Coding Plan 是独立系统，订阅 Key 与开放平台 Key、Base URL 不可混用。
- Kimi Code 官方文档公开 Coding Plan 的模型 ID，但未公开订阅 Key 的 List Models 契约；
  Coding Plan 应使用版本化官方目录，不能把订阅 Key 发往开放平台 `/v1/models`。
- 智谱公开文档列出通用 API 模型集合，但 Coding Plan 使用独立端点且只支持套餐允许的
  子集；本次未在官方文档中发现明确的账号级 List Models API，因此不能把官网全部模型
  直接视为当前套餐可用模型。
- 正常管理员不应手工输入上游模型 ID。无动态列表接口的厂商，由仟流维护受版本控制的
  官方模型目录，并按资源模式、地区、套餐和能力过滤。
- “厂商已发布”不等于“当前凭证可调用”；最终可选集合应是厂商目录、资源模式、当前
  凭证授权和最小探测结果的交集。

## 官方依据

### DeepSeek

- 官方 `GET /models` 返回当前可用模型及可用于请求的模型 ID。
- 当前官方示例包含 `deepseek-v4-flash`、`deepseek-v4-pro`。
- 来源：
  - https://api-docs.deepseek.com/api/list-models
  - https://api-docs.deepseek.com/quick_start/pricing
  - https://api-docs.deepseek.com/updates/

### Kimi

- Kimi 开放平台官方文档提供 List Models API，用于获取 API Key 当前可用模型列表，端点
  属于 `api.moonshot.cn`。
- Kimi Code 官方错误说明明确：Kimi Code 与开放平台是两套系统，Key 和 Base URL 不可
  互换。Kimi Code OpenAI 兼容 Base URL 为 `https://api.kimi.com/coding/v1`。
- Kimi Code 官方模型说明当前列出 `k3`、`k3-256k`、`kimi-for-coding`、
  `kimi-for-coding-highspeed` 四个模型 ID，并明确不同模型受会员档位约束。
- 截至本次收集，没有在 Kimi Code 官方文档中找到供订阅 Key 调用的 List Models API；
  因此仟流对 Coding Plan 使用带日期版本的官方目录，页面必须展示“版本化目录”来源，
  不冒充凭证实时授权结果。
- 来源：
  - https://platform.kimi.com/docs/api/list-models
  - https://platform.kimi.com/docs/models
  - https://www.kimi.com/code/docs/
  - https://www.kimi.com/code/docs/en/kimi-code/models.html
  - https://www.kimi.com/code/docs/en/kimi-code/error-reference.html

### 智谱

- 通用 Chat Completions 文档在 `model` 枚举中列出多个 GLM 模型。
- Coding Plan 使用专属端点 `https://open.bigmodel.cn/api/coding/paas/v4`，官方工具文档
  明确提示套餐只支持指定模型子集，不能选择其他模型冒充套餐免费能力。
- 本次官方文档检索未发现明确的账号级 List Models API；这是“未发现”，不是断言平台
  永远不存在该接口，实施时还应针对真实 Coding Plan 凭证做只读探测。
- 来源：
  - https://docs.bigmodel.cn/api-reference/模型-api/对话补全
  - https://docs.bigmodel.cn/cn/guide/develop/openclaw
  - https://docs.bigmodel.cn/cn/guide/develop/opencode

## 建议产品方案

1. 厂商资源保存成功后，由 Control API 服务端使用加密凭证执行“同步可用模型”；浏览器
   不接触上游凭证。
2. DeepSeek、Kimi API 资源使用官方 List Models API；Kimi Coding Plan、智谱等缺少动态
   列表接口的资源使用仟流维护的版本化目录，并按 API／Coding Plan、地区和套餐过滤。
3. 后台“上游模型”改为可搜索下拉框，展示模型 ID、显示名称、能力、来源、最近同步
   时间和验证状态，管理员只选择，不输入。
4. 增加“刷新模型”按钮；同步失败保留上一次成功快照并明确标记过期，禁止静默展示为
   最新结果。
5. 创建 Model Route 前执行只读能力校验或最小安全探测；不可用模型不能发布路由。
6. 新发现模型默认不自动暴露给员工，也不自动加入 Key 权限。管理员仍需创建／确认统一
   模型、计价规则、路由和员工授权。
7. 模型列表快照需要版本、来源和时间；厂商下架模型时先标记不可新选，不自动删除历史
   Route、Usage 和账本事实。
8. 平台维护者可以通过受审计的厂商目录更新补充尚未进入动态接口的新模型，但普通管理
   员页面不提供自由文本绕过。

## 关键边界

- 不把宣传页模型全集直接展示为可用模型。
- 不在前端调用厂商模型列表接口或暴露凭证。
- 不因模型同步而自动扩大员工 Key 权限。
- 不把 Flash、Pro 等能力和价格不同的模型放在同一个统一模型下随机路由。
- 不删除已经进入历史账本的旧模型 ID。
