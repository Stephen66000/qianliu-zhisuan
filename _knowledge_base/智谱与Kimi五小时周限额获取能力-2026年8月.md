# 智谱与 Kimi Coding Plan 额度查询能力

- 收集时间：2026-08-04（Asia/Shanghai）
- 调研范围：GLM Coding Plan、Kimi Code 订阅套餐
- 结论口径：只采用厂商官方文档与官方开源仓库信息

## 结论

两家都存在由官方客户端实际调用的 Coding Plan 用量查询接口，但能力完整度不同：

- **Kimi Code：可以查询。** 官方 `kimi-cli` 的 `/usage` 实际请求
  `GET https://api.kimi.com/coding/v1/usages`，使用
  `Authorization: Bearer <Kimi Code 凭证>`。返回数据由官方 CLI 解析为周额度和滚动
  5 小时额度，包括 `used`、`limit`／`remaining` 及重置提示。
- **智谱 GLM Coding Plan：可以查询 5 小时额度和用量明细。** 官方
  `glm-plan-usage` 插件请求：
  - `GET https://open.bigmodel.cn/api/monitor/usage/quota/limit`
  - `GET https://open.bigmodel.cn/api/monitor/usage/model-usage`
  - `GET https://open.bigmodel.cn/api/monitor/usage/tool-usage`
  
  中国站以 Coding Plan Token 放入 `Authorization` 请求头。公开插件把
  `TOKENS_LIMIT` 展示为 `Token usage (5 Hour)`；其公开实现没有解析周额度的当前已用、
  剩余和重置时间，因此不能据此承诺智谱周额度可实时同步。

这些接口由厂商官方客户端／插件使用，证据强于网页抓取；但厂商尚未把它们完整定义为
面向第三方的稳定 REST 合约。生产接入必须容忍字段变化、鉴权变化和临时不可用，不能把
同步失败误判为额度耗尽。

## 能力对比

| 能力 | 智谱 GLM Coding Plan | Kimi Code |
| --- | --- | --- |
| 滚动 5 小时额度 | 可通过 `/api/monitor/usage/quota/limit` 查询百分比 | 可通过 `/coding/v1/usages` 查询已用、上限／剩余及重置 |
| 周额度 | 套餐静态上限有官方说明；公开插件未提供当前周已用／剩余解析 | `/coding/v1/usages` 返回并由官方 CLI 解析 |
| 模型／工具用量 | 有 `model-usage`、`tool-usage` 接口 | `/usages` 主要提供窗口额度 |
| 限额错误 | 官方错误码可区分 5 小时、7 天和周／月上限 | 5 小时为 429，周额度耗尽为 403 |
| 接入可信度 | 官方插件正在使用，但非完整公开 REST 合约 | 官方 CLI 正在使用，但非完整公开 REST 合约 |

## 对仟流智算的落地建议

1. **Kimi 先做完整自动同步**：周额度与 5 小时额度均从 `/usages` 获取，保留
   `source=PROVIDER_API`、采集时间和原始窗口类型。
2. **智谱先做 5 小时自动同步**：从 `quota/limit` 获取；模型和工具用量可分别同步。
   周额度在没有验证出稳定字段前，显示“厂商未提供实时周额度”，不要用本地估算冒充
   厂商实时值。
3. 调用均使用已登记资源的 Coding Plan 凭证，不复制浏览器 Cookie，不保存个人网页登录
   会话。
4. 同步失败时展示“未同步／最后成功时间”，不能显示“降级”或“耗尽”；只有厂商明确
   返回配额错误，才进入额度耗尽状态。
5. 给接口适配器加超时、字段校验、脱敏日志、指数退避和功能开关，并保留控制台人工更新
   作为兜底。

   https://docs.bigmodel.cn/cn/coding-plan/overview
