## 高风险依赖摘要

### React Router

- 初次命中版本：`react-router@7.9.6`（经 `react-router-dom` 引入）
- 审计涉及开放重定向/XSS、SSR XSS、RSC/XSS、拒绝服务，以及特定服务端数据流场景的远程代码执行等公告。
- 各公告修复版本不一；按本次审计结果，全部覆盖需升级到至少 `7.18.0`，并完成前端路由回归。
- 适用性说明：项目当前主要是客户端 SPA，部分 Framework/SSR/RSC 公告未必能在现有部署方式下触发；审计结果只能证明依赖版本落入公告范围，不能单独证明项目已可利用。

### Kysely

- 初次命中版本：`kysely@0.28.7`
- 本次命中 JSON 路径键注入、JSON 路径遍历注入，以及 MySQL `sql.lit` 注入公告。
- 按本次审计结果，全部覆盖需升级到至少 `0.28.17`，并回归查询构建、迁移和运行保障账本。
- 适用性说明：项目使用 PostgreSQL，MySQL 专属公告不适用；其余公告仍需结合是否把外部输入传入 JSON Path API 做代码级确认。

### brace-expansion

- 高风险项 `GHSA-mh99-v99m-4gvg` 由 Testcontainers 12.0.4 的归档工具链间接引入，受影响版本为 `>=2.0.0 <2.1.3`。
- 上游 Testcontainers 暂未发布更高版本；工作区用精确 override 把 2.x 链从 `2.1.2` 收敛到已修复的 `2.1.3`，没有把 1.x/5.x 主版本强行替换。

2026-08-04 新增公告 `GHSA-rgw5-rvv9-x895` 证明 `2.1.3` 的防护仍可被绕过。生产依赖链已进一步精确覆盖到 `2.1.4`。

### fast-uri

- 新增高危公告 `GHSA-7p8r-x3mc-p8w7` 涉及 URI 解析与 Node WHATWG URL 对反斜杠处理不一致，可能造成主机策略判断与实际访问目标不一致。
- Fastify 间接引入的 `3.1.4` 与 `4.1.1` 均位于受影响范围；工作区分别精确覆盖到官方修复版 `3.1.5` 与 `4.1.2`，不改变 Fastify 主版本。

## 结论

已完成以下收敛：

- Kysely 升级到 `0.28.17`；
- React Router DOM 升级到当前可安装最新版 `7.18.2`；
- Testcontainers 全部统一到 `12.0.4`；
- Testcontainers 间接依赖 `brace-expansion@2.1.2` 精确覆盖到 `2.1.3`；
- 2026-08-04 将生产链 `brace-expansion@2.x` 更新到 `2.1.4`，并将 `fast-uri@3.x/4.x` 分别更新到 `3.1.5/4.1.2`；
- TypeScript ESLint、Vite React 插件和 Node 类型版本同步升级，`pnpm peers check` 无问题；
- 生产依赖审计退出码为 0。

剩余 `GHSA-qwww-vcr4-c8h2` 只影响 React Server Components Mode。项目代码核验只使用 `BrowserRouter` 客户端 SPA，没有 RSC/server 路由入口，且 npm registry 当前不存在公告所称的 `react-router-dom@8.3.0` 可安装版本，因此在 `pnpm-workspace.yaml` 和质量门禁中登记到期日为 2026-09-01 的显式例外。引入 SSR/RSC 或上游发布修复版本时必须立即复核。
