# 厂商额度扣减规则调研

- 收集时间：2026-07-25
- 调研目的：确认大模型厂商是否存在高峰期、模型档位等额度倍数规则，并形成仟流智算的可配置设计。

## 结论

额度扣减倍数不能写死为统一时间段或统一倍数。不同厂商、套餐、模型和活动期的规则不同，而且会调整：

- 智谱 GLM Coding Plan 当前明确存在分时倍数：GLM-5.2/GLM-5-Turbo 高峰期按 3 倍、非高峰期按 2 倍消耗；当前官方页面另有非高峰期临时 1 倍活动。高峰期定义为每日 14:00–18:00（UTC+8）。
- Kimi Code 当前公开规则中，`kimi-for-coding-highspeed` 是按模型档位进行 3 倍额度消耗；官方错误说明提到工作日 14:00–17:00 可能出现高峰过载，但该说明不是分时额度倍数规则。
- DeepSeek 当前 API 定价按输入/输出 Token 及缓存命中状态计费，官方当前定价页未显示分时倍数；历史夜间优惠已取消。

因此，仟流智算需要在“厂商资源/模型配置”中建立可版本化的额度扣减规则，而不是把高峰规则写死在员工额度中。

## 仟流智算应用口径

- 官方公开定价、企业实际采购渠道和具体合同可能不同。
- DeepSeek 适配器支持版本化分时价格，但系统不预置固定时间段或单价。
- 资源接入时由管理员根据当期公开规则、采购渠道或合同录入，并保存来源、生效时间和规则版本。
- 智谱、Kimi 的系统模板也只是录入起点，正式计算以具体资源上已生效的规则版本为准。

## 建议的数据规则

每条扣减规则至少包含：

- 适用厂商资源、套餐与模型；
- 规则类型：时间段、模型档位、缓存状态或厂商其他原生规则；
- 生效日期与失效日期；
- 星期范围、开始时间、结束时间及时区；
- 额度扣减倍数；
- 优先级和启用状态。

系统同时保存：

- 原始用量；
- 实际扣减额度；
- 命中的规则及规则版本。

计算示例：

`实际扣减额度 = 原始用量 × 命中规则倍数`

员工额度按“实际扣减额度”减少；报表同时展示原始用量和实际扣减量，避免管理员无法解释额度为何快速消耗。
