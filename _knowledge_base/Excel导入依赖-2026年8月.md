# Excel 导入依赖调研

- 收集时间：2026-08-12（Asia/Shanghai）
- 结论：Control API 使用 `@fastify/multipart@10.1.0` 接收受限 multipart 文件，使用 `exceljs@4.4.0` 生成和解析固定 `.xlsx` 模板。
- 安全边界：应用层仍强制 5 MiB、1,000 行、固定工作表/列/模板版本，并拒绝公式、外链和异常压缩内容；依赖默认值不替代业务校验。

## 2026-08-13 生产依赖漏洞复核

- 收集时间：2026-08-13 03:02 CST（Asia/Shanghai）
- 本地锁定链：`exceljs@4.4.0 -> uuid@8.3.2`；以及 `exceljs@4.4.0 -> archiver/unzipper -> glob@7.2.3 -> minimatch@3.1.5 -> brace-expansion@1.1.16`。
- `exceljs@4.4.0` 仍是 npm `latest`，其官方 `package.json` 仍声明 `uuid: ^8.3.0`；`4.4.1-prerelease.0` 也仍声明该范围，上游升级议题 #3055 截至收集时仍为 Open。
- GitHub Advisory 标注 `uuid <11.1.1` 受 GHSA-w5hq-g745-h8pq 影响，11 系补丁版本为 `11.1.1`。`uuid@11.1.1` 的 npm 元数据同时提供 `require -> ./dist/cjs/index.js`；ExcelJS 只使用 CommonJS 命名导出 `const { v4 } = require('uuid')`，与该导出形态相符。
- GitHub Advisory 标注 `brace-expansion <1.1.18` 受 GHSA-rgw5-rvv9-x895 影响，1 系补丁版本为 `1.1.18`；此前 GHSA-mh99-v99m-4gvg 的 1 系补丁下限为 `1.1.17`。因此应直接落到 `1.1.18`，而不是停在 `1.1.17`。
- 最小建议：在根 `pnpm-workspace.yaml` 增加定向 override：`"exceljs@4.4.0>uuid": "11.1.1"`；增加同主版本补丁 override：`"brace-expansion@>=1.0.0 <1.1.18": "1.1.18"`。前者是跨主版本替换，须以 Excel 生成/解析和条件格式 UUID 路径验证；后者满足 `minimatch@3.1.5` 声明的 `^1.1.7`，兼容风险低。

## 2026-08-13 生产依赖许可证门禁复核

- 收集时间：2026-08-13 13:20 CST（Asia/Shanghai）。
- 本地锁定链：`exceljs@4.4.0 -> unzipper@0.10.14 -> binary@0.3.0 -> buffers@0.1.1 / chainsaw@0.1.0 -> traverse@0.3.9`；`exceljs@4.4.0 -> jszip@3.10.1 -> pako@1.0.11`。
- `exceljs@4.4.0` 的 npm 元数据和发布包 `LICENSE` 均为 MIT。`chainsaw@0.1.0` 与 `traverse@0.3.9` 的 npm 元数据为历史写法 `MIT/X11`；`traverse` 发布包内容是标准 MIT 许可文本，可将该精确原始值作为 MIT 系兼容别名放行。
- `jszip@3.10.1` 是 `(MIT OR GPL-3.0-or-later)`；上游明确允许在 MIT 与 GPLv3 中选一，本项目可选 MIT，不因此引入 GPL 义务。
- `pako@1.0.11` 是 `(MIT AND Zlib)`：普通文件适用 MIT，`lib/zlib` 适用 Zlib。它不能被当作“仅 MIT”，但 MIT 和 Zlib 都是宽松许可，可在同时保留两类通知的前提下批准该精确组合表达式。
- `buffers@0.1.1` 的 npm 元数据没有 `license`，发布包也没有 `LICENSE` 或许可声明，所以 pnpm 报 `Unknown` 是准确的。Debian 对同版本源码的审核记录称，上游后续 commit 已将其声明为 MIT；但原 GitHub 仓库目前不可访问，这一项的一手可验证强度低于其他依赖。
- 最小修改建议：许可证门禁仅新增精确值 `MIT/X11`、`(MIT OR GPL-3.0-or-later)`、`(MIT AND Zlib)`；不得全局放行 `Unknown`。若团队接受 Debian 的上游许可证溯源，只对 `buffers@0.1.1` 做包名+版本精确例外；若要求发布包本身必须带许可文本，则不应豁免，应替换该间接依赖链或先做法务确认。
