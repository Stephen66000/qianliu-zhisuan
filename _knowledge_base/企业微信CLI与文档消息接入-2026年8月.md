# 企业微信 CLI 与文档、智能表格、员工消息接入

- 收集时间：2026-08-03（Asia/Shanghai）
- 适用对象：10 人及以下企业/小团队

## 结论

1. 企业微信官方 `wecom-cli` 对 10 人及以下小团队开放消息、文档、智能表格、日程、会议、待办等能力。
2. 文档可以新建、读取（Markdown）、覆写；智能表格可以新建，并管理子表、字段和记录的增删改查。
3. 已有文档和智能表格可直接传企业微信文档 URL，或传 `docid`；但仍受当前机器人/扫码账号的访问权限约束，不能越权读取任意链接。
4. CLI 的消息能力可给企业成员单聊发文本，也可给内部群聊发文本；单聊使用成员 `userid`，群聊使用群 `chatid`。当前 CLI 文档标明发送仅支持文本，最大 2048 字节。
5. “群消息推送 Webhook”主要是外部系统向指定内部群单向推送，不能据此向任意员工单聊，也不能用它监听员工发言。
6. 若需求是“员工在企微里给机器人发消息，后台接收并回复”，应使用 API 模式智能机器人（或自建应用回调）；实时接收可采用企业微信回调/长连接，主动发消息再调用机器人/应用消息接口。CLI 本身提供拉取最近 7 天消息和主动发送命令，但不是一个常驻 Webhook 服务。

## 本企业实测（2026-08-03 16:15）

- 官方 CLI 版本：`0.1.9`
- 扫码初始化：成功，Bot ID 与 Secret 已获取并加密保存到本机。
- 文档/智能表格：CLI 返回完整工具列表，企业端已授权该品类。
- 待办：CLI 返回完整工具列表，企业端已授权该品类。
- 通讯录：失败，企业端返回 `当前企业暂不支持授权机器人「通讯录」使用权限`。
- 消息：失败，企业端返回 `当前企业暂不支持授权机器人「消息」使用权限`。
- 日程：失败，企业端返回 `当前企业暂不支持授权机器人「日程」使用权限`。
- 会议：失败，企业端返回 `当前企业暂不支持授权机器人「会议」使用权限`。

判断：本企业当前只能使用文档/智能表格与待办 CLI，不能使用 CLI 给员工或群聊发消息。该权限组合与官方所述“企业场景只开放文档和待办”的表现一致，说明企业微信服务端没有把该企业识别为可使用小团队扩展能力的企业，或该能力尚未对该企业开放。没有继续创建测试文档、发送消息或开展后续接入。

### 精确 10 人的边界冲突

企业后台实查为正好 10 人。企业微信官方帮助页同一页面存在边界重叠：一处写“10人及以下”为个人/小团队，另一处又写“10人及以上”为企业场景。正好 10 人同时命中两种规则。

本企业服务端实际只下发“文档/智能表格 + 待办”，与官方定义的企业场景能力一致；因此可以判断，本企业在 CLI 权限服务中被按“10人及以上企业”处理。对该企业而言，消息、通讯录、日程、会议能力的实际可用门槛很可能是少于 10 人（最多 9 人），而不是 README 所写的 10 人及以下。该结论来自官方文档冲突与本企业实测的交叉推断，官方尚未公开精确 10 人的判定细节。

## 关键命令

```bash
npm install -g @wecom/cli
npx skills add WeComTeam/wecom-cli -y -g
wecom-cli init

# 普通文档
wecom-cli doc create_doc '{"doc_type":3,"doc_name":"项目周报"}'
wecom-cli doc get_doc_content '{"url":"https://doc.weixin.qq.com/doc/xxx","type":2}'

# 智能表格
wecom-cli doc create_doc '{"doc_type":10,"doc_name":"项目任务表"}'
wecom-cli doc smartsheet_get_sheet '{"url":"https://doc.weixin.qq.com/smartsheet/xxx"}'

# 发员工单聊消息
wecom-cli msg send_message '{"chat_type":1,"chatid":"员工userid","msgtype":"text","text":{"content":"你好"}}'

# 发内部群消息
wecom-cli msg send_message '{"chat_type":2,"chatid":"群chatid","msgtype":"text","text":{"content":"大家好"}}'
```
