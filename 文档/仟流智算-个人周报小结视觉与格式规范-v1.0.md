## 🎯 01 / 产品定位与设计哲学

### 1.1 从“监控看板”到“陪伴手账”
在传统的企业级 IT 系统中，用量报表通常以冷峻、严肃、甚至带有压迫感的技术看板（如 Grafana 仪表盘）呈现。
仟流智算个人周报彻底打破这一范式：
- **人文温度**：员工打开企微收到的不是“审查清单”，而是一张犹如高级文具手账、私人信笺般的**白色浮动卡片**；
- **精神锚点**：卡片以专属**金句**开篇，提振员工每周开启协同工作的心智；
- **克制理性**：摒弃巨幅大数字轰炸，回归 14px 沉稳墨黑排版，让核心指标（请求次数、Token 消耗、日均水平、协同习惯）清晰、安静地呈现；
- **品牌归属**：左下角企业标识与右下角原生矢量 Logo 稳固锚定，建立企业级信任感。

## 🏛 03 / 栅格系统与绝对对齐基准（核心数学法则）

为彻底消除版面视觉上的“左窄右宽”、“上窄下空”问题，本规范锁定两套空间几何基准：

```text
X = 94px (主左基线)              X = 118px (内容缩进线)                  X = 445px (右锚定线)
    │                                │                                      │
    ├─ 张三                          ├─ 一周小结 9.7-9.11                    │
    ├─ “ (外挂引号)                  ├─ 功不求疾，但求有恒 ”                │
    ├─ ──────────────────────────────┼──────────────────────────────────────┤ (浅线)
    │                                ├─ 总请求次数                          │
    │                                ├─ 75 次                               │
    ├─ ──────────────────────────────┼──────────────────────────────────────┤
    │                                ├─ 周消耗 Token 总量                   │
    │                                ├─ 32.9 万                             │
    ├─ ──────────────────────────────┼──────────────────────────────────────┤
    │                                ├─ 日均使用量                          │
    │                                ├─ 4.7 万 / 天                         │
    ├─ ──────────────────────────────┼──────────────────────────────────────┤
    │                                ├─ 最晚请求时间                        │
    │                                ├─ 周四深夜 23:15                      │
    ├─ ──────────────────────────────┼──────────────────────────────────────┤ (预留空行)
    │                                │                                      │
    ├─ 仟流智算                      │                        ┌────────────┐│
    ├─ Qianliu IC                    │                        │ 仟流 Logo  ││
    │                                │                        └────────────┘│
```

### 3.1 X 轴双垂直对齐法则
1. **主基准轴（`X = 94 px`）**：
   - 贯通卡片左侧的核心骨架：**顶部标题「姓名」、金句前双引号「`“`」、横线起点、底栏「仟流智算」、底栏「Qianliu IC」**全部在 `X = 94` 绝对左对齐；
2. **标点外挂缩进轴（`X = 118 px`）**：
   - 采用经典字体排版（Hanging Punctuation）规则：金句首字**「功」**位于 `X = 118`，使开头的双引号自然悬挂在行外空白处；
   - **中间所有数据指标**（标签如「总请求次数」、数值如「75 次」）**统一在 `X = 118` 严格左对齐**，与金句正文形成优美的阶梯式垂直律动；
3. **右侧锚定轴（`X = 445 px`）**：
   - 所有横线的最右端为 `X = 445`（横线全宽为 `351 px`）；
   - 右下角官方 Logo 的最右边界与 `X = 445` 严格对齐，形成右侧直角支撑。

### 3.2 Y 轴绝对等距居中法则（彻底消除失衡）
- **内容整体包围盒（Content Bounding Box）**：
  - 从「张三」文字顶部（`Y = 121`）到底部「Qianliu IC」/ Logo 底端（`Y = 679`），高度精确锁定为 **`558 px`**；
- **上下绝对等距**：
  - 卡片高度为 `700 px`；
  - **顶部空白留白 = `71 px`**；
  - **底部空白留白 = `71 px`**；
  - `顶部留白 === 底部留白`，实现像素级 1:1 绝对垂直居中，彻底消除任何“上面窄、下面宽”的局促感。
- **金句开阔呼吸距**：
  - 标题「张三 一周小结」底线至金句的垂直距离设置为 **`94 px`**（较常规间距翻倍），使金句具有仪式感与尊崇感；
- **指标行距翻倍**：
  - 指标标签基线到下方数值基线的垂直距离设置为 **`24 px`**（数据在标签下方清晰舒展，杜绝贴在一起）。

### 3.3 预留手账线与行距自适应机制
- **预留行数**：在最后一项指标下方，**仅预留 1 行手账线**（彻底移除多余的空行），保留记事本信笺韵味的同时保持卡片精炼紧凑；
- **自适应行距算法**：
  - 当展示 **4 项常规指标** 时：单项槽位高度（Slot Height）为 **`68 px`**；
  - 当展示 **5 项扩展指标**（如加入主力模型分布）时：槽位高度自动动态收缩为 **`56 px`**；
  - 无论指标数量为 4 项或 5 项，外层白卡尺寸、上下外边距（71px:71px）均保持绝对静止稳定！

## 🏷 06 / 核心指标与行业专业术语定义

### 6.1 Token 计量单位统一规范（“万”与“亿”自适应进位规则）
在《个人周报小结》与《全员用量周报》中，所有关于大模型 Token 消耗量的数值一律**杜绝使用无单位或超长千分位纯数字**（如 `328,500 Tokens`），统一推行**“万”与“亿”智能进位法则**：
1. **统一单位后缀**：
   - 消耗总量后缀统一为 **`万`** 或 **`亿`**；
   - 日均用量后缀统一为 **`万 /天`**（或 `亿 /天`）；
2. **精度与四舍五入规范**：
   - 数值除以相应基数后，**严格保留 1 位小数，最后一位四舍五入**（如 `328,500` $\rightarrow$ `32.9 万`；`46,928` $\rightarrow$ `4.7 万 /天`；`1,280,000` $\rightarrow$ `128.0 万`）；
3. **阈值分界阶梯**：
   - **用量 $< 100,000,000$（1 亿）**：以 **`万`**（÷ 10,000）作为基准计量单位；
   - **用量 $\ge 100,000,000$（1 亿）**：自动升格进位为 **`亿`**（÷ 100,000,000），防止图片版面因数字超长而挤压变形。

### 6.2 核心指标定义速查表

| 指标字段 | 官方推荐文案 | 计量单位 | 示例数值 | 业务口径定义 |
| :--- | :--- | :--- | :--- | :--- |
| `totalRequests` | **总请求次数** | `次` | `75 次` | 本统计周（周一 00:00 至周日 23:59）内，该员工通过仟流网关发起的有效模型交互/API请求总和。 |
| `totalTokens` | **周消耗 Token 总量** | `万` 或 `亿` | `32.9 万` | 本统计周内输入 Token 与输出 Token 的合计总消耗，按万/亿单位换算并保留 1 位小数。 |
| `dailyAvgTokens`| **日均使用量** | `万 /天` 或 `亿 /天` | `4.7 万 /天` | `总消耗 Token ÷ 7 天`，反映日常与 AI 协同深度，按万/亿换算保留 1 位小数。 |
| `latestTime` | **最晚请求时间** | 文本 | `周四深夜 23:15` | 本统计周内该员工发起请求的最晚物理时间点，体现“最深陪伴”时刻。 |
| `topModel` *(可选)*| **核心主力模型** | 文本 | `DeepSeek V3` | （5 指标版本支持）过去 7 天内该员工消耗 Token 最多的具体主力模型版本代号。 |

## 🖼 07 / Logo 资产与对齐规范（高精水平基线对齐法则）

1. **Logo 官方标准资产**：提取自工程官方透明标准资产（`apps/worker/src/reporting/assets/qianliu-logo-cropped.png`），剔除所有外围透明留白，四周以最外缘像素紧凑裁切（物理尺寸 `124 × 124` 矢量正方形），避免任何隐形透明填充；
2. **渲染尺寸**：SVG 中等比渲染为 **`38 × 38 px`**（`x = 407, y = 641`），与左侧「仟流智算」(16px) +「Qianliu IC」(12px) 构成完美的双行品牌字高度平衡；
3. **蓝角下沿与英文下端绝对水平对齐法则（强制核心约束）**：
   - **设计准则**：对齐基准**不是指 Logo 整体外框或图片边界**，而是 **Logo 蓝色的最下端（即右下角蓝色括弧 `┘` 的物理最底边缘），必须与左侧英文字样「Qianliu IC」整个英文的最下端（Baseline $Y = 679$）处于同一条绝对水平线上**；
   - **定位数学公式**：
     - 左侧英文 Baseline：$Y = 679$；
     - Logo 顶部位置：$Y = 679 - 38 = 641$；
     - Logo 底部物理边界：$641 + 38 = 679$；
     - Logo 右边缘：$X = 407 + 38 = 445$（与上方信笺横线右端 $X = 445$ 形成严谨垂直锚定）。
   - 经真机与高分屏测试，此对齐方式彻底消除了 Logo 视觉上偏高、浮起的问题，达到大厂工业级平面排版质感。

## 💻 08 / 数据接口与代码渲染架构

### 8.1 数据结构定义（TypeScript Payload）

```typescript
export interface PersonalWeeklyReportData {
  userId: string;
  userName: string;              // 姓名，如 "张三"
  dateRange: string;             // 周期文案，如 "一周小结 9.7-9.11"
  quote: string;                 // 金句，如 "功不求疾，但求有恒"
  quoteColor?: string;           // 默认 "#D97706"
  metrics: Array<{
    label: string;               // 标签，如 "总请求次数"
    value: string;               // 数值，如 "75" 或 "32.9"
    unit?: string;               // 单位，如 "次"、"万"、"万 /天"
  }>;
}

/**
 * 格式化 Token 用量指标为“万”或“亿”
 * 保留 1 位小数，四舍五入
 */
export function formatTokenVolume(tokens: number, isDailyAvg: boolean = false): { value: string; unit: string } {
  if (tokens >= 100_000_000) {
    const val = (tokens / 100_000_000).toFixed(1);
    return { value: val, unit: isDailyAvg ? '亿 /天' : '亿' };
  }
  const val = (tokens / 10_000).toFixed(1);
  return { value: val, unit: isDailyAvg ? '万 /天' : '万' };
}
```
