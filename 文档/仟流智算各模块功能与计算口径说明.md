# 仟流智算各模块功能与计算口径说明

2026年9月14日 2.5 正式发布版

仟流智算用于统一管理企业的 AI 使用主体、厂商供给、调用规则、实际用量与经营支出，并提供端到端的运行保障闭环、企业微信智能服务与激励引擎，以及合规安全的系统设置管理。管理者可以沿着“谁在用、用什么、如何控制、用了多少、花了多少、哪里异常、谁在管理、如何触达与激励”的闭环理解并运营整套系统。

### 阅读方式

每个模块按管理功能、重点指标、计算或判断规则、注意事项介绍。配置型模块的“算法”主要是权限、状态机与策略判断，不强行编造经营指标。示例中的金额、Token 和比例仅用于解释计算方式。

**版本基准**：当前模块名称、计算公式、业务行为与数据库模型以**应用版本 `c62f910`（Git Tag: `2.5`）、数据库迁移基线 `0074_runtime_notification_recipients`** 为权威基准。文末列出子功能边界及实现索引，便于工程维护与审计追溯。

## 0 首页看板（标准版）

### 管理范围与功能

面向企业负责人的月度经营概览与资源健康入口，分两个主分区：
1. **本月概览**：包含“本月 Token 消耗”、“本月费用”、“本月活跃员工”、“本月活跃项目”四张核心 KPI 指标卡；
2. **接入资源**：按厂商列出资源数量、形态（API / 套餐）、调用状态与一句话关注信息。

每张卡片与区块右上角入口均可一键下钻跳转到对应的明细业务页。

### 重点指标与权威来源

| 指标 | 权威来源与口径 | 点击去向 |
| --- | --- | --- |
| 本月 Token 消耗 | 与厂商资源 / 用量总览同源：成功请求（不筛结算状态）的账本行，输入 + 输出合计（北京自然月） | 厂商资源 / 用量总览 |
| 本月费用 | 与经营账单月度总览同源：本月总花费（连续资金账本口径，同币种聚合展示，卡片统一百底） | 经营账单 / 月度总览 |
| 本月活跃员工 | 与用量账本 / 用量概览同源：成功且已结算请求的去重员工数（企业时区自然月） | 用量账本 / 用量概览 |
| 本月活跃项目 | 与经营账单项目账同源：当月有用量归属的去重项目数（严格排除未归属请求） | 经营账单 / 项目账 |

### 同期比较与状态规则

- **半开区间环比基线**：每张卡片提供上月同期参照。时间范围严格取 `[上月 1 日 00:00:00, 上月同一日同一时刻)` 的真实数据聚合；若上月无对应日期（如 3 月 31 日对应 2 月无 31 日），则截止上月月末，并在脚注明确注明。同期为真实数据聚合，不按天数线性推算。
- **差异值表达**：上期为 0、未知或不可比（如多币种混合、数据缺口）时不输出百分比；员工与项目展示纯数值差。Token 卡为页面唯一青色焦点卡，变化量数值保持中性色，避免红绿视觉干扰。
- **接入资源健康态聚合（最差状态原则）**：
  - 接入资源区的厂商调用状态采用厂商内部所有资源的“最差状态”聚合展示：`异常 (unhealthy) > 局部异常 (degraded) > 待确认 (pending_check) > 正常 (normal)`；
  - 额度或余额同步失败、同步数据过期与实际调用状态分别独立判断，状态正常的厂商完整列出资源清单；
  - 凭证失效、调用超时等异常均以固定模板给出具体关注信息与影响范围。右上角“管理资源”直达厂商资源中心。

### 需要注意

- **Token 与费用的集合口径差异**：首页 Token 只统计成功请求；经营费用包含产生实际消耗但最终由于客户端中断等原因失败的请求。两张卡片数字来自各自业务权威源，不构成绝对同一集合。
- **去重独立性**：活跃员工与活跃项目分别独立去重统计，不可将两者数字相加；项目账中的“未归属项目”占位行不计入活跃项目数。
- **服务端聚合与防清零**：数据来自服务端高性能聚合接口（`GET /dashboard/home`），前端只负责格式化呈现；用户点击刷新重新拉取，接口失败时前端保留现有状态并提供重试，绝不清零页面数据。

## 阅读前先区分四类核心数据

### 1. Token 用量与额度扣减

- **总 Token**：按输入 Token（Input Tokens）加输出 Token（Output Tokens）汇总。
- **细分结构**：缓存命中 Token（Cache Hit Tokens）是输入 Token 的子分项；思维链推理 Token（Reasoning Tokens）是独立统计的生成细分字段。**严禁直接将四个字段无脑相加**。
- **套餐扣减**：套餐扣减额度按原始计量值乘命中倍率计算（`套餐扣减 = 原始计量 × 倍率`）。倍率改变的是套餐额度消耗速度，绝不会改变模型实际输入和输出了多少真实 Token。

### 2. API 消耗与现金付款

- **API 消耗**：请求在网关结算产生的计价费用（权责发生制）；
- **充值**：向厂商账户注入的可用额度或授信；
- **实付人民币**：企业银行账户或财务采购实际支出的现金事实；
- **套餐费用**：已登记的订阅周期付款净额。
- 四者在发生时间、记账周期和币种上均有差异。**充值金额绝不能直接当成当月的 API 实际消耗**。

### 3. 多币种与汇率原则

- 不同币种（如 CNY、USD）必须独立汇总，严禁跨币种混加。系统默认币种仅用于单币种视图下的首选展示，不执行任何未经财务确认的动态汇率自动折算。已有“实付人民币”记录时，按实付现金对账，不随意捏造汇率。

### 4. 时间范围与业技分离原则

- **经营账单**：按北京时间自然月（每月 1 日 00:00:00 至次月 1 日 00:00:00，左闭右开 `[start, end)`）统计。
- **用量概览**：按企业时区（如 Asia/Shanghai）划分日、周、月。
- **业技分离原则**：0 Token 的技术失败（如连接超时、上游 500 第一跳失败）在网关直接确认为 `CONFIRMED_ZERO_NO_UPSTREAM`，成本精确确认为 ¥0.00，绝不产生“未知费用”缺口污染财务账本；故障排查与调用耗时归位到运行保障异常中心。

## 1 使用主体

### 管理范围与功能

管理企业内真正调用 AI 的员工（Member）与项目（Project）主体，包含主体的创建、更名、启用、停用、归档以及满足约束条件时的物理删除。负责 API Key 颁发与撤销、模型授权白名单与有效期管控、额度上限与周期扣减，以及核算归属（部门与项目负责人）。支持组织通讯录同步与批量模型授权。

### 重点指标与字段

| 指标或字段 | 如何理解 |
| --- | --- |
| 主体类型与状态 | 员工（MEMBER）或项目（PROJECT）；正常启用（ACTIVE）、停用（DISABLED）、已归档（ARCHIVED） |
| 模型授权与有效期 | 允许该主体调用的模型列表，以及每项授权的生效开始与截止时间 |
| 授权额度与已用额度 | 主体在当前周期（如当月）内的额度限额与已消耗累计额度 |
| API Key 状态 | 用于业务调用的凭证状态；停用主体或手动撤销会立即使 Key 失效 |
| 部门与项目负责人 | 用于费用分摊与账单核算归属；项目所属部门继承自项目负责人的归属部门 |

### 额度预占与结算校正算法

为避免高并发调用导致额度透支穿透，网关采用**“两阶段预占与校正机制”**：

1. **调用前预检与预占**：
   - 当前剩余额度：$$\text{额度剩余} = \text{授权额度} - \text{当前周期已用额度}$$
   - 预计剩余额度：$$\text{预计剩余} = \text{额度剩余} - \text{本次预估扣减}$$
   - 若预计剩余 $< 0$ 且配置不允许超额，网关立即拦截并返回 `QUOTA_EXCEEDED`；若允许超额，则记录超额放行标记。
   - 放行时原子递增已用额度进行预占：$$\text{已用额度}_{\text{预占}} = \text{已用额度}_{\text{原}} + \text{本次预估扣减}$$

2. **调用后结算校正（守恒闭环）**：
   - 请求结算完成后，网关根据实际产生的 Token 计量和命中计价规则，计算实际扣减值，并原子校正主体额度：
     $$\text{新已用额度} = \max\left(0, \text{已用额度}_{\text{预占}} - \text{本次预估扣减} + \text{本次实际扣减}\right)$$
   - 该机制从根本上解决了高并发请求同时看到大额余额导致透支击穿的问题。

### 需要注意

- **主体与后台管理员完全解耦**：使用主体用于承载 AI API 请求，不具备管理后台登录权限；管理员账号由系统设置单独维护。通讯录存在的人员，必须明确开通主体并授予模型权限后方可调用。
- **停用与归档保护**：停用主体将同步吊销其名下所有有效的 API Key；对于已产生调用流水和账单记录的主体，系统禁止物理删除，仅允许归档，以保障历史审计与财务账本的外键完整性。
- **部门与负责人变更的时效性**：调整员工部门或项目负责人仅对后续新结算生效；历史已冻结或已结账月份的账单归属保持历史快照不变。

## 2 厂商资源

### 管理范围与功能

厂商资源中心是整座平台唯一的**“原材料供应链底座与资金核算总基地”**。统一接入外部 AI 模型供应商（智谱、DeepSeek、Moonshot/Kimi、MiniMax、阿里通义、OpenAI 等），管理资源接入、模型权限探测、凭证维护、额度窗口同步、供给健康监控、连续资金总账与充值订阅记录。

### 厂商资源中心 · 四大根本原则

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                             厂商资源中心 · 四大根本原则                       │
├──────────────────────┬──────────────────────┬───────────────────────────────┤
│ 原则一：差异化精准算账 │ 原则二：真金白银严格守恒 │ 原则三：权责发生制 (事实至上)   │
│ (计费与数学基石)     │ (资金中枢与账本闭环) │ (模型状态与计费事实解耦)       │
├──────────────────────┴──────────────────────┴───────────────────────────────┤
│ 原则四：业技清晰分离 (财务闭环 vs 运维排障：0 Token 失败不污染财务账本)         │
└─────────────────────────────────────────────────────────────────────────────┘
```

1. **原则一：差异化精准算账原则（严禁均价，快照固化）**：
   - 每一款模型定价截然不同，网关结算必须严格绑定实际承载请求的底层模型（`actual_model`），严禁使用模糊均价；
   - 细分输入、输出、Cache 命中、思考推理分项计量；
   - 账本行（`ledger_line`）结算时必须永久固化发生时刻的计价规则版本快照，即使厂商后续调价，历史账目 100% 可精准还原复核。
2. **原则二：真金白银与严格守恒原则（资金中枢）**：
   - 全局花钱唯一收口。连续流水总账自动平滑跨月滚动，无需每月补建期初：
     $$\text{当前可用余额} = \text{期初基线} + \sum \text{累计充值} + \sum \text{对账调账} - \sum \text{历史至今所有真实 Token 消耗}$$
3. **原则三：权责发生制（模型下架与计价事实解耦）**：
   - 模型下架仅代表路由层不再接收新请求，绝不抹除历史计费事实；
   - 账单与明细报表严禁用“在架模型”过滤历史数据，已下架模型完整保留并明确标注“已下架”徽章，确保各项求和 100% 等于总花费。
4. **原则四：业技清晰分离原则（0 Token 失败零成本）**：
   - 请求在第一跳失败且 `input=0, output=0` 时，直接确认为 `CONFIRMED_ZERO_NO_UPSTREAM`，费用精确记为 ¥0.00000000，严禁触发“财务缺口”误报；技术故障沉淀在运行保障异常中心。

### 资源双轨形态与命名规范

- **双轨形态**：
  - **API 按量资源**：基于账户余额实时扣减，随用随扣（如 DeepSeek、MiniMax）；
  - **Coding Plan 套餐资源**：按月/年订阅固定并发与额度，按服务周期管理窗口（如 Kimi 编程套餐）。
- **资源命名自适应规范**：新增或同步资源时，系统自动识别并追加规范日期后缀（如 `-0910`），区分历史多批次采购，保证资源识别清晰。

### 100% 权限探针与模型同步

- 网关探针在同步厂商资源时执行模型权限探测：
  - 将上游返回的 `403 Forbidden`（账号未开通某模型权限）与“资源健康降级”彻底解耦；
  - 自动从可用路由列表中过滤掉未授权模型及非活动模型（如 `k3-256k`），避免由于单个未开通模型导致整个资源被错误标记为故障，确保前端下拉与路由候选 100% 真实可用。

### 供给速度与耗尽预测算法

系统采用多时间窗口加权移动平均算法预测资源供给耗尽时间：

1. **多窗口速度统计**：
   - 分别统计近 1 小时、近 24 小时、近 7 天的消耗速度：
     $$\text{速度}_i = \frac{\text{窗口消耗量}_i}{\max(\text{已覆盖小时数}_i, 1)}$$
   - 覆盖不足窗口时长 1/4 或无数据点时，该窗口剔除不参与预测。
2. **综合速度加权计算**：
   - 近 1 小时、24 小时、7 天的权重依次为 0.5、0.3、0.2：
     $$\text{综合速度} = \frac{\sum (\text{速度}_i \times W_i)}{\sum W_i}$$
3. **耗尽时间与置信度**：
   $$\text{剩余可用小时} = \frac{\text{当前剩余额度}}{\text{综合速度}}$$
   $$\text{预计耗尽时间} = \text{当前时刻} + \text{剩余可用小时}$$
   - 数据点 $< 10$ 时置信度评定为“低”；达到门槛且 1 小时、24 小时均有效时评定为“高”，否则为“中”。剩余额度未知或消耗为 0 时不输出伪造的耗尽时间。

## 3 额度规则

### 管理范围与功能

管理模型计价策略与动态调度规则。计价规则决定“单次调用按何种单价与倍率结算”；调度策略决定“在当前网络状态、余额阈值和时段条件下放行、平滑切换等价资源、限流还是阻断”。

### 计价公式与定点精度

API 费用按分项 Token 精确计算，采用十进制定点精度（Decimal）：

$$\text{API 基础费用} = \text{Cache 命中输入} \times P_{\text{hit}} + (\text{总输入} - \text{Cache 命中输入}) \times P_{\text{unhit}} + \text{输出} \times P_{\text{output}} + \text{推理 Token} \times P_{\text{reasoning}}$$

- **倍率计价模式**：最终费用 = $\text{API 基础费用} \times \text{规则版本倍率}$；
- **直接单价模式**：按基础费用直接结算，不额外乘倍率；
- **套餐扣减**：套餐额度扣减 = $\text{原始计量} \times \text{命中倍率}$（按整数结算）。

### 规则匹配唯一性优先级算法

当系统存在多条生效计价规则时，引擎严格按照以下优先级选出**唯一**生效版本，严禁多规则倍率叠乘：
1. **优先级数值更小**（数值越小，优先级别越高）；
2. **适用范围更具体**（指定具体资源与底层模型优先于泛指通配规则）；
3. **配置时间窗规则**（配置了星期/时间段的限时规则优先于全时段通用规则）；
4. **生效版本较新**（生效时间更新的规则版本优先）；
5. **规则 ID 稳定排序**（兜底确定性排序）。

### 技术路由评分算法

技术路由在过滤掉不可用资源与本请求已重试失败的资源后，在最小优先级候选组内按以下公式评分选出最优承载资源：

$$\text{Score} = 0.4 \times \text{归一化权重} + 0.4 \times \text{健康因子} + 0.2 \times \text{会话亲和因子}$$

- **健康因子**：正常（Normal）= 1.0，降级（Degraded）= 0.6，半开探测（Probing）= 0.3；
- **会话亲和因子**：命中该会话最近一次成功调用的资源 = 1.0，否则 = 0.0；
- 最高分资源中选，同分按资源 ID 升序稳定选择。

### 调度节省计算口径

$$\text{调度节省} = \text{基线路由在同等条件下的可比成本} - \text{实际执行调度动作后的结算成本}$$

必须确实执行了降本路由策略并保留可比单价快照方可计入调度节省；未触发动作或基准不可比时不计入虚假节省。

### 重点指标与质量标记

| 指标 | 口径说明 |
| --- | --- |
| 活跃主体数 | 所选时间范围内产生已结算调用的去重主体数 |

## 5 经营账单（v2.1 全面升级版）

### 管理范围与功能

按北京时间自然月汇总企业在 AI 上的全部资金流动与投入产出，包含六大标准子页签：
1. **月度总览**：全盘资金变动大盘、本月总花费、API 消耗与套餐费用、人均指标；
2. **员工账**：按员工维度穿透费用与用量；
3. **项目账**：按项目维度归集费用，支持动态多厂商列与 CSV 导出；
4. **部门账**：按组织架构归集部门费用，支持动态多厂商列与 CSV 导出；
5. **价值确认**：账号复用与稀释折算模型，量化企业集中采购相比散采的真实节约价值；
6. **套餐利用率与采购复盘**：厂商套餐饱和度评估与历史现金流采购复盘。

*(注：旧版冗余的独立“对账与导出”二级页签已全面收敛整合入标准化操作流程中。)*

### 连续资金总账模型与平衡关系

经营账单与厂商资源资金池底层完全打通，遵循真金白银守恒定律：

$$\text{期初可用余额} + \text{本月累计充值} + \sum \text{本月对账调账} - \text{本月 API 花费} = \text{期末可用余额}$$

- **多币种独立平衡**：CNY 与 USD 分开建账与独立平衡，严禁混币种计算；
- **跨月平滑结存**：上月期末结存自动作为本月期初，无需每月人工重新初始化，历史数据平滑连续；
- **成本卡片视觉规范**：每百万 Token 综合成本卡片统一采用纯白高保真底色规范，确保视觉层级一致。

### 部门账与项目账 · 动态多厂商列与导出

在传统报表中写死固定厂商列会导致接入新厂商时账目脱节。v2.1 引入**“动态厂商多列计算与渲染引擎”**：
1. **动态列聚合**：系统自动扫描当月实际产生费用的全部供应商（如智谱、Kimi、MiniMax、阿里、OpenAI 等），在表格中动态扩展对应的费用列；
2. **动态 CSV 一键导出**：点击“导出 CSV”，导出的表头与列结构与屏幕所见的动态厂商列 100% 保持一致，便于财务直接导入 ERP。

### 套餐分摊算法（最大余数法 Hare-Niemeyer）

当月套餐费用按主体在同资源内的原始 Token 消耗比例分摊：

$$\text{主体分摊费用} = \text{该资源当月套餐付款净额} \times \frac{\text{主体当月该资源 Token}}{\text{该资源当月总 Token}}$$

- **尾差守恒补齐**：分摊金额精确到分。计算时先向下取整，对因舍入产生的剩余微小金额，按照各主体小数部分余数由大到小排序依次补齐 1 分钱，保证**全员分摊之和 100% 严格等于套餐总净额**。

### 价值确认模型（账号复用与稀释折算）

为解答“企业集中采购与自建网关到底帮公司省了多少钱”，价值确认页签采用**“账号复用与稀释折算模型”**：
- 对比企业通过高并发复用 Coding Plan 订阅及批量采购协议的实际支出成本与员工个人散采公有云官方按量调用的标称费用（Benchmark Cost）；
- 差额部分即为**“已确认采购节约价值”**，为管理层评估 AI 基础设施投资回报率（ROI）提供直接量化支撑。

### 套餐利用率与采购复盘公式

- **单厂商月利用率**：
  $$\text{月利用率} = \frac{\text{该厂商当月 Coding Plan 消耗 Token}}{\text{该厂商历史月份最高消耗 Token 峰值}} \times 100\%$$
- **年内平均月付款**：
  $$\text{平均每月付款} = \frac{\text{当年 1 月至当前月累计现金实付}}{\text{当前月份序号（如 9 月除以 9）}}$$
- **人均月 Token**：公司当月总 Token ÷ 统计时点未归档员工总数（包含停用未归档员工）。

2. **通知接收人配置（0074 迁移）**：告警通知渠道与人员名录管理，支持企业微信、Webhook、邮件等通道维护，支持接收人姓名智能解析与一键连通性测试。

### 异常生命周期与闭环规则

```
┌──────────┐     人工标记已处理      ┌──────────┐
│  待处理  │ ────────────────────> │  已处理  │
└──────────┘                       └──────────┘
     │                                  │
     │ 出现后续成功客观证据               │ 出现后续成功客观证据
     v                                  v
┌──────────────────────────────────────────────┐
│                   已恢复                     │
│  (记录恢复时间点与同资源后续成功 Attempt 关联)  │
└──────────────────────────────────────────────┘
```

- **客观恢复证据**：系统不因“某次扫描未查出”就假定故障恢复。已发生异常的资源或模型，必须在出现**“同资源后续真实调用成功”**或**“后台同步重试成功”**的客观时间戳与 Attempt 记录时，方自动翻转为“已恢复”；
- **排他性过滤**：常规额度超额拦截（Quota Exceeded）、策略主动限流或客户端主动中断不作为故障写入异常中心。

- **一键连通性测试（Ping Test）**：提供“发送测试通知”功能，即时调用 Webhook 发送测试报文并校验 HTTP 响应，秒级检验网络打通状态。

- **自定义岗位配置引导闭环**：
  - 当系统中尚未配置自定义岗位或权限为空时，在新增管理员卡片与角色选择区呈现直观指引链接：`💡 尚未配置自定义岗位？前往配置岗位与权限 →` 或 `配置「{岗位名称}」权限 →`；
  - 点击链接后，页面**平滑滚动并高亮聚焦**到下方的“自定义岗位配置”区域，形成丝滑的管理闭环。

### 权限模型与最后超管行锁保护

- **两级权限架构**：
  - **超级管理员（SUPER_ADMIN）**：默认拥有全部 8 个模块的查看与操作权限；
  - **自定义角色（CUSTOM）**：定义一套岗位名称（如“财务审计员”、“运维专员”），并按模块独立勾选 `view`（可查看）与 `operate`（可操作）。
- **最后超级管理员保护机制（Row-level Lock）**：
  - 核心接口执行降级、停用、归档或删除前，强制加数据库行级排他锁（`SELECT ... FOR UPDATE`）统计有效超管总数；
  - 当有效超管仅剩 1 人时，严禁对其执行任何削权、停用、归档或删除操作，坚决避免企业管理后台出现“全员锁定、无人可用”的死锁故障。

### 认证体系与密码安全策略

- **Argon2id 强哈希算法**：密码存储采用 Argon2id（内存 64MB、迭代 3 次、并行度 1），不留存任何明文密码；
- **密码复杂度与首次改密**：密码长度必须为 12 至 128 位，且强制同时包含大写字母、小写字母、数字与特殊字符；新建或被重置密码的管理员首次登录强制重置密码（`must_change_password=true`）；
- **防暴力破解速率限制**：内存滑动窗口流控，在指定窗口（5 至 60 分钟）内连续失败达到设定次数（3 至 10 次）后，自动锁定该账号登录；
- **会话有效期与实时截断**：会话有效期可配置（15 至 1,440 分钟）；调小有效期时，服务端动态截断现有活跃会话的最晚存活时间，确保安全策略变更即时生效。

### 审计日志时区切分与变更详情

- **企业时区精确切分**：审计日志后端 SQL 查询强制通过 `created_at AT TIME ZONE :timezone` 转换，严格按照企业所属自然日进行时间范围切分，彻底消除因 UTC 跨日时差造成的报表偏移；
- **审计事实全覆盖**：记录管理员登录、信息修改、主体变更、资源启停、额度调整与权限保存，明确区分操作人、来源 IP、动作类型并提供 JSON 级字段前后对照（Diff）。
