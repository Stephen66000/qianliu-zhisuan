## 首页看板｜本月核心指标布局

- 状态：已修改（v4）
- 问题：当前 7 张指标卡呈现为“上 6、下 1”，最后一张“有证据的调度节省”被单独挤到第二行，视觉失衡。
- 建议：改为“上 4、下 3”的 12 栅格布局。
  - 上排：厂商资源账号、活跃人数、套餐支付、API 费用。
  - 下排：充值金额、预计最早耗尽、有证据的调度节省。
- 分组逻辑：上排回答“谁在用、花了多少”；下排回答“钱够不够、风险在哪、系统创造了什么价值”。
- 设计意图：让风险与价值类卡片拥有更宽的说明空间，同时去除孤卡落单的观感。

## 首页看板｜Gateway 冷却 / 隔离资源表达

- 状态：已修改（v4）
- 问题：当前以“冷却 / 隔离资源 1”呈现系统内部状态，管理者无法判断：是账号彻底不可用、临时不可用，还是系统主动保护；也看不出对业务的影响和系统动作的价值。
- 建议：改为完整的业务因果表达，优先展示：
  - 发生了什么：例如“1 个资源触发供应商限流”。
  - 系统做了什么：例如“系统已自动暂停调用并切换至健康资源”。
  - 影响是什么：例如“当前业务无影响，预计 12:06 自动恢复”。
  - 不处理的风险：例如“继续调用会产生连续失败、重试浪费，并可能触发更长时间的供应商限制”。
- 推荐卡片文案：
  - 标题：冻结账号 1
  - 短说明：上游限流 1 · 12:06 恢复。
- 文案决策：仅替换术语，不增加卡片文字。“冻结”在团队内部的准确含义是：上游出现限制时，为避免后续请求受影响，系统暂时停止向该账号分配请求；到恢复时间后再重新放出。

## 持续供给摘要｜预测口径

- 状态：已修改（v4）
- 决策：供给侧预测以贴近正常消耗为目标，不人为采用过度保守的消耗假设。
- 实现要求：以真实剩余额度 / 余额、历史用量账本和当前消耗趋势计算；数据不足或趋势突变时降低可信度或提示异常，而不是把异常增长直接伪装成常态预测。
- 追加要求：预测必须纳入高峰 / 非高峰时段的真实请求分布与不同扣减倍率、价格或套餐规则，不能只按全天平均消耗外推；页面应能说明预测是否已包含该因素。

## 厂商资源｜统一模型与路由的新建入口

- 状态：已修改（v4）
- 用户疑问：`统一模型与路由`是否需要自己手工配置；点击“新建模型路由”没有反馈，无法理解用途与操作边界。
- 产品语义：仅管理员在接入新模型 / 新厂商时配置一次；把统一模型名映射到真实 Provider、候选账号、协议和路由策略。日常请求由 Gateway 自动选择账号，不要求业务人员逐次配置。

## 厂商资源｜资源账号登记与 API Key

- 状态：已修改（v4）
- 问题：当前原型未提供清晰的 API Key 粘贴入口，用户无法完成 DeepSeek 等 API 资源的实际登记。
- 最小登记流程：选择厂商 → 选择资源类型（API / 套餐）→ 粘贴 API Key 或完成账号授权 → 点击“测试连接”。
- 连接成功后：系统自动识别可用模型与基础能力；优先权重、并发上限等作为高级设置或由系统默认推荐，不能阻塞首次登记。
- 安全要求：API Key 仅以掩码显示和安全存储，不在页面、日志或账本中明文回显。
- 文案决策：当前资源模式为 API 时，将字段名“上游凭证”直接改为“API Key”，占位文案改为“粘贴 DeepSeek API Key”；其他认证方式再按所选类型动态显示对应名称。
- 文案决策：将“Provider 能力”改为“接口能力”；由系统探测并只读展示，用于判断资源能承接哪些请求。
