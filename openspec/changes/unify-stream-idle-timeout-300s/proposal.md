# Proposal

## Why

仟流 Gateway 当前对流式空闲使用 45 秒全局默认值，并为智谱 Coding Plan 保留 120 秒特例；厂商和模式级环境变量还能继续覆盖全局值。长推理模型可能在已经开始响应后较长时间没有新上游数据，现有门限会中止仍可能恢复的请求，而且不同协议和客户端收到的提示不一致。

本变更把正式模型调用的流式空闲门限统一为 300 秒，并在确认为流式空闲超时时返回可理解、可操作的提示，同时保证底层 HTTP、下游代理、并发租约和三种北向协议不会抢先破坏该合同。

## What Changes

- 正式流式模型调用统一使用 300,000 毫秒的连续上游空闲门限；厂商和模式级旧空闲覆盖不再改变该值。
- 将通用 Caller、正式 Gateway 装配和部署示例的默认行为对齐，保留首字节超时、总请求时限和管理探针各自的现有语义。
- 仅在 `STREAM_IDLE_TIMEOUT` 时返回“上游模型响应中断，等待超时。请稍后重试，或切换其他模型。”，并保留机器可读错误码、故障层和真实请求 ID。
- 明确空闲超时发生后不再启动新的上游 Attempt；已提交的流继续使用协议内错误，未提交的请求返回兼容的 HTTP 504 错误。
- 使底层 HTTP body timeout、并发租约和可控代理时限覆盖业务空闲窗口，避免多个 300 秒计时器竞争或长请求被提前回收。
- 按 Chat Completions、Messages、Responses 的真实输出方式验证下游保活；Messages 继续使用协议 ping，Chat 与 Responses 以真实客户端和反向代理验收为准。
- **BREAKING**：旧的厂商级和模式级 `*_STREAM_IDLE_TIMEOUT_MS` 环境变量不再控制正式模型调用的流式空闲门限；部署时必须清理并记录弃用提示。
- 不加入自动换模型、自动重放、断点续写、Agent 任务恢复、管理后台配置页或新的监控平台。

## Capabilities

### New Capabilities

- `stream-idle-resilience`: 规定正式流式调用的统一空闲门限、活跃数据定义、分层超时、协议错误、下游等待、Attempt 边界和资源清理行为。

## Impact

- 主要代码区域：Gateway 超时策略、上游 Caller、流式响应解析、失败呈现、failover 判定、并发租约装配，以及 Chat/Messages/Responses 协议适配。
- 部署区域：Gateway 环境变量、实际公网反向代理时限和候选镜像；不涉及数据库迁移。
- 外部行为：长流式请求最多允许连续 300 秒无上游数据；空闲超时提示发生变化；旧空闲覆盖变量失效。
- 验证区域：确定性假时钟测试、真实 HTTP 慢流、三协议集成、WorkBuddy 5.5.6 经等效公网链路的 300 秒真实时间验收。
