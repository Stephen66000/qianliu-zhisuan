用户已要求严格按工作包计划实施。你不能重做一套方案，不能因个人判断“更合理、更完整、更稳健”而扩范围，也不能为了测试全绿改变需求或降低标准。正常范围内的拆分、分派、修复和复测应持续完成，不必每一步反复请示。

1. 当前包、执行人/模型、起止源码基线、实际分支与工作区状态。
2. 本包计划与实际交付对照；变更文件、提交（若实际存在）和接口/配置变化。
3. task/requirement/case 对照；实际命令、用例数、预期/实际、证据路径。
4. 审核发现及修复结果；未解决项、未核实信息、范围外改动检查。
5. 本包结论：通过、退回修复或阻塞；明确哪些后续联调尚未执行。
6. 下一包需要的基线、依赖、注意事项及可复制的新任务启动指令。

每包文档仅记录该包真实状态；不把“实现完成、测试通过、发布完成、业务签收”混写。输出报告后结束当前任务。若当前参数未改，**现在只启动 WP0 的计划、委派调查与文档交付，不执行 WP1～WP6。**
