# 验收计划：API费用估算与官方账户余额解耦

版本：v1.1；日期：2026-11-02；状态：计划，所有业务用例待执行。OpenSpec 文档严格校验通过不代表以下业务验收通过。

## 1. 验收范围与职责

依据 [三份规格](../specs/) 的 21 条需求、42 个场景，逐一执行；另列 8 项跨服务/迁移回归。开发子 Agent 提供自动化与自测证据，各包总指挥在相同候选版本独立复核，业务验收人确认页面结果与操作体验。总指挥不能把开发子 Agent 自报通过当作复核；记录实际执行人和模型。各包仅验证负责层，依赖后包的场景留待联调，WP5 汇总全部 50 条结果，WP6 对实际发布候选补充正式切换/回退演练。

规范正文为需求来源，本文将其展开为可操作用例。任何步骤与规范冲突，先修正文档，不允许只改测试预期迁就实现。

## 2. 开测条件

1. 记录源码 SHA、各服务构建版本、迁移水位、浏览器、企业时区和实际配置；接口合同及同步参数已有明确版本。
2. 使用隔离数据库、测试账号、注入的余额响应/模拟上游及可控时钟。不得把等待月底、真实充值或真实付费推理当成场景前提。
3. 安装实际测试依赖；集成测试可启动 PostgreSQL 容器。Web E2E 使用专用 `_e2e` 库，其 globalSetup 会清理和播种，不得连接共享/生产数据。
4. 各工作包已有对应测试及文档，页面连接真实测试 API。仅以截图、mock 页面或 0 tests 的命令不能完成端到端验收。
5. 保存迁移前的旧关账快照、用量/规则和资金事实摘要，明确新建/变更数据白名单；新环境及旧库升级都要测。

## 3. 固定测试夹具

以下均为合成数据和测试单价，不表示 DeepSeek 当前官方价格或真实账户余额。每组独立或通过 fixture ID 分隔，避免不同用例互相污染。

| 夹具 | 准备内容 | 核对基准 |
|---|---|---|
| F01 基础 API | API-A；无期初/充值/资金账户；授权与凭证有效；输入 1000（含缓存 400）、输出 200；未命中/命中/输出为 1/0.1/2 元每百万；价格来源标为已核实测试来源 | 真实 Token 1200；估算 0.00104000 元；缓存不重复计数 |
| F02 费用质量 | 独立期间三条消费：已计价 1 元、2 元及有用量缺价格；另备未访上游拒绝、用量未知、历史未迁移、价格依据未核实记录 | 已知部分 3 元且不完整；明确未访问可为零，其他未知不补零 |
| F03 重试/处置 | 同一请求失败 Attempt 0.01 元＋成功 Attempt 0.02 元；可重复提交同一终态；另备现有合法历史费用排除记录 | 0.03 元且不重复；原处置仍有效并可追溯 |
| F04 官方余额 | 注入总额 110、赠送 10、充值 100、币种 CNY、available=true；另备刷新后总额 160、429、401、超时 | 官方总额 110 而非 220；刷新用 160；错误不生成金额 |
| F05 来源/时效 | 官方成功 50 元在 T0；其后较新的 ADMIN 手工 999；T1 查询超时；另备从未成功资源；固定时钟可推进过期阈值 | 当前官方值仍为 50、时间为 T0；手工 999 不覆盖；失败和过期可同时显示 |
| F06 不支持 | 尚未实现官方余额适配的测试厂商 API；可信用量和计价记录齐全 | 余额暂不支持；用量和估算有效 |
| F07 多 Key | 两个已证明同账户资源各查得 100；另一组两个 Key 也查得 100 但不能证明账户关系 | 不出现 200 的账户总额，不按金额自动识别账户 |
| F08 历史 | 已关账版本 V1：期初 100＋充值 50－期末 120＝旧费用 30；另备可信历史请求估算 10.15；以及仅有余额桥接、无请求计价的月份 | V1 仍为 30 且旧口径；有依据的新读取可为 10.15；无依据不把 30 填成新估算 |
| F09 套餐 | 同企业 Coding Plan：固定费用 100 元、周期有效、额度 1000、扣减 400；分别准备自动续订关/开状态；API 无期初 | 套餐费用/额度及开关不变；用模拟时间与本地事件验证续订，不触发真实购买 |
| F10 员工/其他控制 | 员工 API 月额度 1000、已用 900，测试请求预计 200；allow_overage 分别关/开；另备独立 Key/项目限制及套餐耗尽窗口 | 禁止超额拒绝；允许超额记录实际消费；其他门禁分别仍有效 |
| F11 月界/价格/币种 | 企业 Asia/Shanghai；11 月 30 日 23:59 开始、12 月 1 日 00:02 结算；价格 A/B 有明确生效点；另备 API 10 CNY＋2 USD、套餐 100 CNY | 费用按原结算口径归月、员工额度按预占月；旧价格不变；人民币部分 110，美元 2 分列 |
| F12 资源状态 | 资源仅资金 PENDING、无状态记录、凭证无效、人工停用及真实 EXHAUSTED 分别独立；保留隔离前旧正余额和隔离后新正余额 | 仅资金条件不阻断；其他隔离不误解除；更新证据才可走原恢复流程 |

金额核对使用十进制及既有账本精度，F01 存储/接口按既有 8 位金额格式核对；UI 可按显示精度格式化，但小额非零估算应能从详情查明，不能仅凭四舍五入显示判断计算结果。

## 4. 执行层次与证据

| 层次 | 执行内容 | 最低证据 |
|---|---|---|
| 单元 | 分项计价、价格版本、状态/过期、按币种汇总 | 实际测试文件/用例名、非零用例数、断言日志 |
| 数据库/HTTP 集成 | 新旧库、资金退役、账户缺失、权限、同步/恢复、消费归集 | 迁移水位、脱敏响应、查询断言、失败前后事实对比 |
| 浏览器联调 | 资源、用量、账单、套餐、历史及 CSV | 同版本 API、截图、操作记录、导出文件；不能只有静态 mock |
| 跨服务演练 | Gateway→结算→Control API→Web、Worker 同步、月界及回退 | 各服务版本、模拟上游计数、状态变化与金额核对表 |
| 业务复核 | 读懂估算与官方余额，能无期初使用，能管理套餐 | 实际验收人、日期、结果及未决项 |

证据建议放在实施方的 `V4/Evidence/API-COST-OFFICIAL-BALANCE/<run-id>/`，目录由其创建；本轮未生成业务证据。每条结果包含：case ID、源码/镜像版本、fixture、命令或步骤、预期、实际、状态、证据路径、执行人与日期。

状态限定为 PASS / FAIL / BLOCKED / NOT_RUN；缺环境为 BLOCKED，没执行为 NOT_RUN，不能记 PASS。旧用例因新合同调整时记录原因及新替代用例，不能无说明删除。

## 7. 人工业务验收路线

1. 在测试环境创建或打开无资金期初的 API 资源，确认不要求初始化。通过模拟上游发起 F01 消费，在请求明细核对 1200 Token 和 0.00104 元估算。
2. 用同一期间核对资源、首页和账单，确认无 API 期初、充值、内部月末余额或待补账提示；点开依据能查到当时价格与费用完整性。
3. 查看官方余额 110 元及成功时间，切换模拟余额为 160 后刷新。随后制造超时并推进时钟，确认保留 160、原时间和失败/过期说明，不变成零。
4. 查看不支持同步的 API 资源，确认仍能统计费用；查看两个关联 Key，不出现重复余额合计。
5. 打开套餐与订阅，确认采购、周期、费用和原自动续订开关；员工额度禁止/允许超额分别演示，不能因官方有余额而绕过控制。
6. 打开 F08 已关账历史及只读旧资金，确认金额/来源不变；导出当前 CSV，确认新旧口径没有混淆。

## 8. 通过标准与交付结论

- 42 个规格场景和 8 个集成回归均 PASS；每条有可追溯证据，不接受 NOT_RUN/BLOCKED 冒充通过。
- 改动包 typecheck/lint/build 与相关测试通过，测试发现数大于零；CI 对本改动要求的其他检查有明确结果。基线遗留问题单独记录，若影响本功能或发布则仍阻断，不靠降阈值消除。
