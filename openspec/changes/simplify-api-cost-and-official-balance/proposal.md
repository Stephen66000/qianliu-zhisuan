# Proposal: API费用估算与官方账户余额解耦

## Why

API 余额目前关联期初、充值、对账、资金初始化和部分调用准入，管理员为一个参考数字承担了月初维护成本。用户于 2026-11-02 确认：取消 API 内部余额管理，以真实用量计算“API费用估算”，保留官方账户同步余额。

## What Changes

- 统一名称为 **API费用估算**：按经由仟流的 API 输入、输出、缓存等用量及当次有效的官方价格规则计价，不表示厂商实际扣款或现金支出。
- **BREAKING**：退出 API 期初、充值登记、余额调整、余额对账、月末结转和资金就绪要求；API 新建与正常调用不再要求内部资金账本初始化。
- 官方余额单独展示为 **官方账户余额**，附币种、最近同步时间、同步状态和手动刷新；不支持的厂商明确显示暂不支持，不允许人工金额或内部推算冒充官方数据。
- 费用估算、官方余额、员工月度额度、Coding Plan 套餐额度各自独立；保留现有鉴权、授权、额度、Key 限制及上游明确余额不足后的隔离和恢复。
- “充值与订阅”调整为“套餐与订阅”，仅管理 Coding Plan 的采购、续订、订阅周期和相关费用；API 旧资金事实只读留档。
- 首页、资源、用量、经营账单、部门/项目、年度统计、导出及含 API 金额的报表采用同源费用估算；API 估算与套餐费用合计须注明“含 API 估算”。
- 保留历史用量、计价快照、费用质量状态、历史处置证据和已关账版本；历史余额桥接金额不直接改名为按 Token 计价的估算费用。

## Capabilities

### New Capabilities

- `api-cost-estimation`: API 分项用量计价、完整性、聚合、名称与历史价格追溯。
- `official-account-balance`: 官方余额采集、来源、刷新、时效、账户范围和已有恢复逻辑。
- `api-funding-retirement`: API 内部资金管理退出、调用准入解耦、套餐保留及历史兼容。

### Modified Capabilities

无。2026-11-02 本地 `openspec list --specs --json` 返回空列表，已有方案位于在途 changes，不能当作主规格使用 MODIFIED/REMOVED delta。本次新增行为合同，并在 design 中明确对旧在途需求的替代关系，不改写旧 change。

## Impact

- Gateway/Database：复用现有计价、规则快照和 Attempt 结算；移除 API 资金 PENDING 准入与费用读取对资金初始化的依赖，检查数据库触发器和共享质量门禁。
- Control API：费用和官方余额分开响应；停用 API 资金写入口，保留历史查询及 Coding Plan 写路径；新增受权限控制的官方余额刷新能力。
- Worker/Adapters：复用 DeepSeek 余额查询，解除日同步和资金模式耦合；不扩展新厂商适配器，不新增模型调用或自动充值。
- Web/报表：调整上述页面、栏目、状态、CSV 和已有 API 金额展示；纯 Token 图表及已授权的员工额度改动不受本方案替代。
- 数据：采用新增兼容迁移，旧资金表和已关账快照保留；实施时再确认迁移编号、生产版本和实际开关。
- 本地研究基线 HEAD：`2a2fdbe3c52b6853d12be476a6162221fc8163fe`，工作区已有其他未提交改动；未核验生产当前全套版本。证据和冲突清单见 [design.md](design.md)。
- 后续基线更新（2026-11-02）：已核实 [PR #7](https://github.com/Stephen66000/qianliu-zhisuan/pull/7) 合并及远端 main `ae506fed47d21865420afa91137e8b244072933e`。旧研究 SHA 不再作为默认开发起点；生产部署/0092 迁移未执行状态与源码合并分开，见[基线更新](handoff/baseline-update-20261102.md)。
