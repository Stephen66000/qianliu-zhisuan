## Purpose

为管理员提供可追溯到官方账户的余额参考，明确币种、来源、更新时间、可用状态和失败情况；让余额同步独立于内部资金账本运行，同时避免把账户级金额重复计算、把旧数据称为实时余额或用本地费用反推官方余额。

## ADDED Requirements

### Requirement: OAB-01 官方余额只接受官方来源

系统 SHALL 将官方查询返回的余额显示为“官方账户余额”，同时展示币种、最近成功同步时间和同步状态。系统 MUST NOT 把人工余额、内部账本余额或从 Token 推算的金额显示为官方余额，MUST NOT 以页面刚打开或刷新成功的时间代替余额成功采集时间。

#### Scenario: DeepSeek 官方查询成功
- **WHEN** 官方接口返回总可用余额 110 元、赠送余额 10 元及充值余额 100 元
- **THEN** 页面显示官方账户余额 110 元，可查看两项组成，不把三个金额再次相加

#### Scenario: 本地还有历史手工余额
- **WHEN** 历史经营快照为人工录入，且从未成功同步官方余额
- **THEN** 当前官方余额显示暂无官方数据，历史手工金额只在旧资料中保留原来源

### Requirement: OAB-02 支持能力按实际适配器声明

系统 SHALL 仅对已实现且验证的厂商官方查询能力显示同步支持。本期 SHALL 复用已接入的 DeepSeek API；其他厂商或接入模式未实现时显示“暂不支持”，不以零值、无限余额或要求人工补账替代。

#### Scenario: 余额查询尚未适配
- **WHEN** 用户查看未实现余额适配的厂商 API 资源
- **THEN** 显示暂不支持官方余额同步，Token 和费用估算仍正常统计

### Requirement: OAB-03 定期与手动刷新独立运行

系统 SHALL 支持可配置周期的后台同步和受现有资源管理权限约束的手动刷新，不要求内部资金账本启用、API 充值记录或月初初始化。重复手动请求 SHALL 复用在途刷新或返回明确冷却状态，不无限触发官方查询。

#### Scenario: 内部资金模块停用
- **WHEN** API 资金管理已退出，后台同步时点到达且官方查询能力可用
- **THEN** 系统仍执行余额查询并保存采集结果，不因旧资金开关关闭而跳过

#### Scenario: 在厂商后台充值后手动刷新
- **WHEN** 管理员在官方后台充值后点击刷新余额
- **THEN** 系统查询官方最新值，不要求先在仟流登记充值

#### Scenario: 无刷新权限
- **WHEN** 仅有资源查看权限的用户尝试手动刷新
- **THEN** 可按原权限查看余额，服务端拒绝刷新操作，凭证不下发浏览器

### Requirement: OAB-04 失败和时效状态不掩盖旧值

系统 SHALL 区分从未同步、同步中、成功、失败、已过期及暂不支持；过期按可配置阈值判定。失败时 SHALL 保留上次成功值和成功时间，同时显示本次失败，不把失败或超时转换为零，也不将旧值标为实时。

#### Scenario: 曾成功后遇到超时
- **WHEN** 上次成功余额为 50 元，本次查询超时
- **THEN** 展示上次同步 50 元及原时间，标记本次同步失败；超过时效阈值时同时标记数据过期

#### Scenario: 首次查询失败
- **WHEN** 没有历史成功值且本次鉴权失败
- **THEN** 显示暂无余额和失败原因，不显示 0 元，也不据此判定聊天调用一定鉴权失败

### Requirement: OAB-05 官方账户与资源的范围明确

系统 SHALL 将官方余额解释为对应账户的余额而非每个 Key 或模型专属金额。同一账户在多个资源或模型重复展示时 MUST NOT 重复累加；无法确认账户对应关系时 SHALL 仅展示资源关联的查询结果，不输出声称已去重的账户余额合计。

#### Scenario: 同账户关联多个 Key
- **WHEN** 两个资源已确认属于同一官方账户，均返回 100 元
- **THEN** 可分别展示同一账户参考余额，但账户合计不得显示为 200 元

#### Scenario: 无法证明账户关系
- **WHEN** 两个 Key 返回相同余额但官方未提供足以确认账户关系的信息
- **THEN** 不凭相同金额自动识别账户，也不直接合计；无需新增账户管理流程即可查看各自查询结果

### Requirement: OAB-06 余额参考不代替调用控制

系统 MUST NOT 因余额同步失败、未知、过期或本地估算接近余额而新增调用拒绝或自动换厂商。系统 SHALL 保留上游明确余额不足后的既有隔离，并仅以隔离后新取得的官方可用证据执行既有恢复流程，恢复不等于已证明模型调用成功。

#### Scenario: 同步失败而 API 调用正常
- **WHEN** 余额查询失败，但资源原本可用且其他准入条件满足
- **THEN** 调用不因余额查询失败被阻断

#### Scenario: 真实耗尽后充值恢复
- **WHEN** 资源因上游明确余额不足而隔离，之后取得更新的官方正余额且可用标记为真
- **THEN** 可按现有流程解除耗尽隔离并等待真实调用确认；旧快照不能解除新的隔离

### Requirement: OAB-07 既有余额预测保持参考属性

系统 SHALL 使现有 API 余额告警与耗尽预测仅使用来源合格且时效有效的官方数据；缺少余额或可比较消费速率时显示不可计算或数据待更新。预测 SHALL 标明估算，MUST NOT 根据余额差额造费用或直接形成新的硬性调用门槛。

#### Scenario: 存在平台外消费
- **WHEN** 官方账户同时有仟流以外的消费，而现有预测仅掌握仟流消费速率
- **THEN** 预测说明仅按已观察速率估算，不承诺账户实际可用时长

#### Scenario: 余额已过期
- **WHEN** 现有预测使用的余额超过时效阈值
- **THEN** 不展示无时效说明的确定耗尽时间，显示数据待更新或不可计算
