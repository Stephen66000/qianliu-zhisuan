## Purpose

让管理员按仟流实际记录的 API 用量理解人员、项目、模型和厂商的费用估算，并追溯当时的价格与数据完整性，使估算结果不再依赖厂商钱包余额、充值流水或内部资金初始化，也不会被误认为官方实际扣款。

## ADDED Requirements

### Requirement: ACE-01 统一费用名称及范围

系统 SHALL 将新口径的 API 用量计价金额显示为“API费用估算”，说明仅覆盖经由仟流记录的 API 消费。系统 MUST NOT 将其描述为厂商实际扣款、实际支付或由账户余额变化计算的实际支出。

#### Scenario: 资源和用量页面显示相同含义
- **WHEN** 管理员查看同一期间、同一资源的用量总览、请求详情和费用明细
- **THEN** API 金额均标注为“API费用估算”，说明可查看且不宣称包含平台外调用

### Requirement: ACE-02 按分项用量和当时官方价格计价

系统 SHALL 区分输入、输出、缓存命中及厂商适用的其他计费项，按对应模型、币种、生效时间和分项单位计算估算费用，保留请求当时的价格证据。缓存属于输入子集时 MUST NOT 重复计数，系统 MUST NOT 用总 Token 统一乘一个价格代替分项计价。

#### Scenario: 输入包含缓存命中
- **WHEN** 一次 API 调用输入 1000 Token（含缓存命中 400）、输出 200，三类价格分别为 1、0.1、2 元/百万 Token，且无其他收费项
- **THEN** 费用为 `(600×1 + 400×0.1 + 200×2)/1000000 = 0.00104` 元，真实输入加输出仍为 1200 Token

#### Scenario: 价格发生调整
- **WHEN** 模型价格从版本 A 调整为版本 B
- **THEN** 新调用按生效时点选择价格，旧调用保留版本 A 的估算结果，不因刷新页面而重算

#### Scenario: 配置价格缺少官方来源
- **WHEN** 管理员查看或维护 API 价格规则，但其官方来源或适用模型尚未核实
- **THEN** 系统明确显示价格依据待核实，不将已有自定义价格宣称为已核实官方价格

### Requirement: ACE-03 估算费用不依赖余额和资金初始化

系统 SHALL 在有可计价用量和价格依据时产生费用估算，不要求 API 期初、充值、内部余额、官方余额或企业资金激活状态。官方余额的变化 MUST NOT 反向改变费用估算。

#### Scenario: 没有任何余额数据
- **WHEN** API 已产生可信用量和价格记录，但未登记期初且官方余额暂不支持同步
- **THEN** 费用估算正常产生，并且不提示补期初或充值记录

#### Scenario: 官方余额因平台外消费下降
- **WHEN** 官方账户余额下降，但仟流没有新增 API 用量
- **THEN** 仟流费用估算不增加，系统不以余额差补造用量或费用

### Requirement: ACE-04 保留未知与已知部分

系统 SHALL 区分已计价、明确零费用、用量未知、价格缺失、价格依据待核及历史未迁移等适用状态。汇总 SHALL 提供可确认的金额部分和完整性说明，MUST NOT 将缺失数据自动视为零，也不因余额缺失而抹去已知估算费用。

#### Scenario: 部分请求缺少价格
- **WHEN** 本月两条已计价记录分别为 1 元和 2 元，另一条有用量但价格缺失
- **THEN** 展示已计价部分 3 元并说明存在待计价请求，不把 3 元称为完整总费用

#### Scenario: 已明确没有访问上游
- **WHEN** 请求被本地拒绝且能够确认没有上游消费
- **THEN** 可显示明确零费用，不制造未知消费或推算余额

### Requirement: ACE-05 按消费事实而非成功次数汇总

系统 SHALL 计入所有具有可信消费和计价依据的 API Attempt，包括有消费的失败及重试；对同一 Attempt 的重复结算只计一次。系统 SHALL 保留现有有效的历史费用处置，不因字段名称含 finance 而一并删除。

#### Scenario: 请求重试且两次均有消费
- **WHEN** 首次 Attempt 失败但计价 0.01 元，第二次成功并计价 0.02 元
- **THEN** 请求费用估算合计为 0.03 元，成功请求次数仍按请求统计口径计算

#### Scenario: 历史取消记录已有可追溯处置
- **WHEN** 一条无已记录费用的取消请求已通过现有可追溯规则排除费用缺口
- **THEN** 新费用读取保留该处置及说明，不重新引入误报，也不删除原始记录

### Requirement: ACE-06 全部消费视图采用同源费用

系统 SHALL 在首页、厂商资源、用量、经营账单、部门、项目、年度统计及含 API 金额的通知和导出中，采用相同范围、期间、计价事实及完整性语义。期间 SHALL 沿用企业时区与现有消费时间口径，不因本次调整改变员工额度归属月份。

#### Scenario: 资源明细和月度汇总核对
- **WHEN** 用户按相同期间和资源范围核对请求明细、首页和经营账单
- **THEN** API费用估算可由同一批消费事实核对，差异明确归因于筛选范围或完整性而非不同余额算法

#### Scenario: 跨月完成的请求
- **WHEN** 一个 Attempt 跨月完成
- **THEN** 费用继续按既有消费结算时间口径归集，员工额度仍按既有预占月份合同执行，不要求两者强行相同

### Requirement: ACE-07 币种与套餐合计可解释

系统 SHALL 按币种分别汇总 API费用估算；与 Coding Plan 套餐费用合计时，仅合并币种及统计口径可比较的金额，并标注“综合费用（含 API 估算）”及组成口径。系统 MUST NOT 直接将不同币种相加，也不将合计称为实际现金支出。

#### Scenario: 人民币 API 与套餐费用合计
- **WHEN** 同期 API费用估算为 10 元、既定口径的套餐费用为 100 元
- **THEN** 可显示综合费用 110 元，标明含 API 估算及套餐费用口径

#### Scenario: 同时存在美元和人民币
- **WHEN** API费用估算有 2 美元和 10 元，套餐费用为 100 元
- **THEN** 显示 2 美元及人民币部分，不生成无汇率依据的单一总金额
