## Purpose

让 API 接入摆脱内部资金账户的建账、月初维护和余额对账要求，同时保留用量与计价证据、厂商真实故障处理、员工和项目使用控制及 Coding Plan 套餐管理，保证新流程与已有历史记录之间有明确、可核对的切换边界。

## ADDED Requirements

### Requirement: AFR-01 API 内部资金操作退出日常流程

系统 SHALL 从 API 日常管理中移除期初余额、充值登记、期初更正、余额调整、余额对账、月末结转及相关初始化要求。旧 API 资金写入口 SHALL 返回明确停用结果并且不写入，不允许隐藏前端后继续通过旧入口或初始化草稿新增这些事实。

#### Scenario: 打开 API 资源
- **WHEN** 管理员打开 API 资源及其可用操作
- **THEN** 可管理接入、查看用量、费用估算及官方余额，不出现资金初始化或余额维护表单

#### Scenario: 客户端继续调用旧充值接口
- **WHEN** 已认证且有原写权限的客户端调用旧 API 充值、对账或期初写入口
- **THEN** 返回明确功能停用结果，资金事实、候选和费用估算均不发生变化

#### Scenario: 旧混合初始化草稿包含 API 资金事实
- **WHEN** 客户端提交包含 API 期初或充值事实的旧初始化候选
- **THEN** 系统拒绝过时的 API 资金部分并说明原因，不静默忽略后激活混合候选；Coding Plan 可以通过新合同独立初始化

### Requirement: AFR-02 API 接入不再要求资金就绪

系统 SHALL 在其他准入条件满足时允许没有 API 资金期初、激活状态或资金就绪标记的资源进入调用候选。取消该前置条件 MUST NOT 自动启用已停用资源、恢复无效凭证、解除真实耗尽、改配路由或放宽其他额度门槛。

#### Scenario: 新增没有资金期初的 API 资源
- **WHEN** 资源配置、凭证、模型和授权均满足既有准入条件，但从未建立内部资金账户
- **THEN** 不因缺期初或资金未就绪而被排除，可以产生正常用量及费用估算

#### Scenario: 存量资源资金标记未就绪
- **WHEN** 存量 API 资源只有资金未就绪问题，其他准入条件全部满足
- **THEN** 切换后忽略旧资金前置条件，不要求管理员补录虚构的零期初

#### Scenario: 同时存在真实凭证错误
- **WHEN** API 资源同时具有旧资金未就绪标记和有效的凭证无效隔离
- **THEN** 解除资金依赖不解除凭证隔离，仍遵守原恢复流程

### Requirement: AFR-03 月初无需 API 余额维护

系统 SHALL 按新月份自动聚合 API 用量与费用估算，不要求补本月期初、结转上月余额或确认充值。员工月度额度初始化、Coding Plan 周期重置 SHALL 继续按各自既有合同运行。

#### Scenario: 跨入新月
- **WHEN** 企业时区进入下月第一天且尚无人访问资金页面
- **THEN** API 新月用量和费用正常统计，官方余额保留最近同步属性，员工和套餐额度照原规则运行

### Requirement: AFR-04 套餐管理保持独立完整

系统 SHALL 将日常“充值与订阅”调整为“套餐与订阅”，保留 Coding Plan 购买、续订、有效期、固定费用、实付、适用额度和既有自动续订开关。套餐初始化及续订 MUST NOT 因 API 余额缺失而阻断，也不因本次变更改变既有自动续订配置。

#### Scenario: API 无期初但套餐正常续订
- **WHEN** 同一企业没有任何 API 资金期初，已有 Coding Plan 满足原续订条件
- **THEN** 套餐按现有授权与开关工作，不要求补 API 资金记录，也不自动开关续订

### Requirement: AFR-05 使用控制与财务参考分开

系统 SHALL 保留员工按月按厂商额度、允许超额策略、项目与 Key 限制、Coding Plan 额度窗口、真实 Token 及套餐扣减语义。系统 MUST NOT 把 API 余额管理退出解释为不限用量、取消额度记录或以官方账户余额替代内部使用额度。

#### Scenario: 员工额度禁止超额
- **WHEN** API 员工额度不足且禁止超额，即使官方账户余额充足
- **THEN** 仍按原额度合同拒绝，并保留准确原因；不以账户有钱为由放行

#### Scenario: 允许超额的授权
- **WHEN** 一条 API 员工授权已允许超额
- **THEN** 其配置保持不变，真实用量和超额继续计量，不因取消余额维护而清零

### Requirement: AFR-06 历史事实和关账版本不改写

系统 SHALL 保留原始用量、规则快照、API 旧资金事件、历史费用处置及已关账版本，并标明原来源和原口径。新口径不得通过余额差额重建 Token 估算，也不得将旧余额桥接金额直接改名冒充新估算；历史重算或重开账期不属于本次切换。

#### Scenario: 阅读已关账的旧月份
- **WHEN** 用户打开旧版本已关账账单
- **THEN** 原版本金额和口径不变，可明确识别为历史记录，不套用当前官方余额或最新价格

#### Scenario: 旧月份只有余额桥接金额
- **WHEN** 历史月存在余额差计算金额，但缺少可追溯的请求计价依据
- **THEN** 保留原历史金额及其标签，不填入“API费用估算”作为已确认值

### Requirement: AFR-07 切换后现行视图退出余额缺口

系统 SHALL 在新口径的首页、资源、用量、经营账单和导出中移除 API 期初、充值、月末内部余额及其待补提示；仍展示真实存在的用量或价格缺口。历史资金信息 SHALL 通过带有旧口径标识的只读入口查看，不参与当前费用完整性判断。

#### Scenario: 缺期初但费用已计价
- **WHEN** 当月费用全部可计价而历史 API 从未登记期初
- **THEN** 当前页面不显示“待补期初”“内部负余额”或资金账户未激活，不据此隐藏费用估算

#### Scenario: 套餐和 API 同页
- **WHEN** 页面同时展示 API 与 Coding Plan
- **THEN** API 不再显示内部资金栏目，Coding Plan 仍保留套餐费用和额度信息；不存在一刀切隐藏所有“余额”或“额度”的处理
