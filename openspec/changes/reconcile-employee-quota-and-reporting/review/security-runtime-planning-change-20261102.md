# Planning Change：上线前安全依赖与项目局部运行时

日期：2026-11-02。授权：用户明确选择“纳入本次，修依赖并用局部 Node 22.x 重验（推荐）”。这追加授权不包含生产部署、迁移、改账、重发或切换系统默认 Node。

## 触发与选定版本

原 `pnpm audit --prod --audit-level moderate` 报告 67 条公告，现有 Undici 8 及补丁要求的 Node 最低版本高于工程规范的 22.17.x。保留未修复的安全门禁为失败，不能通过新增 ignore 或隐去依赖使之通过。

官方 latest-v22.x 只读 SHA 清单和实际下载确认 Node **22.23.4**。Darwin arm64 官方包 SHA-256 为 `037650d0839f457747396f052073fb48333d31bf5abd3c98b74da20d89ebb1ad`；下载校验与 Docker linux/amd64 平台 digest 见本次 security/ 证据。新运行时位于项目 `.local-runtime/`，不进入 Git、不修改系统默认 Node。项目 `.node-version`、engines、CI、四服务 Dockerfile 和工程 runtime 合同统一到 22.23.4；这是候选配置，不是生产变更。

## 范围与验收

应用直接依赖更新为同主版本 Fastify 5.12.6、Undici 7.30.1、Zod 4.6.6。传递补丁按主版本与父依赖限定；ExcelJS 和旧 glob 的可调用 API 不能被全局跨主版本替换。当前限定 matcher 组合仍是待验证候选，失败则修正组合，不能削弱兼容断言或审计。

所有旧 runner 已在安装前自然结束。旧锁文件下的通过结果保持原始记录，仅作基线。安装后重新审计与许可证检查，重新运行原全包测试、覆盖率/ratchet、变异处置、浏览器、官方 CLI 本地协议端到端和 Linux 候选容器检查；最终证据绑定新锁文件、运行时和源码。

原月界循环等价证明限定 Node 22.17.1/ICU77.1/tz2025b，新局部运行时为 Node22.23.4/ICU78.3/tz2026e。因此原证明绑定主动失效，需在新本地与 Linux 容器运行时重新核验后才能更新；不能凭旧生产运行时记录让新候选门禁通过。

这次安全修复不改变月度额度规格、原始 Token、费率、历史账本、允许超额策略或发布授权边界。实际生产月界、自动报表及接收确认仍需上线后证据。
