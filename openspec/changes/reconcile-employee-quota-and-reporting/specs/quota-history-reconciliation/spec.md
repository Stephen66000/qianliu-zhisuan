# Spec Delta

## Purpose

为额度及报表修复建立可审阅的历史核账和上线衔接合同，在新每月规则生效时保存旧账，明确可以证明与尚不能证明的余额，避免因修复图片而改写既有财务事实、已发送消息或员工授权策略。

## ADDED Requirements

### Requirement: 历史核账区分已证事实与待核事实

系统 SHALL 在历史核账清单分别列出真实 Token、套餐扣减、API 金额、员工授权及超额策略、已用周期、已证归属和缺失事实。无法重建的期初/期末余额 MUST 保持待核，不能根据现有授权或截图推造历史分配与准确余额。

#### Scenario: 十月已有生产证据
- **WHEN** 使用已核实的十月报告证据
- **THEN** 保留 22607 次、2709467730 Token、388884913 套餐扣减、DeepSeek API 2020667201 Token，并标记 22 亿不是已证明的十月新增月额度

#### Scenario: 允许超额的生产事实
- **WHEN** 现有 12 条员工授权均允许超额
- **THEN** 核账报告明确此策略，不能把曹磊超过 1 亿分配本身判为禁止超额策略失效

### Requirement: 新月度规则从明确生效月份开始

系统 SHALL 将首次正式月度周期设为生产激活后的首个完整企业自然月，提前部署并记录生效时点；此前保留旧计数器为历史事实，不在月中清零已用。追溯启用当前月必须是另一份有证据和影响清单的变更，不能随本方案自动执行。

#### Scenario: 十一月发布
- **WHEN** 新月度实现于 2026 年 11 月获授权并完成上线
- **THEN** 默认从 2026 年 12 月 1 日 00:00 企业时区启用，新规则不清空 11 月计数器或伪称 10 月已按月重置

#### Scenario: 错过原定激活月界
- **WHEN** 拟定激活月份已经开始而切换条件仍未满足
- **THEN** 不通过把已用清零来补切换；重新选择下一个完整自然月，或另行审阅当前月重建方案

### Requirement: 新额度消费及配置变更保留历史归属

系统 SHALL 为每条新额度消费保留企业、员工、厂商池、授权版本、月份、额度基础和原消费事实关联；额度设置、追加、停用、启用及允许超额变更 SHALL 保留前后事实。无法证明的历史授权归属不得按今天的授权强行填入。

#### Scenario: 消费后管理员修改额度
- **WHEN** 消费已结算而管理员修改当月上限或允许超额策略
- **THEN** 原消费的月份、额度基础和授权版本保持不变，变更有独立前后记录

#### Scenario: 历史请求跨授权版本
- **WHEN** 旧请求无法唯一确认其消费时授权版本或计量基础
- **THEN** 只进入待核清单，不自动绑定到当前授权或改写已用

### Requirement: 历史修复先预览后按确定清单执行

系统 SHALL 先生成不写生产的核账预览，明确来源范围、可修复行、待核行、差额及影响；只有单独授权后才执行冻结清单。重复执行同一清单不得重复加量，事实范围变化时必须重新预览，不能使用旧差额盲加。

#### Scenario: 本次只生成方案
- **WHEN** 用户要求使用 OpenSpec 形成具体方案
- **THEN** 只生成提案、规格、设计、任务与核验材料，不执行迁移、额度补扣、代码部署或消息重发

#### Scenario: 同一修复清单再次执行
- **WHEN** 已授权且已成功执行的同一清单被重复提交
- **THEN** 已处理事实不会再次增加额度已用；待核项仍留待核

### Requirement: 原始用量和财务账本不被额度修复改写

系统 SHALL 保留原始输入/输出、套餐规则快照、API 金额和已结账财务结果，内部额度更正作为可追溯补充事实。禁止为让额度图表相等而改真实 Token、填套餐扣减、重算历史价格或改变已归档账期。

#### Scenario: API 内部额度补记
- **WHEN** 一条已授权修复的历史 API 用量补记内部额度
- **THEN** 原 API 套餐扣减仍为空、原费用不变，不产生第二次 API 收费或厂商充值动作

#### Scenario: 已结账账期
- **WHEN** 核账范围包含已结账财务账期
- **THEN** 内部额度补充不解封或重写该财务账期；若需要财务变更，另走既有流程

### Requirement: 分阶段发布保持明确兼容边界

系统 SHALL 先发布可独立验证的报表修正，再在独立上线步骤中发布每月额度与 API 计量；后者必须核对数据库、Gateway、Control API 和 Worker 的一致版本。旧“仅发布 Worker”授权不能被扩大为本次完整生产切换授权。

#### Scenario: A 段报表先上线
- **WHEN** A 段内容修正获得发布授权而 B 段未上线
- **THEN** 报告明确旧额度待核，实际用量及时间范围正确，不宣称 API 额度和每月重置已经生效

#### Scenario: B 段回滚
- **WHEN** B 段上线后需要回滚
- **THEN** 保留新月及历史事实，并在受影响流量得到保护后回滚兼容组件；不直接把不认识月度账的旧 Gateway 放回生产接流量

### Requirement: 验收分工程受控与真实自动业务三个层次

系统 SHALL 分别记录规格校验、代码/数据库测试、受控送达和真实月界/自然报表验收。固定时钟证明算法不证明生产自动重置或送达；缺少实际接收确认或真实窗口时，业务状态必须保留待验收。

#### Scenario: OpenSpec 严格校验通过
- **WHEN** proposal、specs、design、tasks 通过严格校验
- **THEN** 仅标记方案结构及合同校验通过，实施任务仍未勾选，不宣布代码或生产修复完成

#### Scenario: 真正跨过月界
- **WHEN** 发布后首个约定月界到达
- **THEN** 核对旧月留存、新月额度继承、新月已用/预占、真实请求归属和超额策略；后续月报再核对自然任务、回执与人工确认

#### Scenario: 部分业务证据缺失
- **WHEN** 仅有受控发送回执或缺少个人实际收到确认
- **THEN** 对应业务项保留待验收，不以测试或其他报表成功替代
