# Change Proposal: 资金账本初始化与严格资金写激活

> 状态：`DISCUSSION_DRAFT / IMPLEMENTATION_NOT_AUTHORIZED`
> 对应计划：`V4/资金账本初始化与API期初余额录入开发计划-v1.2-20260921.md`

## Why

当前系统已有资金事件、订阅周期、历史用量回填、守恒检查和严格资金写门禁，但缺少面向管理员的一次性初始化闭环：

1. API 资源没有前端期初余额入口。
2. 切换时点后的历史 API 充值和 Coding Plan 购买可能仍停留在旧购买记录中。
3. Coding Plan 用量可能缺少有效订阅周期归属。
4. 普通充值与订阅写入口只有在严格资金写激活后才开放，因此不能依赖这些接口完成激活前初始化。
5. 当前预检只检查已落库事实，不能对完整草稿做财务事实只读的假设投影。
6. 现有资金写入和用量回填方法各自开启事务，不能直接拼接为一个原子激活事务。

如果只增加一个“期初余额”输入框，系统仍会缺少历史充值、购买、周期、候选防漂移、并发激活和完整审计，无法证明资金与 Token 守恒。

## What Changes

本变更新增企业级资金初始化工作流：

1. 生成包含 API 期初、历史 API 充值、Coding Plan 购买/续费、跨切换周期、旧记录关闭决定和用量修复摘要的完整候选。
2. 对候选执行财务事实只读的假设投影，输出 `GO_CANDIDATE` 或结构化 `NO_GO`。
3. 用稳定候选哈希、完整事实水位、有效期和企业级幂等记录防止预检后漂移。
4. 在一个 `SERIALIZABLE` 事务中写入全部初始化事实、执行允许的四字段历史修复、验证守恒并激活严格写。
5. 为管理员提供初始化向导、缺口定位、候选确认和激活回执。
6. 加固现有期初接口，防止绕过说明、证据和资源级资金启用流程。
7. 提供激活后 Control API 与 Worker 双端停写和恢复运行手册。
8. 提供激活前企业级静默租约：暂停目标企业 Gateway 新请求和自动续订，排空在途结算后再生成候选并激活。

## Scope

### In Scope

- `packages/database`：候选、事实水位、只读投影、事务原语、原子激活和数据库约束。
- `apps/control-api`：activation-state、activation-preview、activate 及权限/错误合同。
- `apps/web`：资金初始化向导、结构化缺口和激活确认。
- 本地隔离企业全链路验收。
- 部署候选与双端停写演练。

### Out of Scope

- 自动抓取支付渠道、银行或厂商敏感凭证。
- 自动猜测金额、币种、订单或服务周期。
- 修改模型计价、路由、凭证或主体授权。
- 自动解决证据不足的未知 API 成本。
- 由 OpenSpec 实施任务自动部署、录入生产金额或激活生产资金账本。

## Compatibility

1. 资金事件继续追加写；既有事实不覆盖、不删除。
2. 日常充值、订阅、更正、冲销和对账接口保持原有语义与严格写门禁。
3. 允许新增非资金事实的候选/激活控制表；候选不得参与余额和经营账单。
4. 激活状态仍不可逆；异常停写通过服务运行模式完成。

## Risks

| 风险 | 约束 |
|---|---|
| 漏迁移历史充值导致余额错误 | 每条旧购买记录必须有唯一关闭结果 |
| 预检后事实变化 | 完整事实水位复验，漂移即冲突 |
| 多事务造成半成功 | 单一外层事务，内部原语接受同一 `trx` |
| 重复激活或候选串用 | 企业级幂等键、候选哈希和不可变结果快照 |
| 历史回填越界 | 只允许四字段，非目标字段哈希必须不变 |
| 激活后无法回退 | 双端 `DARK/OFF` 停写，资金事实走更正/冲销 |
| 持续用量写入导致候选反复漂移 | 企业级静默租约、在途排空和 30 分钟候选 TTL |
| 提交阶段序列化失败 | 整体回滚并返回人工可重试冲突；服务端不自动重跑 |
