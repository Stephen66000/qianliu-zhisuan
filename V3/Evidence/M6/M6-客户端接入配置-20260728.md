# M6 客户端接入配置与协议能力矩阵（2026-07-28）

## 1. 四类客户端统一接入模型

经与 Owner（佳哥）确认：**仟流 IDE 与 WorkBuddy、Claude Code、ZCode 一样是智能体客户端，四类客户端统一通过"配置 Gateway Base URL + 主体 Key"接入**，不做员工账密登录。PRD §12.1 原文"仟流 IDE 员工登录后自动取得凭证"按本澄清不适用于一期——IDE 同样由管理员发放主体 Key，员工填入。

> 数据库预埋的 `employee_login` 表（M1/0001 迁移，注释"员工登录仟流 IDE 用"）本轮不启用，保留供后续版本。

| 客户端 | 协议兼容 | 接入步骤 | 一期验证设备 |
| --- | --- | --- | --- |
| 仟流 IDE | OpenAI / Anthropic 兼容 | 填 Gateway URL + 主体 Key + 选模型别名 | 2 台 Apple Silicon Mac |
| WorkBuddy | OpenAI 兼容 | 手工填 Gateway URL + 员工 Key + 模型 | Win11 |
| Claude Code | Anthropic 兼容 | 配置 Anthropic 兼容 Gateway 地址 + 员工 Key | Win11 |
| ZCode | OpenAI / Anthropic 兼容 | 配置 Gateway 地址 + 员工 Key | Win11 |

四类客户端共用同一把主体 Key（PRD §12.1：同一员工默认共用一把 Key）。Gateway 通过 Bearer Key 识别主体并归因；无法可靠识别客户端类型时标记"未知客户端"，不影响员工归因。

## 2. Gateway 接入参数

- **Base URL**：`http(s)://<gateway-host>:<port>/v1`（默认 `127.0.0.1:8787`，生产由部署配置 `GATEWAY_HOST`/`GATEWAY_PORT`）
- **认证**：`Authorization: Bearer sk-qianliu-<key>`（主体 Key，管理员在后台创建/重置，明文仅一次展示）
- **模型别名**：`qianliu-*`（由 `GET /v1/models` 列出，客户端只看到别名，不接触真实 Provider/模型名）

## 4. 停用／重置即时生效（M6 DoD）

M6 DoD 要求停用/重置 5 秒内生效。架构查证：`principal-auth` 每次请求直接查 `principal_key` 表比对 HMAC digest，**无 Redis 缓存层**（principal-auth.ts 注释"W07 接入 5 秒 TTL"实际未接入）。停用/重置同步写 DB（主体 DISABLED / Key REVOKED），下一次请求即时被拒——**实际 0 秒生效，优于 5 秒要求**。

证明测试：`apps/gateway/src/__tests-integration__/m6-key-revocation.test.ts`（宿主机 Docker 复跑）。
