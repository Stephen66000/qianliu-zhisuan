# M7 部署指南 —— Mac Mini（W24 第一层最小可部署）

> 本指南让 Mac Mini 能 `docker compose up` 跑起仟流智算全栈，同事用 WorkBuddy/ZCode 等客户端连接测试。
> 这是 W24 的"最小可部署层"，**不是** W24/W25 完整 DoD（最小权限/出站白名单/异地备份/RPO-RTO 演练等是第二层，后续做）。

## 0. 前提

- Mac Mini（Apple Silicon，arm64）已装 Docker Desktop 并运行
- 仓库代码已同步到 Mac Mini（`git clone` 或拷贝，含 `deploy/`、`apps/`、`packages/`）
- **真实 Provider 凭证**（DEP-PROVIDER-CREDENTIALS）：DeepSeek/智谱/Kimi 的 API Key 或 Coding Token——没有这个，同事连上来也调不通真实模型（Gateway 会用 StubUpstream 返回模拟响应）

## 1. 配置 .env

```bash
cd 仟流智算/deploy
cp ../.env.example .env
```

编辑 `deploy/.env`，填入真实值（**不要用 PLACEHOLDER**）：

```bash
# 上游凭证（真实 Key）
DEEPSEEK_API_KEY=sk-你的真实DeepSeek密钥
ZHIPU_CODING_TOKEN=你的真实智谱CodingToken
KIMI_CODING_TOKEN=你的真实KimiCodingToken

# 服务端密钥（用下面的命令生成，不要复用占位值）
GATEWAY_KEY_PEPPER=$(openssl rand -base64 32)
SESSION_AFFINITY_HMAC_KEY=$(openssl rand -base64 32)
CREDENTIAL_KEK=$(openssl rand -base64 32)
COOKIE_SECRET=$(openssl rand -base64 32)

# 数据库（容器内用默认值即可，compose 会覆盖 DATABASE_URL 指向 postgres 服务）
POSTGRES_DB=qianliu
POSTGRES_USER=qianliu
POSTGRES_PASSWORD=换一个强密码

# 其余保持默认
```

生成密钥的命令（终端直接跑）：
```bash
openssl rand -base64 32
```

> **Secret 红线**：`.env` 不进 Git（已在 .gitignore）；不要把 `.env` 内容贴到聊天/日志/工单。

## 2. 构建并启动

```bash
cd 仟流智算/deploy

# 构建所有镜像（首次约 5-10 分钟，装依赖 + argon2 编译）
docker compose build

# 启动（migrate 先跑，然后 control-api/gateway/worker/web/caddy）
docker compose up -d

# 看启动日志，确认全绿
docker compose logs -f --tail=50
```

## 3. 验证服务起来

```bash
# health 检查（应返回 {"status":"ok"}）
curl http://localhost/health          # 经 Caddy → control-api
curl http://localhost:8787/health     # 直连 Gateway

# Web 管理后台
open http://localhost:8080            # 登录页

# Gateway 模型列表（需先在 Web 创建企业/管理员/主体/Key，见 §4）
curl -H "Authorization: Bearer sk-qianliu-你的Key" http://localhost:8787/v1/models
```

## 4. 创建试点数据（首次必做）

Web 起来后，用管理员账号登录管理后台，按顺序创建：
1. 企业（已由数据库初始化）
2. 管理员账号（用 seed-admin 命令，或 Web 创建）
3. Provider（DeepSeek/智谱/Kimi）+ 资源 + 凭证
4. 统一模型 + Model Route
5. 主体（员工/项目）+ Key（**发给同事的就是这个 Key**）+ Grant（模型授权 + 额度）

> seed-admin 示例（在仓库根目录跑）：
> ```bash
> pnpm --filter @qianliu/control-api seed:admin --enterprise 你的企业 --username admin --password 你的密码
> ```

## 5. 同事用 WorkBuddy/ZCode 连接

把以下信息给同事：

| 项 | 值 |
|----|-----|
| **Gateway Base URL** | `http://<Mac-Mini的IP>:8787/v1`（局域网）或内网穿透地址 |
| **主体 Key** | `sk-qianliu-...`（你在 §4 给该员工创建的） |
| **模型别名** | `qianliu-*`（在 §4 创建的统一模型别名） |

### WorkBuddy（OpenAI 兼容）
- Base URL：`http://<Mac-Mini-IP>:8787/v1`
- API Key：员工的 `sk-qianliu-...`
- 模型：`qianliu-deepseek`（或其他别名）

### ZCode（OpenAI 或 Anthropic 兼容）
- 同 WorkBuddy（OpenAI 模式），或配 Anthropic 兼容地址 `http://<Mac-Mini-IP>:8787`

### Claude Code（Anthropic 兼容）
- Anthropic Base URL：`http://<Mac-Mini-IP>:8787`
- API Key：员工的 `sk-qianliu-...`

## 6. 网络可达性（同事怎么连到 Mac Mini）

取决于 Mac Mini 的网络位置，三选一：

- **同一局域网**：同事和 Mac Mini 同网段，直接用 Mac Mini 的局域网 IP（如 `192.168.1.100:8787`）
- **内网穿透**（frp/tailscale/zerotier）：把 Mac Mini 的 8787/80 端口暴露，同事用穿透地址
- **公网 IP + 域名**：在 Caddyfile 配域名 + 自动 HTTPS（取消 Caddyfile 注释，换真实域名）

> **生产必须 HTTPS**（TRD 要求）。局域网/内网测试可先用 HTTP；正式对外时在 Caddyfile 配 TLS。

## 7. StubUpstream → 真实 Provider 切换

⚠️ **重要**：Gateway 当前默认用 `StubUpstream`（模拟上游响应，返回假 usage）。要让同事真的调通 DeepSeek/智谱/Kimi，需切换到真实 HTTP caller。

切换点在 `apps/gateway/src/main.ts`（StubUpstream → createRealPipeline + 真实 Adapter）。这需要真实凭证就绪后做（DEP-PROVIDER-CREDENTIALS）。切换前同事连上来能通协议层，但响应是模拟值。

## 8. 日常运维

```bash
# 看日志
docker compose logs -f gateway
docker compose logs -f control-api

# 重启某服务
docker compose restart gateway

# 停止全部
docker compose down

# 停止并删数据（⚠️ 清空数据库，仅重置时用）
docker compose down -v
```

## 9. 已知限制（第一层 vs W24 完整 DoD）

本指南部署的是 **W24 第一层（最小可部署）**，以下 W24/W25 完整 DoD 项**尚未做**（第二层，后续推进）：

- ❌ 最小权限（non-root / read-only fs / cap_drop）
- ❌ 出站白名单（egress firewall）
- ❌ Docker Secret 注入链路（目前 env_file）
- ❌ 正式 TLS（目前 HTTP，Caddyfile 预留）
- ❌ 监控/Trace/指标导出
- ❌ 每日加密备份 + 恢复 + RPO/RTO 演练
- ❌ 故障手册
- ❌ worker 定时调度器（目前跑一次 reconciliation 即退出）

这些在第一层验证（同事能连、能测）后逐步补，不阻塞试点。
