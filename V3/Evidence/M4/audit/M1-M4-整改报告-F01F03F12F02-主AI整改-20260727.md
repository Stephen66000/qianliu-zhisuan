## 1. Finding 逐项整改状态

### F-01 · 额度门禁接入 real-pipeline 热路径（P1）→ **CLOSED**

**整改内容**（`apps/gateway/src/pipeline/real-pipeline.ts`）：

1. `RealPipelineDeps` 增加必填 `quotaRepo: QuotaGateRepository`（非可选——DoD 核心验收）
2. 新增私有预估器 `estimateRawTokens(body)`：body.messages 字符数 / 4 + 256 output 预留，返回保守上界（bigint）；不引入 tokenizer 依赖
3. 步骤 3b 前插额度门禁（`// 3a-bis`）：
   - **仅 CODING_PLAN 模式**触发（API 模式 `deductedQuota=null`，跳过）
   - `acquireLease`（按 provider_resource_id 并发限流）→ 满（null）则排除资源重评
   - `reserveQuota`（按 `(principal, provider, model_alias)` 的 grant 预占）→ REJECT 则释放租约 + 排除资源
   - **per-attempt reserve**：grant 键含 provider，跨 provider failover 命中不同 grant，per-request 无法正确归属
4. 步骤 3d 后结算（`// 3d-bis`）：
   - committed 成功 → `settleQuota(grantId, reservedEstimate, actualDeducted)`：**deducted_quota 回写 quota_counter**（多退少补）
   - 失败/可切换 → `releaseQuota` 释放预占
   - 释放 lease

**关键设计决策**：
- estimatedCost 用 multiplier="1" 口径预占（raw token）；有计价倍率时预占略偏低，settle 校正补足——`settleQuota` 多退少补天然容忍估计误差
- API 模式不触发门禁（monetary 计费，无 deducted_quota）

**验证**（`w18-quota-pipeline.test.ts` 新增 7 用例）：
- F-01-1：CODING_PLAN 成功 → `quota_counter.used_value` = ledger_line.deducted_quota（回写验证）
- F-01-2：额度耗尽（quota_value=1）→ REJECT_EXHAUSTED → 503，counter 不变
- F-01-3：并发达 concurrency_limit=1 → acquireLease 返回 null → 排除资源 → 503
- F-01-4：allow_overage=true → ALLOW_OVERAGE → 成功 + 超额记录
- F-01-5：API 模式 → 门禁跳过，正常放行（不被误拒）
- F-01-6：双 Attempt failover → 首 Attempt 429 释放预占 + 第二成功结算（used = 仅成功 Attempt）

### F-03 · ledger_transaction token 聚合用 finalOutcome 而非明细之和（P1）→ **CLOSED**

**整改内容**（`real-pipeline.ts` 行 336-368 + dispatch 节）：

1. transaction 聚合改为基于 `listLedgerLines(requestId)` 求和（仓储层 helper 已存在）：
   - `total_input/output/cache_tokens` = SUM(ledger_line.raw_*)
   - `total_deducted_quota` = SUM(ledger_line.deducted_quota)
   - `total_api_cost` = SUM(ledger_line.api_cost)，用 Number 求和 + toFixed(8)（≤2 条明细，double 精度无误差）
2. **删除** transaction 级 `computeBilling`（行 341-349）：明细已冻结 billing_rule/multiplier/cost，事务级不再二次匹配——**消除 Date.now() 选不同规则版本的隐患**
3. dispatch 节 `actualCost` 复用事务聚合值 `transactionApiCost`（不再二次 computeBilling）

**根因修复**：原实现用 `finalOutcome.usage`（末次 Attempt）会漏算 failover 前置 Attempt 的 ESTIMATED usage，违反 TRD §5.7 行 348 + §10.1 行 653"请求级总费用=全部明细之和"。

**验证**（w18 用例 7）：单 Attempt 成功 → `tx.total_*` = SUM(line.raw_*)（input/output/cache/deducted 全维度）。w17 SETTLEMENT_MISMATCH 扫描正常路径不再产生偏差。

### F-12 · 生产入口 main.ts 注入 stubPipeline（P1）→ **CLOSED**

**整改内容**（`apps/gateway/src/main.ts`）：
