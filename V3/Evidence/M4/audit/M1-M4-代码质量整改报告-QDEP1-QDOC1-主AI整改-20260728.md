## 1. Findings 处置逐项

### Q-DEP-1 · 依赖漏洞（round 1 P2 必处置）→ **CLOSED**

**问题**：undici 7.16.0（GHSA-g8m3-5g58-fq7m，high）+ fastify 5.6.1（body validation bypass 等 4 个漏洞）。

**整改**：
- undici 7.16.0 → **7.29.0**（gateway + provider-adapters）
- fastify 5.6.1 → **5.8.5**（gateway + control-api；修复全部 4 个已披露漏洞）
- @fastify/cookie 11.0.2 → **11.1.2**（适配 fastify 5.8.x 运行时）

**关键附带修复（M1~M4 既有 typecheck bug）**：
升级过程中独立核实发现 **M1~M4 既有的 cookie 类型增强缺陷**——`@fastify/cookie` 的 `declare module 'fastify'` 增强（FastifyRequest.cookies / FastifyReply.setCookie / clearCookie）在 base tsconfig 的 `verbatimModuleSyntax: true` + NodeNext 模块解析 + pnpm 隔离组合下未被 TS 合并到编译单元。用 `git stash` 验证：**当前 HEAD（`64b7a08`）的 typecheck 本就是坏的**（control-api 6 个 TS2339 错误），round 2 功能审核报告"Evidence 全绿（typecheck 11 包 Done）"与此矛盾——审核时大概率因 corepack 缓存的 pnpm 故障误判（见 §3 风险披露）。

**修复方式**：`apps/control-api/src/cookie-types.d.ts`——在项目 src 内显式 `declare module "fastify"` 增强 control-api 实际使用的 3 个 cookie 成员（cookies/setCookie/clearCookie，签名精确对照 @fastify/cookie@11.1.2）。验证：同内容文件置于 src 内可生效，从 node_modules 经 import/reference 加载则不合并（TS 在 verbatim+NodeNext 下对 node_modules 内 .d.ts 的 module augmentation 处理差异）。

**验证证据**：
- `pnpm audit`：undici/fastify 不再出现在漏洞列表（清零）。剩余 15 个漏洞为 vitest/vite/esbuild/kysely 等（不在 Q-DEP-1 范围）。
- typecheck：11 包全 0 错误（含修复后的 control-api）。
- 北向合同回归：gateway 69 集成全绿（w05/w08/w09/w10/w12/w16/w18/r2-n1 全过）；control-api 23 全绿。
- build + canary：build emit 0 错误；canary postgres/redis/logs/traces 全 0。

**Planning Change**：PC-20260727-05 已登记（安全依赖升级属实质安全变化）。

## 3. 风险与如实披露

1. **round 2 功能审核"typecheck 全绿"Evidence 失实**：round 2 报告 §3 声称 typecheck 11 包 Done，但当时 control-api 实际有 6 个 cookie 类型错误（M1~M4 既有 bug）。审核时大概率因 corepack 缓存的 pnpm 报 ERROR 被误读为"无类型错误"。本次整改修复了该 bug，但 round 2 其他结论的可信度建议佳哥/审核方独立判断是否需要复核。
2. **fastify 5.8.5 后续漏洞**：截至整改时（2026-07-28），5.8.5 清零了已披露的 4 个漏洞。fastify 后续若新披露漏洞，需再次升级（@fastify/cookie 上游适配进度是依赖约束）。
3. **变异测试 Gap**：GAP-MUT-1 未产出变异分数，R3 核心规则的测试有效性未经变异验证。这是真实的 Evidence Gap，是否阻断 PASS 由审核方判、佳哥定。
4. **剩余 15 个漏洞**：vitest/vite/esbuild/kysely 等，不在 Q-DEP-1 范围。esbuild/kysely 是开发依赖或核心数据访问库，建议后续单独评估。
