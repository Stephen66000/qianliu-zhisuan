## 本轮审计问题与整改

1. **并发发布不同规则会覆盖 Key 模型集合**：发布事务锁定 ACTIVE Key，并在锁内按“手工基线＋全部有效规则”重算最终集合，避免最后写入者覆盖其他规则。
2. **Key 新建／重置遗漏已发布规则模型**：创建、更新、重置统一调用同一授权策略；重建 Key 会继承手工模型、当前有效规则模型及原有 IP、有效期、额度和并发限制。
3. **发布预览不是最终有效权限**：校验结果改为基于手工授权与全部有效规则计算 `added/retained/removed`，与事务落库语义一致。
4. **有效期语义不一致**：静态 Key 白名单保存完整声明上限；请求热路径仍由当前有效 Grant 做最终门禁，过期或撤权立即失效。
5. **迁移回滚破坏来源审计**：`0038 down` 在已存在员工规则版本时拒绝回滚，防止删除规则来源与审计链。
6. **质量证据不足**：补充并发发布、Key 重建、错误路径、ALL 范围、纯授权策略、迁移回滚保护、前端 API／页面测试、增量覆盖率门禁与变异测试。
