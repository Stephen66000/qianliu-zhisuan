## 需求实现

1. 经营账单拆为独立员工账、员工详情和项目账路由；旧主体路径只做兼容跳转。
2. 员工总览展示总／输入／输出／缓存 Token、额度扣减、API 成本、套餐分摊、归集成本、
   活跃天数、请求数和最近使用时间。
3. 员工详情按厂商聚合，再按稳定 `unified_model_id` 展开具体正式 alias；请求明细保留请求
   发生时 alias，历史名称不会被当前名称覆盖。
4. 项目账复用同一组账本事实并按唯一项目归属投影；未归属请求单列，多条 ledger line
   不会重复计请求或费用。
5. CLOSED 账期读取冻结证据；旧快照缺失／JSON `null` 时返回 409，不伪造历史。
6. `UNKNOWN`／`MIXED` 用量和未知费用保持 `null` 或明确质量标签；Web 只展示服务端聚合，
   不重算 Token 或费用。

## 模型身份、权限与结算不变量

- `ai_request.unified_model` 保留历史 alias，新增 `unified_model_id` 作为稳定统计身份；0044 仅按
  可证明的当前 alias 和 POOL-038 显式映射回填，无法证明的历史记录保持 `NULL`。
- Gateway 在请求与 attempt 上冻结稳定模型身份；每个上游 attempt 的 Token、缓存／推理 Token、
  API 成本和质量证据在同一结算语义中落账，失败不会伪装成零成本。
- `/v1/models` 与上游调用前最终栅栏均使用同一计费规则匹配器，完整校验时区、星期、时段、
  生效边界和资源模式；最终栅栏用单条 SQL 同时复核 Key／Grant／route／resource／provider 与
  候选计费规则，并冻结精确规则版本供 Attempt 结算，规则在上游在途停用也不丢失成本事实。
  API 空价格与套餐空倍率均 fail-closed，不再用默认倍率或旧价格兜底。
- 经营调度在 SWITCH／REJECT／RATE_LIMIT／上游动作前先写不可覆盖的核心决策审计；写入失败
  直接终止请求。结算证据在请求终态前补齐；运行保障信号、资源健康和半开探针释放分别隔离，
  首次决策写失败将请求置 FAILED 且不创建 Attempt／访问上游；调度补充证据在核心终态后独立
  幂等重试，失败不阻断账本、额度、租约或探针释放。
- 关账和结算使用“企业＋北京时间月份”事务级 PostgreSQL advisory lock；结算在同一事务中
  检查 CLOSED、触碰 DRAFT 账期并写 ledger，关账只对 SQLSTATE `40001` 做有界重试。
- 真实并发测试覆盖：初始无账期、结算／关账竞争、CLOSED 后拒写、DRAFT 版本触碰、重复请求
  幂等、缺失 request/attempt、不同企业同月互不阻塞和失败整体回滚。
- 完整 E2E 暴露的权限扩大缺陷已修复：厂商池自动刷新只纳入 ACTIVE unified model、启用 route、
  可服务 provider/resource，且存在当前有效 billing rule 的模型；PENDING_CONFIG／无价模型不再
  自动写入 Key 的 `allowed_model_ids`。
