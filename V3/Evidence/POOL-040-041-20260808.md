## 实现摘要

### POOL-040（P1）

新增 `apps/gateway/src/admission/invocation-admission.ts`，由 `/v1/models` 和 Adapter 前最终栅栏
共同调用。单次 PostgreSQL 查询同时检查：企业/主体/Key 状态与有效期、Key 模型白名单、统一模型
ACTIVE、Route enabled、Provider ACTIVE、Resource 当前可服务状态、exact/pool Grant 状态与有效期，
以及 pool 的 `principal_provider_disabled_model`。

生产候选从 `main.ts` 绑定 `model_route.id`；额度 reserve、并发 lease、attempt 创建后，在 Adapter
调用前再次复核。复核失败时不触达上游，释放额度预占、lease 和 half-open probe，attempt/request
记录失败，不生成成功扣费账本；若只是当前候选失效，排除该 Route 后继续选择仍有效候选。

候选评分仍按既有资源级 failover 语义处理上游失败；仅最终准入撤权按 `routeId` 从当前候选集过滤，
因此同一 Resource 的不同 upstream Route 不会被误排除。

### POOL-041（P2）

新增 `apps/control-api/src/principals/access-configuration-schema.ts`。请求 Schema 在 trim 后拒绝
重复 `provider_code`，并拒绝同一 provider 项内重复 `enabled_model_ids`；Control API 稳定返回 400、
首条 `message` 和结构化 `detail`，校验失败早于任何数据库写入。
