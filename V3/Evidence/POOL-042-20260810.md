- **本地修复候选：PASS**。
- DeepSeek API 资源摘要已展示本月 Token 分项、模型下钻、Token／费用速度，以及明确标注为估算的余额可承载 Token。
- 初始候选的标准全量工程门禁通过；双审补丁随后通过 Database／Control API typecheck 与 lint、真实 PostgreSQL、POOL-042 真实 Playwright E2E 和当前源码定向变异测试。

## 实现口径

1. 本月 Token 直接聚合 `ledger_line` 已落账的输入、输出、缓存、推理和总 Token；模型下钻展示当前正式 alias。
2. 本月费用继续使用 `ledger_line.api_cost`，Web 不按 Token 重算金额。
3. 余额可承载 Token 按每个 API 资源账号的余额、当前有效计价规则和最近 24 小时模型／输入输出缓存分布分别估算后求和，不参与额度门禁；任一账号缺余额、近期分布或价格时整体明确不可计算。
4. 数据质量区分 `EXACT`／`ESTIMATED`／`UNKNOWN`；余额、用量、当前价格或币种无法形成完整口径时返回明确原因，不伪造精确值；估算置信度取所有资源账号中的最低样本量。
5. Coding Plan 原有额度窗口、消耗速度和预计耗尽语义保持不变。

## 关键边界

- 多账号、多模型、多计价版本、输入／输出／缓存／推理 Token 分项均由 PostgreSQL 聚合；同厂商账号异价不会再用聚合余额除以局部价格。
- 当前规则缺失、币种不一致、余额缺失、最近用量缺失、零价格和未知 usage 均 fail-explicit。
- 所有金额计算使用 Decimal；不记录或回显明文 Key、凭证、请求正文或上游响应正文。
- POOL-033 既有回归用例的“未来 60 秒”夹具会在整包排队超过 60 秒后自然生效，导致标准门禁假失败；已改为用例执行时生成 24 小时边界，仅修测试时钟稳定性，不改产品语义。
