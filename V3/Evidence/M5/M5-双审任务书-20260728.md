2. **P1-02：W19 声称的管理写操作闭环没有进入桌面 Web。**

3. **P1-03：11/11 E2E 存在“绿但没执行目标行为”，不能证明 WT-01～20 Web 路径。**
   `apps/web/e2e/wt-web.spec.ts:25-35` 的 WT-01 只填凭证，不提交 API；`:65-76` 的 WT-05 接受空态即通过；`:78-88` 的 WT-10 在无账本数据时整段不执行；`:90-94` 的 WT-15 只断言静态标签；`:96-107` 的告警用条件分支允许不执行处置。`apps/web/e2e/README.md:31-34` 又把 WT-04/06/11/12/14/16/17/18/19 整体归为“非 Web”，但这些 WT 明确包含管理员创建项目、开启超额、查看逐 Attempt/调度/评分、定位能力和受控恢复等 Web 行为。双平台 11/11 只能证明这 11 个浅用例通过。

4. **P1-04：账本下钻缺少逐 Attempt 计量与全部账本明细。**
   `apps/control-api/src/gateway-requests/routes.ts:92-117` 只返回 Attempt 的状态/时间/错误，不读取已有 `ledger_line`；`apps/web/src/pages/RequestDrilldown.tsx:117-153` 因此不展示每个 Attempt 的输入/输出/缓存 Token、扣减、费用、计量质量，也不展示全部不可覆盖账本明细。测试 `apps/control-api/src/__tests-integration__/w20-diagnostics-alerts.test.ts:245-257` 只验证两个 Attempt 的状态。缺少 PRD `V3/仟流智算-产品需求文档-v0.3.md:450-458` 的硬要求，WT-11 不能判闭合。
   **解除条件**：按 `upstream_attempt_id` 返回并展示 `ledger_line`/usage 明细，覆盖两次均产生可证明用量、失败 Attempt 也入账、请求汇总与明细一致。

5. **P1-05：告警派生实现会报陈旧告警，且“历史”并不持久。**
   `packages/database/src/repositories/alert-repository.ts:199-233` 读取某资源全部 `supply_forecast` 快照，没有按资源选择最新快照；任一旧快照覆盖时长 `<24h` 会持续生成告警，并可能以相同 `alertKey` 重复。`:51-94` 每次只从当前源事实重新派生，再合并处置状态；源状态恢复后该告警立即从结果消失，`apps/web/src/pages/Alerts.tsx:55-83` 的“显示已处理历史”无法显示已消失事件。该设计还与 TRD `V3/仟流智算-技术需求文档-v0.3.md:761-763` 的阈值配置和 `alert_event` 事实记录相冲突。
   **解除条件**：冻结告警事实与生命周期；至少按最新预测判定、保留触发/恢复/处置历史、保证唯一键和并发幂等，并覆盖 PRD/TRD 四域八类信号。

#### P2

1. **P2-01：毫秒截断的 `updated_at` 乐观锁存在同毫秒 ABA 窗口。**
   `packages/database/src/repositories/admin-write-repository.ts:14-20,33-40` 将数据库时间截到毫秒，同时更新值来自 JS `new Date()`；若连续写落在同一毫秒，时间戳可不变，旧快照仍可能命中。现有测试 `apps/control-api/src/__tests-integration__/w19-admin-writes.test.ts:129-153` 只验证通常情况下的串行旧快照，没有构造同毫秒碰撞。建议改为单调 `version`，或使用能完整往返数据库精度的版本令牌。

2. **P2-02：额度更新输入校验会把客户端错误变成 500，并接受负额度。**
   `apps/control-api/src/admin-writes/routes.ts:37-46` 在 Zod transform 中直接 `BigInt(v)`；独立探针确认 `"abc"`、`"1.5"` 会从 `safeParse` 抛 `SyntaxError`，`"-1"` 则通过，而数据库没有非负约束。应先用整数正则/安全整数 schema 校验，再转换，并加数据库 `CHECK (quota_value >= 0)`。

3. **P2-03：展示格式化存在大整数精度损失。**
   `apps/web/src/lib/format.ts:21-27` 把 token/额度字符串转为 `Number` 再格式化，超过 `Number.MAX_SAFE_INTEGER` 会显示错误值。它没有越界重算账本，但应改用 `BigInt` 或字符串分组。

### 8.5 对 §4 五个关键决策的审查意见

1. **告警不建表 + 复用 reconciliation：驳回。** 当前实现既污染对账语义（`PASS` sentinel 下挂告警差异），又不能保存真实告警历史，并与 TRD 的 `alert_event` 冲突。域 2 固定 100 元也不是“突增”判定，且违反“阈值由配置管理”。
2. **`updated_at` 乐观锁：驳回当前实现。** 企业边界和原子 WHERE 更新方向正确，但毫秒截断不是可靠版本号；整改为单调版本令牌后可采纳。
3. **E2E = Web 路径 WT 子集：驳回当前边界和套件。** 运行时内核可以由后端集成测试证明，但所有管理员观察/配置/处置动作仍属于 Web 路径，不能整体转移；条件跳过不能算覆盖。
4. **凭证明文一次提交 + AES-256-GCM + 指纹：有条件采纳。** 直接代码路径未发现明文回显/入库，W19 canary 也命中 0；但当前 canary 只扫 `provider_resource` 和响应，正式签署前应覆盖 operation_log、应用日志、错误对象、Trace、测试快照，并验证失败路径。
5. **前端只读消费后端、不重算账本：采纳。** `format.ts` 的千分位、单位和百分比属于展示转换，不是账本重算；但需修复 P2-03 的精度问题。
