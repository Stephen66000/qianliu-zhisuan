## 2. 根因证据

### 已确认

- Provider Caller 原先完整消费并聚合上游 SSE，返回 `Outcome` 后 Gateway 才开始写响应。
- Chat 原先由聚合结果合成 SSE；Messages 忽略流式请求；Responses 也是缓冲转换。
- 429 与通用故障共用 `UNAVAILABLE` 路径；半开只有候选标记，没有原子单探针租约。
- `upstream_attempt.first_byte_at` 已有字段但未写入，且没有失败层字段。
- Caddy Gateway 路径此前没有显式关闭响应缓冲。

### 未确认

- 生产约 60 秒后的 404 HTML 缺少同一 request ID 对应的 Gateway、Caddy 和 Kimi
  日志，因此无法证明由哪一层生成。本次不把全部 404 归因于流式；只确认完整缓冲会
  放大长流故障与客户端误报。

## 3. 实现结果

### 协议与超时

- `/v1/chat/completions`：合法上游 chunk 到达即写 OpenAI SSE；保留模型、请求标识、
  finish reason、工具调用、最终 usage 和 `[DONE]`。
- `/v1/messages`：实时转换为 Anthropic `message_start`、内容块 start/delta/stop、
  分片 `input_json_delta`、`message_delta` 和 `message_stop`；流中错误输出 `event: error`。
- `/v1/responses`：能力矩阵从 `NATIVE` 改为 `TRANSFORMED`。当前仍是 Responses 子集
  到 Chat Completions 的缓冲转换，不支持原生 Responses 事件与托管工具，不宣称原生兼容。
- 增加首字节、流式空闲、请求总时长三层配置，默认分别为 `30s / 45s / 10min`。
- HTTP HTML、网络、协议和超时只返回稳定 JSON/SSE 错误；不读取、保存或回传 HTML 正文。
- Caddy `/v1/*` 反向代理增加 `flush_interval -1`。

### 429、冷却与半开

- 新增 `RATE_LIMITED` 运行态，429 保留 `Retry-After`，默认短时冷却且封顶。
- 同一冷却窗口内并发 429 只形成一个状态迁移，不重复累计失败或延长冷却。
- 唯一资源冷却期间返回 429 与剩余等待时间，不改报 503，也不在同一请求内立即重打。
- 冷却到期通过 PostgreSQL 条件更新获取半开租约；多实例同一时刻只有一个真实请求探测。
- 半开租约默认 11 分钟，覆盖 Gateway 10 分钟请求总时长，避免 K3 长流中途出现第二探针。
- 探针成功进入 `DEGRADED`，后续成功再恢复 `ACTIVE`。

### 诊断与数据边界

- `ai_request` 记录协议、stream 和脱敏客户端标识；`upstream_attempt` 记录首字节、
  上游 HTTP 状态、失败层、提交状态和 request ID 关联。
- Control API 与 Web 请求下钻展示失败层和首字节耗时。
- 迁移只增加运行状态约束和 `failure_layer` 元数据列，不修改历史账本，不增加正文列。
- 自动化真实链路复核消息正文仍只在进程内存中处理。
