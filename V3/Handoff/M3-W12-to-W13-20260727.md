## 2. W12 关键决策（接手者必须知道）

1. **评分器是纯函数，因子框架可扩展**。`scoreAndSelect` 无随机、顺序无关、可回放；容量/负载/错误率/TTFT/额度/成本因子**预留 absent 处理**（数据源 W15/W16 就绪后接入，权重在 ROUTING_POLICY.weights 加项即可）。
2. **提交前/后边界是硬规则**：committed=false + `isSwitchable` 才排除重评；committed=true 立刻 break（不拼接第二上游）。W13/W14 在 pipeline 里加逻辑时不得破坏。
3. **每次 Attempt 冻结 route_candidate**：score_factors 含 factors + policy_version + affinity_resource_id,total_score,reason_code。WT-18 可解释 + 回放对账的事实底座。
4. **修正记录**：初版 DEGRADED 测试预期算术错误（weight 3:1 时 weight 优势仍胜），已改双向边界断言；评分器行为本身正确。

## 3. W13 要做什么（明确范围）

**详细计划行 289**：统一 Token 事实、Decimal 金额、价格／倍率／周期规则版本、逐 Attempt 计价。验收：历史不重算、币种与精度、WT-05。

### 可用集成点（W09~W12 已备好）

- **原始用量事实**：`usage_event`(input/output/cache + usage_quality)+ `ledger_line.raw_*_tokens` 已落库；CODING_PLAN `api_cost=null`、API 模式当前是 M2 简化固定价（real-pipeline `computeApiCost`)。
- **倍数需求来源**：智谱高峰 14:00–18:00（UTC+8）分时倍数（TRD §7.2 行 483）；Kimi 模型档位倍数（TRD §7.3 行 491）——W09/W10 Adapter 都只保原始口径，折算在此落地。
- **规则版本化**：domain 已有 `BILLING_RULE_TYPE`(API_PRICE/PLAN_QUOTA_MULTIPLIER)；需建 billing_rule_version 表 + 版本快照（历史不重算）。
- **Decimal**：decimal.js 10.6.0 已在工程规则基线；数据库金额 numeric。

### W13 不做（边界）

- 额度预占/并发租约/耗尽停止热路径（→ W14）
- 供给预测（→ W15）、经营调度（→ W16）
- 真实凭证（DEP-PROVIDER-CREDENTIALS）
