## 2. 第二轮逐项结论

### 2.1 事件模型：PASS

- 7类事件完整；
- 金额方向可直接翻译为数据库约束；
- 已确认零期初和缺期初可区分；
- 期初更正不破坏期初唯一性；
- 冲销金额由原事件派生；
- 事件只追加，纠错不改历史。

### 2.2 币种与现金：PASS

- 账户原币与人民币实付分离；
- CNY/USD余额不混算；
- USD经营成本不伪装人民币；
- 现金支出只汇总明确人民币实付；
- 精度和舍入规则明确。

### 2.3 API使用账本：PASS

- 继续复用现有 `ledger_line`，不复制第二份扣费账；
- `api_cost_currency`、`api_cost_status`、`settled_at`职责清晰；
- 确认未访问上游的零审计行不会造成币种缺口；
- 费用未知导致余额不可计算，不会返回虚高正常余额；
- 历史回填范围和Evidence要求明确。

### 2.4 Coding Plan：PASS

- 资金事件与服务周期分离；
- 默认按上海自然月从扣费日持续到下个月同日，覆盖28/29/30/31天；
- 扣费日=周期开始日；
- 重叠周期归属明确；
- 暗周期准备顺序闭合；
- 使用周期ID冻结，冲销后历史使用不改写；
- 真实Token不重复累计缓存和推理。

### 2.5 对账案件：PASS

- OPEN/REJECTED/RESOLVED状态可实现；
- 确认决策、调整事件和案件终态同事务；
- 最终跨表闭环由延迟约束触发器验证；
- 费用不完整和缺期初不误建对账案件；
- 负余额案件允许本地余额为负，厂商确认余额保持非负。

### 2.6 幂等与重复入账：PASS

- 技术幂等与业务凭证唯一分离；
- 同一付款不能通过购买/续费换类型重复登记；
- 无凭证重复候选有持久对象和一次性确认；
- 一个原事件最多冲销一次。

### 2.7 余额读取：PASS

- asOf边界、未来时间和状态优先级明确；
- 组件与事实水位来自同一数据库快照；
- 缺期初、费用不完整、负余额和历史封存均失败关闭；
- 多资源、多模型和多币种归属无歧义。

### 2.8 迁移与切换：PASS

- 加法迁移和暗部署先行；
- 周期先准备、Gateway后暗写；
- 9月1日后API使用不复制，只补币种/状态/结算时间；
- 正式读写和旧端点废止同窗完成；
- 新账本接受真实写入后禁止直接回旧写链；
- 第一次失败停止和Evidence边界明确。

## 3. 实施阶段强制门禁

合同通过后，代码实现仍必须逐项证明：

- [ ] 实时迁移头无冲突；
- [ ] 数据库DDL可表达事件矩阵、复合租户外键和延迟闭环约束；
- [ ] 所有切换后API行能归类为已计价、确认未上游零事实或费用未知；
- [ ] 余额读取确实使用一个SQL或REPEATABLE READ快照；
- [ ] Coding Plan暗周期能覆盖切换窗口前新增使用；
- [ ] 历史回填非目标字段哈希不变；
- [ ] 数量、金额、余额、币种、周期和水位守恒；
- [ ] 所有后端消费者同窗切换；
- [ ] 旧资金写入口全部关闭；
- [ ] 定向测试、类型、Lint和差异检查通过；
- [ ] 部署和真实用户验收另行授权。

任一门禁失败，不影响本合同的设计PASS，但实现候选必须判定FAIL并停止。

## 4. 剩余非阻断风险

以下不是合同缺口，但可能在数据演练中形成NO-GO：

1. 旧充值/订阅缺少人民币实付；
2. 旧API结算行缺少可恢复的冻结币种；
3. Coding Plan历史使用没有可确认覆盖周期；
4. 9月1日期初余额缺少Owner确认；
5. 旧消费者未能在同一切换窗口全部切换。

这些问题必须进入迁移缺口报告，不得自动猜测。
