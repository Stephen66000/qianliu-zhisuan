## 2. W09 关键决策（接手者必须知道，否则会走偏）

1. **高峰扣减倍数不在 Adapter 计算**。Adapter 只保原始 Token/Prompt 口径；14:00–18:00（UTC+8）的智谱高峰倍数属版本化计价规则，归 **W13**。依据：TRD §7.2「规则由管理员按实际套餐维护」+ 工程规则 §7「规则须版本化、可回放」。W10 Kimi 同样遵循此边界。
2. **真实凭证不阻塞 Adapter 开发**。W09/W10 用 `UpstreamCaller` 注入点 + StubUpstream 验证 Adapter 形状；真实 HTTP 在 `DEP-PROVIDER-CREDENTIALS` 解锁后才接入，仅阻塞**上线签字**，不阻塞离线契约。不要因为没有凭证就停工或制造泛化阻塞。
3. **Coding Plan 模式账本边界**：`mode=CODING_PLAN` → `api_cost=null`、`total_api_cost="0"`、`total_deducted_quota=0`（套餐模式不产生 API 费用；扣减额度在 W13/W14）。这是 TRD §7.2/§10 的硬边界，别在 W10 破坏。

## 4. 如何运行（命令与 PATH，必看）

**关键**：系统 `pnpm` 不在 PATH，必须先加 `.corepack-bin`。所有命令从项目根 `/Users/mac/Projects/仟流智算` 执行：

```bash
# 每个新 shell 先执行（或加到 ~/.zshrc）
export PATH="$PWD/.corepack-bin:$PATH"
# 验证：pnpm --version 应输出 11.11.0；node --version 应是 v22.17.1

# 全工程命令（W09 实测全绿，W10 改动后重跑这些）
pnpm typecheck          # 11 包
pnpm lint               # 11 包，--max-warnings=0
pnpm test               # 单测（含集成，因为各包 test 脚本已含）
pnpm test:integration   # 显式集成（database 4 + gateway + control-api 23）
pnpm build              # 11 包
pnpm evidence:canary    # postgres/redis/logs/traces 应全 0

# 单包快速验证（W10 开发时）
pnpm --filter @qianliu/provider-adapters test      # KimiAdapter 单测
pnpm --filter @qianliu/gateway test:integration    # kimi e2e
```

集成测试依赖 PostgreSQL Testcontainer（`@qianliu/testing` 的 `startPostgresContainer`），需本机 Docker 运行。
