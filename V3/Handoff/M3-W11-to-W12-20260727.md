## 2. W11 关键决策（接手者必须知道）

1. **状态机是纯函数，副作用在仓储**。`deriveResourceTransition(state, classification, now)` 注入时钟、无随机（退避确定性指数，可回放）；落库走 `ResourcePoolRepository`（行锁 + 状态更新 + 审计事件同事务）。W12 在请求路径调用 `recordFailure`/`recordSuccess` 驱动迁移。
2. **恢复边界**：CREDENTIAL_INVALID/EXHAUSTED/EXPIRED 只能 `adminRecover`（人工，→DEGRADED）；UNAVAILABLE 冷却到期自动半开（`evaluateAdmission` probe=true）。一次成功 → DEGRADED，不直接回 ACTIVE（TRD §9 行 598）。
3. **版本化参数** `RESOURCE_POOL_POLICY`（failureThreshold=3、429 退避 30s 基准、熔断 60s 基准、30min 封顶，version `w11-v1`）。调整需 Planning Change。
4. **429 与临时故障分开**：429 直接冷却退避（不计入熔断阈值路径的语义差异——429 是上游明确信号）；临时故障计数达阈值才熔断。

## 3. W12 要做什么（明确范围）

**详细计划行 288**：硬过滤、多因子归一化、稳定 tie-break、Affinity、提交前切换、提交后不切换。验收：属性测试、回放 100%、WT-13/18。

### 可用集成点（W11 已备好）

- **硬过滤**：`ResourcePoolRepository.listServableResources(enterpriseId, poolId?, now)` → `ServableResource[]`（含 `probe` 半开标记）。W12 评分在此过滤之后（TRD §9 行 583：评分不能替代硬过滤）。
- **状态驱动**：Attempt 失败且 committed=false → 排除已尝试资源重新评分，并对失败资源 `recordFailure`。
- **route_candidate**：W07 已落候选快照；W12 需冻结原始因子/归一化值/总分/reason code/策略版本（TRD §9 行 579）。
- **model_route**：priority（数值小优先）/weight（同优先级加权）/enabled 已在 0005 就位。

### W12 不做（边界）

- 额度预占/耗尽停止（→ W14）；经营调度策略（→ W16）
- 真实凭证（DEP-PROVIDER-CREDENTIALS 解锁后佳哥跑）
- 提交后切换：禁止（TRD §9 STREAM_INTERRUPTED_AFTER_COMMIT 不切换；W12 只需在测试中证明不拼接）
