## 1. 已完成能力

新增 `ProviderFinanceCutoverRepository`，提供：

1. `buildPreflightReport`：逐资源列出期初候选、9月1日后旧充值/订阅候选、carryover周期和使用事实缺口；
2. `backfillUsageFacts`：默认只读演练，显式确认后才允许回填；
3. `buildConservationReport`：检查事件数量、API费用分类、Coding Plan周期归属、Token事实、余额公式和月度完整性；
4. `finance:preflight` CLI：输出可保存的JSON Evidence，并给出 `GO_CANDIDATE` 或 `NO_GO`。

## 2. 旧数据处理结论

### 2.1 期初余额

旧 `provider_resource_operating_snapshot` 只作为候选证据。没有新账本期初事件时状态保持 `CANDIDATE` 或 `MISSING`，不能自动确认或填0。

### 2.2 旧充值与订阅

旧 `resource_purchase_record` 没有独立的 `cash_paid_cny` 字段，因此不得自动把原币金额当成人民币实付。9月1日后的旧记录逐笔进入 `CASH_PAID_CNY_MISSING` 审核清单；Coding Plan缺周期时另报 `SUBSCRIPTION_PERIOD_MISSING`。

### 2.3 Carryover周期

切换日仍有效的旧Coding Plan只生成 `MIGRATED_CARRYOVER` 周期候选，不生成资金事件和9月成本。周期未审核并暗创建前，Gateway周期归属门禁不得打开。

### 2.4 使用事实

自动回填严格限制为四个原本为空的字段：

- `api_cost_currency`
- `api_cost_status`
- `subscription_period_id`
- `settled_at`

Token、API费用金额、资源、请求、规则快照和原创建时间不允许改变。执行前后以逐行JSONB规范哈希校验非目标字段，任一哈希变化即失败。

## 3. 回填判定

API使用：

- 有冻结计价快照且币种为CNY/USD：`PRICED_USAGE`；
- 明确未访问上游、零Token、零费用且失败类型为下游授权/额度：`CONFIRMED_ZERO_NO_UPSTREAM`；
- 费用为空且不能证明为零费用：`UNKNOWN_COST`；
- 费用币种与冻结快照冲突：不覆盖，保留缺口并输出 `API_COST_CURRENCY_CONFLICT`。

Coding Plan使用：

- 费用状态回填为 `NOT_APPLICABLE`；
- 按结算时间选择开始日最新的未冲销覆盖周期；
- 没有覆盖周期时保持空值并输出缺口。

## 4. 演练结果

自动化测试覆盖两套生产等价数据：

1. **缺口场景**：旧充值缺人民币实付、期初未确认、API币种冲突、未知费用、周期未准备和Token不守恒，结果必须为 `NO_GO`；
2. **完整场景**：CNY/USD期初均确认、月度事实完整、余额公式一致，结果才为 `GO_CANDIDATE`。

验收结果：

- 只读预检不修改数据；
- 显式回填只改变四个白名单字段；
- 非目标字段哈希变化数为0；
- 同一批次重复执行的变更数为0；
- CNY和USD余额分别计算；
- `期初 + 充值 + 更正 + 对账 + 冲销 - 已结算使用 = 当前余额`；
- Token事实不一致会阻断GO；
- 月度资金缺口会阻断GO。

## 5. 操作入口

只读预检：

```bash
corepack pnpm@11.11.0 --filter @qianliu/database run finance:preflight -- \
  --enterprise=<enterprise-uuid> --month=2026-09
```

受控使用事实回填：

```bash
corepack pnpm@11.11.0 --filter @qianliu/database run finance:preflight -- \
  --enterprise=<enterprise-uuid> --month=2026-09 \
  --apply-usage-backfill --confirm-enterprise=<enterprise-uuid>
```

第二条命令只能在备份可读、迁移头和候选代码已锁定、期初/周期候选已审核后执行。它不会迁入旧充值、订阅或期初金额。

## 6. 进入正式切换前仍需完成

1. 对真实数据库执行只读预检并保存JSON Evidence；
2. Owner逐资源确认期初余额；
3. 逐笔补齐旧充值/订阅的人民币实付、币种、业务日期和凭证；
4. 审核并暗创建carryover与9月购买周期；
5. 在生产副本执行回填，确认哈希、数量、金额、余额和周期守恒；
6. 锁定T0/T1、备份标识、候选Commit/Tree和正式切换窗口。

在上述六项全部通过前，生产资金写入口和统一读取切换维持 `NO-GO`。
