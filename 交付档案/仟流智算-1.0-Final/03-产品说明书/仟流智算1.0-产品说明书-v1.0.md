## 1. 产品是什么

仟流智算把企业购买的 DeepSeek API、Kimi／智谱 Coding Plan 等 AI 算力统一接入一个 Gateway，再按员工或项目分配模型、额度和 Key。管理员看到的不只是“调了多少 Token”，还包括资源健康、预计耗尽、费用、套餐利用率、员工账、项目账和每次真实上游 Attempt。

一句话：**把分散的 AI 账号和 API 变成可分配、可计量、可追溯、可调度的企业算力池。**

## 2. 解决的核心问题

1. 多家 AI 厂商、多个账号和套餐分散，员工接入方式不统一。
2. API 费用、套餐额度、峰谷倍率口径不同，企业不知道真实成本与剩余供给。
3. 资源限流、失效或耗尽时，缺少可解释的故障切换与恢复路径。
4. Key、权限、模型和额度容易失控，离职、停用或重置后需要立即生效。
5. 管理者能看到请求，却难以回答“谁用了、用在哪、花了多少、有没有价值”。

## 3. 用户与权限

### 3.1 企业管理员

- 登录管理 Web；
- 创建和停用员工／项目主体；
- 生成、重置和撤销主体 Key；
- 登记厂商资源、凭证、额度和重置周期；
- 创建统一模型、Model Route、计价规则和调度策略；
- 分配单人或批量模型权限与厂商池额度；
- 查看首页、用量账本、经营账单、异常和运行保障；
- 管理同企业管理员和密码生命周期。

1.0 的管理员为同级权限，不提供分级 RBAC。RBAC、多租户、企业身份源进入 2.0 候选。

### 3.2 使用主体

主体类型包括员工和项目。主体不登录管理后台，而是使用管理员分配的 `sk-qianliu-*` Key，通过 WorkBuddy、ZCode、Codex 或其他兼容客户端调用 Gateway。请求、额度和账本均归属该主体。

## 4. 主要功能

| 功能 | 用户可以完成什么 | 关键边界 |
| --- | --- | --- |
| 首页看板 | 查看本月资源数、主体数、Token、费用、耗尽风险、超额和资源摘要 | 本账期与厂商额度重置周期分开 |
| 使用主体 | 新建员工／项目、Key、接入配置、单人模型和厂商池额度、停用／归档 | 完整 Key 只在生成或重置后一次展示 |
| 批量模型授权 | 选择多名员工、模型、厂商池额度，草稿校验后原子发布 | `SET`／`ADD` 额度语义必须显式选择 |
| 厂商资源 | 登记 Provider Resource、凭证、模式、购买事实、额度窗口、健康和模型发现 | Secret 不回显；单资源异常不拖垮整个资源池 |
| 额度规则 | 按依赖顺序配置统一模型、Route、API 价格／套餐倍率和调度策略 | 规则版本不可原地改写历史 |
| 用量账本 | 按请求、主体、资源、模型、时间和状态筛选，查看候选、Attempt、Token、费用和质量 | 前端不重算账本；正文默认不保存 |
| 经营账单 | 查看月度总览、员工账、项目账、套餐利用、价值确认和结账 | 结账后不因新规则改写历史；修正需重开新版本 |
| 运行保障 | 查看资源态势、可用性规则、熔断事件、异常中心、企微通知与人员 | 人工恢复留操作记录；通知失败不反向篡改业务事实 |
| 管理员 | 新增、停用、重置密码和强制首次改密 | 防止最后一个可用管理员被停用 |
| 系统设置 | 查看部署和运行配置、主题等系统信息 | Secret 只展示是否配置，不展示明文 |

## 5. 管理员推荐操作顺序

1. 创建第二个管理员，避免管理单点。
2. 在“厂商资源”登记 DeepSeek、Kimi、智谱资源及凭证。
3. 在“额度规则”建立统一模型和可服务的 Model Route。
4. 配置 API 计价、套餐倍率、时间窗及调度策略。
5. 在“使用主体”创建员工／项目并生成 Key。
6. 按厂商选择可用型号和额度，保存后复制一次性接入信息。
7. 让员工通过 `GET /v1/models` 确认授权模型并完成首次调用。
8. 从用量账本核对 request ID、Attempt、Token、费用和最终状态。
9. 从首页、经营账单和运行保障持续观察耗尽、异常与经营结果。

## 6. Gateway 接入

### 6.1 生产参数

| 参数 | 值 |
| --- | --- |
| Gateway Base URL | `https://gw.qianliuai.com/v1` |
| 认证 | `Authorization: Bearer sk-qianliu-<完整Key>` |
| 模型列表 | `GET /v1/models`；只返回 Key 和当前有效 Grant 共同允许的可服务模型 |
| OpenAI Chat | `POST /v1/chat/completions`，支持非流式和 SSE |
| Anthropic Messages | `POST /v1/messages`，支持非流式和 SSE |
| OpenAI Responses | `POST /v1/responses`，1.0 为转换模式，不是原生事件全量透传 |

### 6.2 正式模型别名

| 厂商 | 模型别名 |
| --- | --- |
| DeepSeek | `ql-deepseek-v4-flash`、`ql-deepseek-v4-pro` |
| Kimi | `ql-k3`、`ql-k3-256k` |
| 智谱 | `ql-glm-4.6`、`ql-glm-4.7`、`ql-glm-5.2` |

实际可见模型以主体 Key 的 `/v1/models` 返回为准；同一厂商多个模型共享管理员配置的厂商池额度，但 API 模型按各自价格计费。

### 6.3 明确不支持

- `POST /v1/embeddings`；
- `POST /v1/messages/count_tokens`；
- WebSocket Gateway。

上述能力返回明确错误，不静默降级。Responses 仅支持当前转换子集；托管工具和原生事件保真不能按 NATIVE 宣称。

## 7. 路由、额度和账本口径

### 7.1 路由

Gateway 先执行 Key、主体、模型、Grant、Route、Provider、资源、计价 readiness 和额度等硬门禁，再在可用候选中综合优先级、权重、健康、负载、错误率、时延、额度、重置、成本与 Affinity 选路。只在响应提交前对可重试错误做有界切换；首个有效输出后不跨上游拼接。

### 7.2 额度

- 主体按厂商拥有额度池，可在池内启用或关闭具体模型；
- 套餐到期、耗尽或模型被关闭时在上游前拒绝；
- 超额默认停止，只有明确开启才记录超额；
- 额度预占、并发租约和结算必须最终一致。

### 7.3 账本

- 一个下游请求只有一个结算汇总；
- 每个真实发生用量的上游 Attempt 留不可覆盖明细；
- Token 区分输入、输出、缓存和推理；
- API 费用取请求开始时命中的规则快照，不用新价格反算历史；
- 套餐扣减与 API 费用是两个不同口径；
- 用量质量标记 `EXACT / ESTIMATED / UNKNOWN`，数据不足时不伪造精确值。

## 8. 安全与隐私

1. 调用正文默认不写数据库、不写业务日志；用 canary 检查泄漏。
2. 主体 Key 只保存摘要，明文只在创建／重置时一次展示。
3. Provider Secret 加密保存，Web 和日志不回显。
4. 停用主体、撤销或重置 Key 对下一次请求即时生效。
5. 管理写操作使用认证、版本控制、二次确认和操作日志。
6. 生产发布必须绑定 Commit、迁移、配置和回滚路径。

## 9. 常见异常

| 现象 | 含义 | 建议处理 |
| --- | --- | --- |
| `401` | Key 无效、已撤销或复制不完整 | 联系管理员重新生成，不在群里发送完整 Key |
| `model_not_allowed` | Key／Grant 没有当前模型权限 | 使用 `/v1/models` 返回的模型或申请授权 |
| `404` | 客户端 Base URL 重复或缺失 `/v1` | 按客户端规则检查最终请求路径，避免 `/v1/v1/...` |
| `413` | 请求正文过大 | 减少历史上下文或使用受支持的长上下文模型 |
| `429` | 上游限流／额度门禁 | 等待恢复、切换已授权模型或联系管理员查看资源窗口 |
| `503 no healthy candidate` | 当前没有可服务候选 | 查看厂商资源健康、凭证、额度、Route 和熔断事件 |

报障时提供：发生时间、客户端、模型、HTTP 状态和 request ID；不要提供完整 Key 或会话正文。

## 10. 1.0 范围边界

- 单企业运行，核心对象保留企业边界，但不提供多租户运营界面；
- 管理员同级，不提供团队／成本中心／分级 RBAC／OIDC；
- 仟流 IDE 不作为一期最终客户端签字项；
- 完整自然月经营结果尚待 M8 Evidence；
- 不支持受控正文留存、语义检索或会话内容审计；
- 2.0 必须基于 1.0 遗留清单立项，不能直接修改本 Final 档案。
