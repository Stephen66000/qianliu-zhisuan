1. M1～M7 全部 DoD 和适用 Review／Audit 通过，同一最终候选完成两道正式 Audit 与 Planning Final Review。

## 2. AI 原生容量与排期结论

### 2.1 估算模型

- `D1` 是 Stage 03 正式启动日，开发排期使用连续 AI 执行日和实际测试工时，不使用传统团队 Sprint。
- AI 执行按“生成 → 机械检查 → 自动测试 → 失败修正 → Evidence”连续循环；工作包仍保留验收边界，但不人为等候到第二天。
- AI 会话是执行工具，不是责任 Owner；范围、真实凭证、发布和业务签字仍由佳哥负责。
- 功能候选和质量候选按 AI 连续执行估算；Windows 真机、真实员工自然月和人工发布确认不能伪装成 AI 编程时间。
- 内部构建超时才算排期偏差；外部设备、凭证、域名和人员等待单列为事件门禁，不计入 AI 编程工时。

### 2.2 AI 执行时间盒

估算依据：采用 §5 工作包时间盒自下而上汇总；W01～W25 的实现、测试和 M1～M6 中间审核约 70 个 AI 小时，最终全量回归、双 Audit 和缺陷修正约 12 小时。当前没有历史项目样本可做统计校准，因此 82 小时是 AI 执行经验估算，不是承诺工时；实际偏差只按测试和 Evidence 回填。

| 日程 | 覆盖里程碑／工作包 | 估算工时 | 输出 |
| --- | --- | --- | --- |
| D1 | W01～W08／M1～M2 | 约 18h | 工程基线＋DeepSeek 纵向闭环＋M1/M2 中间 Audit |
| D2 | W09～W17／M3～M4 | 约 22h | 三厂商、账号池、路由、额度、预测、经营账本＋M3/M4 中间 Audit |
| D3 | W18～W23（不含 W22 实机）／M5～M6 代码 | 约 14h | 七入口 Web、客户端接入、协议夹具＋M5/M6 中间 Audit |
| D4 | W24～W25／M7 工程 | 约 16h | 可部署、可恢复、可观测的功能候选和全量回归 |
| D5 | W27 | 约 12h | 双 Audit、缺陷修正、候选锁、部署／回滚验证和 Final Review |

结论：

- P50：D4 形成完整功能候选。
- P80：D5 形成完成独立审核与部署验证的质量候选。
- 若 2026-07-27 启动：07-30 功能候选，07-31 质量候选。
- W22 Windows 真机、W26 10 人入组、真实 Provider 上线签字和 M8 自然月是外部验收事件，不延长 AI 编程时间。

### 2.3 关键路径

```text
D1 工程基线＋首条真实闭环
→ D2 核心 Gateway 经营能力
→ D3 Web 与客户端代码
→ D4 部署／恢复／全量回归，形成 P50 功能候选
→ D5 双 Audit 与修正，形成 P80 质量候选
→ 外部事件：真实凭证／Windows 真机／10 人入组／发布授权
→ 下一个完整自然月
```

不能并行的合同：

- Schema／幂等结算合同未冻结前，不做完整账本与 Web 聚合。
- Adapter 能力合同未冻结前，不启用扩展协议。
- 路由 Evidence 不完整时，不做“节省”经营口径。
- M7 最终候选锁定后，任何修改都生成新候选并按影响范围重审。
- 外部验收失败只打开对应 Adapter／客户端／部署工作包，不把整夜构建回退成数周排期。

## 3. 纵向里程碑

### M1：资源和使用主体可管理

- 风险：`HIGH`；命中认证、授权、密钥和可复用正式基线，影响 M1 全部候选。
- 入口：管理员登录 Web。
- 输出：资源、统一模型、路由、员工／项目、Key、授权和额度可创建、停用、审计。
- Scope：单企业、多同权管理员；`enterprise_id` 贯穿；Key 明文一次展示；Secret 加密／指纹保存。
- Non-scope：多企业 UI、分级 RBAC、企业身份源。
- DoD：WT-01、WT-02、WT-04、WT-09 的代表性运行链通过；Key／Secret 明文扫描为 0；操作日志完整。
- 集成点：为 M2 提供真实 `principal_id`、Key、资源和 Model Route。

### M2：Gateway 内核和 DeepSeek 纵向闭环

- 风险：`HIGH`；命中公共协议、数据库合同、逐 Attempt 账本和结算，影响 Gateway 公共主链。
- 入口：兼容 OpenAI 的 `GET /v1/models`、Chat HTTP／SSE。
- 输出：鉴权、能力校验、候选快照、DeepSeek Attempt、usage、ledger line、settlement 和 Web 诊断。
- Non-scope：三厂商智能池化与完整经营调度。
- DoD：WT-03、WT-05、WT-11、WT-12、WT-14 的 DeepSeek 路径通过；重复结算为 0；正文 canary 为 0。
- 集成点：形成后续所有 Adapter、计价、路由和客户端共用的北向／账本合同。

### M3：三类上游和资源池闭环

- 风险：`HIGH`；命中上游凭证、共享协议、账号池并发状态和故障切换，影响三类 Provider 资源。
- 入口：员工选择统一模型并发起请求。
- 输出：DeepSeek／智谱／Kimi、API Key／OAuth／套餐会话、账号池、健康、冷却、Affinity、评分回放和有界切换。
- Non-scope：未被客户端证据要求的扩展协议正式启用。
- DoD：WT-07、WT-13、WT-18、WT-19 通过；单资源异常不拖垮全池；提交后跨上游拼接为 0。
- 集成点：为 M4 提供资源余额、运行状态、路由因子和实际 Attempt。

### M4：额度、预测、经营调度和分层账本闭环

- 风险：`HIGH`；命中额度、金额、不可变账本、并发租约和经营决策，影响全部计量与调度结果。
- 入口：每次 Gateway 请求及资源余额／周期快照。
- 输出：Token 事实、价格／倍率、额度预占、超额、供给预测、经营动作、反事实证据、不可变账本和对账。
- Non-scope：自动采购、自动同步厂商价格。
- DoD：WT-06、WT-15～17 通过；规则版本不反算历史；无反事实证据的节省为 `NOT_CALCULABLE`。
- 集成点：为 M5 看板和 M8 月度验证提供唯一业务事实。

### M5：桌面 Web 完整可用

- 风险：`HIGH`；该里程碑将被封存为管理员可使用的正式产品基线，并执行高权限写操作，影响七入口管理闭环。
- 入口：管理员从首页发现异常或经营问题。
- 输出：七个一级入口的查询、下钻、调整和处置闭环。
- Non-scope：手机端、Agent 入口功能、多企业管理。
- DoD：WT-01～20 的 Web 路径在真实 API 上回归；Windows 11 Chrome、macOS Chrome 通过；模拟数据不进入试点库。
- 集成点：调用 M1～M4 的管理 API 和只读模型，不在前端重算账本。

### M6：四种员工工具兼容

- 风险：`HIGH`；命中下游鉴权、公共协议和跨客户端兼容合同，影响四类真实调用入口。
- 入口：仟流 IDE、WorkBuddy、Claude Code、ZCode 配置 Base URL 与主体 Key。
- 输出：普通、流式、工具调用、取消、错误、主体归因和能力矩阵 Evidence。
- Non-scope：仟流 IDE Windows 版。
- DoD：每个工具至少 2 名真实员工；停用／重置 5 秒内生效；必要扩展协议 100% 通过，未启用能力明确拒绝。
- 集成点：只连接 M2～M4 的统一 Gateway，不在客户端复制智算领域逻辑。

### M7：内部试用就绪与完整最终候选

- 风险：`HIGH`；命中部署、迁移、恢复、生产 Secret 和完整最终候选条件，必须执行最终两道 Audit。
- 入口：冻结的部署候选。
- 输出：HTTPS Web／Gateway、迁移、备份恢复、监控告警、故障手册、10 人账号和回滚方案。
- Non-scope：高可用、多区域、正式对外 SaaS。
- DoD：RPO≤24h、RTO≤4h 演练通过；最终候选两道正式 Audit 同对象 PASS；Planning Final Review 和佳哥发布确认完成。
- 集成点：M8 只使用该冻结候选及其后经审计的新候选。

### M8：完整自然月验证

- 风险：`HIGH`；命中真实人员、生产数据和外部业务副作用，代码变化必须重新打开受影响工作包并按客观条件审核。
- 入口：质量候选发布且 10 人／设备／资源齐备后的下一个月 1 日 00:00；若 2026-07-31 前齐备，则从 2026-08-01 开始。
- 输出：每日快照、每周签字、月末十五项指标、预测偏差、资源／费用／异常和下一版本结论。
- Non-scope：用开发／演示数据补真实指标。
- DoD：自然月结束后 2 天内形成业务评审；未达项进入下一版本，不伪装完成。

## 4. Stage 02 冻结的执行参数

以下是 v0.3 的首个可实现基线。开发中可以在不改变产品合同的前提下用测试修正参数；若影响目标、自动动作、安全、账本或验收阈值，必须走 Planning Change。

### 4.1 容量与部署候选

- Pilot 容量：10 名员工；100 个并发 Gateway 请求；其中最多 50 个并发流式连接。
- 性能门禁：Gateway 自增 TTFT P95≤150ms；管理 API 常用查询 P95≤500ms；不含上游模型耗时。
- 初始服务器候选：Linux x86_64，4 vCPU、8GB RAM、100GB SSD；Web、Control API、Gateway、Worker、PostgreSQL、Redis 分容器部署。
- 数据库和 Redis 不开放公网；Web／Gateway 经 HTTPS；备份写入与运行服务器分离的位置。
- W27 用真实候选复测容量。若 4C8G 不达标，先形成容量 Evidence，再决定优化或扩容，不暗改性能目标。

### 4.2 路由评分 `routing-v1`

先硬过滤协议／能力、模型授权、凭证、额度、并发、冷却和熔断，再对剩余候选评分。所有原始值、归一化值、权重、总分、缺失原因和版本必须保存。

| 因子 | v1 归一化 | 权重 |
| --- | --- | ---: |
| 静态优先级／配置权重 | 管理员优先级与权重归一到 `[0,1]` | 0.20 |
| 健康／容量余量 | 健康为 1，半开为 0.25；并发余量线性归一 | 0.15 |
| 当前负载／队列 | `1 - min(负载率,1)` | 0.10 |
| 5 分钟错误率 | `1 - min(error_rate/0.20,1)` | 0.15 |
| 5 分钟 TTFT P95 | `1 - min(ttft_ms/3000,1)` | 0.10 |
| 额度余量 | 可用额度／周期额度，截断到 `[0,1]` | 0.10 |
| 重置与覆盖 | 剩余覆盖时长相对下一恢复窗口归一 | 0.05 |
| 边际成本 | 在当前等价资源组内反向 min-max | 0.10 |
| Session Affinity | 健康绑定命中为 1，否则 0 | 0.05 |

- Provider 不提供某因子时使用中性值 `0.5`，同时保存 `MISSING_PROVIDER_SIGNAL`，不得伪装实测。
- 总分相同时依次按静态优先级、资源 ID 排序，形成跨实例稳定 tie-break。
- Affinity 不得绕过任何硬过滤。
- 429、5xx、超时只在 `response_committed=false` 且未超重试预算时重新评分。

### 4.3 凭证生命周期 `credential-v1`

```text
UNCONFIGURED
→ ACTIVE
→ EXPIRING
→ REFRESHING
→ ACTIVE

REFRESHING → DEGRADED → COOLDOWN → ACTIVE
REFRESHING → REAUTH_REQUIRED
ACTIVE／EXPIRING → INVALID
任意可用状态 → DISABLED
```

- 401／403 或确定刷新失败只隔离当前 `provider_resource`。
- `REAUTH_REQUIRED` 只能经管理员重新授权后进入受控探测；探测成功才回 `ACTIVE`。
- 刷新使用单资源锁、指数退避和抖动；不得并发刷新同一凭证。
- 凭证状态、版本、到期时间和错误分类进入审计；Secret 明文不进入状态事件。

### 4.4 供给预测 `forecast-v1`

- 速度窗口：1 小时、24 小时、7 天；只使用已结算 Token 事实。
- 默认加权：数据充分时 `1h×0.5 + 24h×0.3 + 7d×0.2`；缺失窗口按剩余可用窗口重新归一。
- `forecast_exhaust_at = 当前时间 + 可用余额 / 加权消耗速度`；下一恢复来自厂商周期配置，不凭历史猜测。
- 可信度：少于 24 小时或少于 100 个已结算样本为 LOW；达到 24 小时且≥100 为 MEDIUM；达到 7 天且≥1000 为 HIGH。
- 告警：预计 72 小时内耗尽为 NOTICE，24 小时内为 WARNING，6 小时内为 CRITICAL。
- 余额未知、速度为 0、周期规则缺失或快照过期时返回不可计算原因，不产生伪精确时间。

### 4.5 经营调度 `dispatch-v1`

- 等价资源必须由管理员显式建组，并满足统一模型、协议、工具能力、内容边界和错误语义等价。
- 首批自动边界：只允许同 Provider、同模型、同采购模式的已授权等价资源自动切换。
- 跨 Provider、套餐转 API、改变输出语义的动作默认关闭，需发布新策略并二次确认。
- 默认动作顺序：等价低倍率资源切换 → 同池限流 → 额度保护拒绝；纯提示不计节省。
- 只有实际动作同时具备已发布策略、请求前基线和真实结算时计算节省；其余统一为 `NOT_CALCULABLE`。

### 4.6 协议启用集

- 默认启用：Models、OpenAI Chat、Anthropic Messages、HTTP／SSE。
- 默认关闭：Responses、Embeddings、count_tokens、WebSocket。
- W23 只根据 W21/W22 的真实客户端证据启用必要能力；未启用能力返回 `capability_not_supported`。

### 4.7 数据保留与恢复

| 数据 | v0.3 保留 |
| --- | --- |
| ledger、settlement、规则版本、操作审计 | 3 年 |
| request、route candidate、attempt、usage 元数据 | 180 天 |
| 应用结构化日志 | 30 天 |
| Trace | 7 天 |
| 聚合指标与每日预测快照 | 400 天 |

| Redis 幂等缓存 | 24 小时；最终事实仍在 PostgreSQL |
| 并发／连接租约 | 最长 60 秒，续租失败受控释放或关闭 |

- 每日加密数据库备份，保留 30 个日备份和 12 个月备份；RPO≤24h、RTO≤4h。
- 每月至少做一次隔离恢复；M7 发布前必须完成一次全流程恢复。
- 到期删除不得触碰仍被账本、规则或审计引用的法定业务事实；正文始终不进入保留策略。

### 4.8 企业演进边界

v0.3 所有核心对象保留 `enterprise_id`，API 和 Schema 不写死仟流；团队、成本中心、分级 RBAC、OIDC／OAuth 企业身份源和多租户 UI 进入自然月后的 M9。未来受控正文留存必须独立立项并满足 TRD §14.3，不作为日志开关实现。

### 7.3 Evidence 合同

路径：`V3/Evidence/<Milestone>/<WorkPackage>/<YYYYMMDD-HHmm>-<name>/`

1. `README.md`：候选对象、环境、输入、命令、预期、实际、结论、残余风险。
