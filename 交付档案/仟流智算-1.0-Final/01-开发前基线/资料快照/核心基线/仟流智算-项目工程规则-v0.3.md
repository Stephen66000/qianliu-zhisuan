## 1. 进入项目

新会话开始时必须依次读取：

1. 本规则；
2. `仟流智算-stage-state-v0.3.yaml`；
3. 当前阶段权威成果；只有状态文件已授权工作包时才读取详细计划中的工作包定义；
4. PRD／TRD 的受影响章节；
5. 当前动作的前置 Evidence。

只执行状态文件中的 `allowed_actions`。发现目标、范围、安全、关键依赖或验收合同变化时，停止受影响范围并登记 `Planning-Change-Log.md`。

## 3. 目标目录

```text
/
├── apps/
│   ├── web/                 # 桌面管理 Web
│   ├── control-api/         # 控制平面与管理 API
│   ├── gateway/             # 北向 Gateway 数据平面
│   └── worker/              # 对账、预测、恢复、备份任务入口
├── packages/
│   ├── contracts/           # 北向/管理 API 与错误合同
│   ├── domain/              # 仟流领域模型与确定性规则
│   ├── database/            # Schema、迁移、Query
│   ├── provider-adapters/   # DeepSeek／智谱／Kimi Adapter
│   ├── observability/       # 日志、指标、Trace、canary
│   ├── config/              # 配置 Schema，不含 Secret
│   └── testing/             # 跨包夹具和代表性运行链
├── deploy/                  # Compose、TLS、部署与恢复
├── V3/                      # 需求、计划、ADR、评审和 Evidence
├── package.json
├── pnpm-workspace.yaml
├── pnpm-lock.yaml
└── tsconfig.base.json
```

权威边界：

- PRD 决定做什么；TRD 决定技术保证；Stage 01 立项基线决定是否具备进入开发计划的条件；详细计划仅在 Stage 02 获授权后决定顺序和 DoD。
- PostgreSQL 是业务事实源；Redis 只保存短期状态、租约、速率和缓存。
- Web 不重算账本、额度、路由或节省。
- PoC 和 `参考/` 只作 Evidence／行为对照，不是产品源码目录。

## 5. 配置、密钥与数据

- 开发环境变量名：`DEEPSEEK_API_KEY`、`ZHIPU_CODING_TOKEN`、`KIMI_CODING_TOKEN`。
- 真实 Secret 只从进程环境、Docker Secret 或正式 Secret Manager 注入；`.env.example` 只写变量名和假值。
- 下游 Key 仅一次展示；数据库保存带 Pepper 的不可逆摘要。Pepper 不与摘要同库存储。
- 上游凭证只保存密文、指纹、类型、版本和生命周期元数据；页面、日志、Trace、测试快照不得出现明文。
- 默认 `content_retention_mode=METADATA_ONLY`；请求／响应正文、代码、文件、工具参数和可反推正文的缓存键不得进入数据库、Redis、日志和 Trace。
- 本地、测试、试点数据库和凭证完全隔离；演示／开发数据不得进入 M8 指标。
- 新增任何出站域名都需进入 Provider 白名单并由佳哥确认。

## 6. Git、提交与发布权限

- 当前目录没有 Git 仓库，故 Stage 02 使用 Local First；禁止把“无 Git”伪装成已有 commit。
- W01 经 Stage 03 启动授权后初始化 Git，建立 `main` 与里程碑工作分支；一个活动工作包对应一个工作分支／worktree。
- AI 可在获授权工作包内修改和运行测试；`commit`、`push`、Draft PR、merge、发布分别是独立权限。
- 未收到佳哥明确授权，不得 push、创建 PR、merge、发布、切换生产流量或修改外部服务状态。
- 候选锁至少记录 Git commit；Local First 过渡期则记录文件清单与 SHA-256。正式 Audit 前必须是 Git commit。
- 时序固定为：Stage 02 Owner 放行 → W01 初始化 Git 并形成首个 commit → M1～M6 候选锁定到 Git commit → 执行对应正式 Audit；不存在“未建 Git 先做正式 Audit”的路径。
- 发现用户已有改动时保留并绕开；不得 `reset --hard`、覆盖或删除不属于当前工作包的内容。

## 7. 质量门禁

- TypeScript `strict`；禁止无理由 `any`、吞错、静默降级和无界重试。
- 所有金额、倍率、周期、路由和账本规则必须确定、版本化、可回放；不得由 LLM 决定热路径。
- 所有写操作必须校验企业边界、权限、对象状态和幂等。
- 每个真实消耗 Attempt 保留独立明细；一个请求只有一个幂等 settlement。
- SSE／WebSocket 首个有效输出后禁止跨上游切换或拼接。
- 数据库不可写时拒绝新调用；Redis 不可用且无法保证额度时拒绝，不能无账放行。
- 每个工作包至少完成受影响单测／集成／E2E、负向场景、canary 和 Evidence。
- 新依赖必须说明必要性、许可证和锁定版本；禁止直接复制 TokenHub／Sub2API 源码。

## 8. Evidence 与 Handoff

- Evidence 唯一路径：`V3/Evidence/<Mxx>/<Wxx>/<timestamp>-<name>/`。
- 阶段状态或工作包状态变化时，先保存 Evidence，再更新 `仟流智算-stage-state-v0.3.yaml`；Stage 01／02 进度图分别由 `V3/tools/render-stage01-progress.rb`、`V3/tools/render-stage02-progress.rb` 从该事实生成阶段级快照，禁止反向手改同名状态。
- Handoff 至少写：完成结果、候选标识、测试、Evidence、残余风险、未做项、下一工作包输入。
- 没有 Evidence 不得把工作包或里程碑标记为完成。

## 9. 禁止事项与升级

禁止：

- 提前执行非当前工作包；
- 把未提供真实凭证写成所有开发阻塞；
- 把没有 Windows 客户端写成服务器、Gateway 或 Web 开工阻塞；
- 将计划、PoC、模拟页面或文档声明当作生产完成；
- 未经 Planning Change 扩大一期范围；
- 将真实 Secret、正文、个人数据或生产快照写入仓库；
- 未经授权提交、推送、发布或操作外部系统。

升级：

- 范围／合同变化：登记 Planning Change，暂停受影响范围。
- Secret／隐私／资金／不可逆数据风险：立即停止，按 `HIGH` 处理。
- 外部依赖只影响单一 Provider／客户端时，只阻塞对应工作包，未受影响主线继续。
- 连续无法推进时记录已验证事实、解除条件和唯一需要佳哥决定的问题，不制造泛化阻塞。
