# 仟流智算 0.3 原型审核总结

审核对象：K3 原型 v4 / PRD v0.3  
审核方式：浏览器逐页点击与 WT-01～WT-20 真实任务走查  
结论：V4 原型产品走查 20／20 PASS；逐项证据见 [WT-01～WT-20 签字走查](./仟流智算-WT01-WT20逐项签字走查-v0.3.md)。真实客户端与上游行为仍以 POC Evidence 为准。

## 已通过

- 使用主体：员工与项目作为统一责任主体的设计清晰，无改动。
- 额度模板：支持员工包、项目包、模型包等按需创建并批量套用，灵活性满足预期。
- 计费规则：厂商 / 模型、有效期、时段、价格与规则版本的设计合理；历史账本按命中版本保留，不重算。
- 用量账本：按请求记录主体、模型、最终上游、Token、费用、规则和状态；路由诊断用于下钻，不存在方向性问题。

## 首页看板

### 信息顺序

调整为：

1. 本月核心指标
2. AI 厂商
3. 超额名单 + 未处理异常
4. Gateway 运行态

将“持续供给摘要”改名为“AI 厂商”。逻辑是先看经营结果与资源供给、责任边界和待办风险，最后再看底层运行细节。

### 本月核心指标布局

- 当前 7 张卡“上 6、下 1”视觉失衡。
- 建议改为“上 4、下 3”的 12 栅格布局。
- 上排：厂商资源账号、活跃人数、套餐支付、API 费用。
- 下排：充值金额、预计最早耗尽、有证据的调度节省。

### Gateway 运行态文案

- “冷却 / 隔离资源”改为“冻结账号”。
- 卡片短说明改为“上游限流 1 · 12:06 恢复”，不展示技术码“429”。
- “冻结”的内部定义：上游受限时，系统为避免后续请求受影响，暂时停止向该账号分配请求；恢复后再放出。
- 正式版以业务影响表达为主，避免让管理员理解底层技术术语。

### 供给预测

- 预测以贴近正常消耗为基线，不人为过度保守。
- 基于真实余额 / 剩余额度、真实账本和当前消耗趋势计算。
- 必须纳入高峰与非高峰时段的真实请求分布、扣减倍率、价格或套餐规则。
- 数据不足或趋势突变时，通过可信度或异常提示说明，不伪装成精确预测。

## 厂商资源

### 统一模型与路由

- 用于管理员在接入新模型 / 新厂商时，配置“统一模型名 → 实际厂商、候选账号、协议、路由策略”的映射。
- 日常调用由 Gateway 自动选择账号，业务人员无需逐次配置。
- “新建模型路由”当前无响应；应打开创建抽屉或向导，或明确展示暂不可用状态。

### 资源账号登记

- 首次登记保留：厂商、资源模式、资源账号名称、API Key / 授权、测试连接。
- “上游凭证”改为“API Key”；当前选择 DeepSeek API 时，占位文案为“粘贴 DeepSeek API Key”。
- “Provider 能力”改为“接口能力”，由系统探测、只读展示。
- 上游模型、能力模板、优先级 / 权重、并发上限应提供合理默认值或放进高级设置，不阻塞首次接入。
- API Key 仅以掩码显示和安全存储，不在日志、账本或界面明文回显。

### 持续供给

- 首页“AI 厂商”展示汇总；资源页“持续供给”展示预测依据和具体资源情况。

## 额度规则

- 主体额度边界：员工或项目用尽自身额度后，按规则停止、管理员授权超额，或在可接受前提下切换等价资源；公司总余额仍存在不等于主体可继续使用。
- “新建调度策略”当前无响应；应支持配置适用对象 / 模型、触发条件、动作、候选资源、优先级、生效时间和发布前影响预览。

## 系统设置

- 正式版设置页以管理员账号、权限、操作审计、安全与隐私为主。
- 研发期的“一期 / 二期功能开关”应隐藏，或仅对发布管理角色提供。
- “Gateway 执行边界”应隐藏或改为超级管理员只读的“系统保护规则”，避免暴露技术术语。
- 操作日志除登录外，还应记录额度、规则、资源账号、管理员权限与凭证状态等关键操作。

## 全局导航与品牌

- 删除侧边栏分组标题“管理”。
- “首页看板”改为“看板”。
- Logo 待提供后替换，并检查左上角品牌区的尺寸、留白与深浅背景适配。

## 待补原型交互

无。新建模型路由、新建调度策略、额度模板、管理员和资源登记均已形成可点击闭环。
